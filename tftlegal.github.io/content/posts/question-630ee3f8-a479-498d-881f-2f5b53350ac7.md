# Руководство по развертыванию AWX через AWX Operator на K3s

Данное руководство описывает современный стандарт развертывания AWX. Начиная с версии 18.0, AWX официально перешел на архитектуру **Kubernetes Operator**. Мы будем использовать **K3s** — легкий дистрибутив Kubernetes, идеально подходящий для установки на один сервер.

---

## 1. Подготовка инфраструктуры

### Системные требования
*   **CPU:** Минимум 2 ядра (рекомендуется 4+).
*   **RAM:** Минимум 4 ГБ (рекомендуется 8 ГБ+). *Важно: При нехватке памяти процесс OOM Killer принудительно завершит контейнеры базы данных.*
*   **ОС:** Ubuntu 22.04 LTS / Debian 11/12.
*   **Диск:** Минимум 40 ГБ свободного места.

### Установка K3s
Выполните последовательно:
```bash
# Обновление системы
sudo apt update && sudo apt upgrade -y

# Установка K3s
curl -sfL https://get.k3s.io | sh -

# Настройка прав доступа
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $USER:$USER ~/.kube/config

# Делаем конфигурацию постоянной
echo "export KUBECONFIG=~/.kube/config" >> ~/.bashrc
source ~/.bashrc

# Проверка работоспособности
kubectl get nodes
```

## 2. Установка AWX Operator

AWX Operator — это контроллер, который управляет жизненным циклом приложения AWX.

### Шаги установки:
1. **Создание пространства имен:**
   ```bash
   kubectl create namespace awx
   ```

2. **Установка оператора:**
   *Всегда проверяйте актуальную версию в официальном репозитории [ansible/awx-operator](https://github.com/ansible/awx-operator).*
   ```bash
   # Пример установки актуальной версии (замените версию на текущую стабильную)
   kubectl apply -k https://github.com/ansible/awx-operator/deployments/awx-operator/2.1.0/ --filename -
   ```

3. **Мониторинг установки:**
   Дождитесь, пока оператор перейдет в статус `Running`:
   ```bash
   kubectl get pods -n awx -w
   ```

---

## 3. Конфигурация экземпляра AWX

В Kubernetes вместо редактирования конфиг-файлов мы используем **Custom Resource (CR)**. Создайте файл `awx_instance.yml`:

```yaml
apiVersion: awx.ansible.com/v1beta1
kind: AWX
metadata:
  name: awx-server
  namespace: awx
spec:
  # Тип сервиса: NodePort открывает порт на IP вашего сервера
  service_type: NodePort

  # Настройки базы данных (PostgreSQL)
  postgres_enabled: true
  postgres_resource_requirements:
    requests:
      memory: "1Gi"
      cpu: "500m"

  # Настройки Redis
  redis_enabled: true

  # Настройки веб-интерфейса
  web_server_host: 0.0.0.0

  # Настройки ресурсов для Task Containers (где запускаются плейбуки)
  task_containers_resource_requirements:
    requests:
      memory: "512Mi"
      cpu: "500m"
```

**Примените конфигурацию:**
```bash
kubectl apply -f awx_instance.yml
```

> **⚠️ Важное предупреждение по хранилищу:**
> Если вы разворачиваете AWX на "чистом" K3s без настроенного StorageClass (например, Longhorn или Local Path Provisioner), данные базы данных могут быть временными. Для продакшена убедитесь, что у вас настроен `StorageClass`.

## 4. Мониторинг развертывания

После применения YAML-файла оператор начнет создавать поды. Это может занять 5–10 минут.

```bash
# Следите за созданием подов
kubectl get pods -n awx -w
```
Вы должны увидеть поды: `awx-server-postgres`, `awx-server-redis`, `awx-server-web`, и несколько `awx-server-task`.

## 5. Доступ к интерфейсу и учетные данные

### Определение порта
Так как мы используем `NodePort`, Kubernetes назначит случайный порт в диапазоне 30000-32767.
```bash
kubectl get svc -n awx
```
Найдите сервис `awx-server`. В колонке `PORT(S)` вы увидите что-то вроде `80:30445`. В данном примере порт — **30445**.

### Получение пароля администратора
Пароль генерируется автоматически и хранится в секрете:
```bash
kubectl -n awx get secret awx-server-admin-password -o jsonpath='{.data.password}' | base64 --decode; echo
```

### Доступ
Откройте в браузере: `http://<IP_ВАШЕГО_СЕРВЕРА>:30445`
Логин: `admin`
Пароль: *(тот, что получили выше)*

## 6. Базовая настройка системы

Для начала работы с автоматизацией выполните следующие шаги внутри интерфейса AWX:

### 1. Настройка учетных данных (Credentials)
*   Перейдите в **Credentials** -> **Add**.
*   Выберите тип **Machine**.
*   Вставьте ваш **Public SSH Key**. Это позволит AWX подключаться к вашим серверам без ввода пароля.

### 2. Подключение проектов (Projects)
*   Перейдите в **Projects** -> **Add**.
*   Укажите URL вашего Git-репозитория (GitLab/GitHub).
*   Укажите путь к папке с плейбуками.
*   AWX будет автоматически скачивать код при запуске задач.

### 3. Инвентаризация (Inventories)
*   Перейдите в **Inventories** -> **Add**.
*   Создайте группу серверов (например, "Web_Servers").
*   Добавьте IP-адреса хостов и привяжите к ним созданные ранее **Credentials**.

### 4. Создание шаблона задачи (Job Template)
*   Перейдите в **Templates** -> **Add**.
*   Выберите созданный **Inventory**, **Project** и **Credentials**.
*   Нажмите **Save**.
*   Теперь вы можете нажать **Launch**, чтобы запустить ваш первый Ansible плейбук.
