# Сравнительный анализ Kafka и NATS (JetStream) и руководство по развертыванию в режиме HA

Данный документ содержит сравнительный анализ систем обмена сообщениями Apache Kafka и NATS (с использованием JetStream) по критериям ARE (Availability, Reliability, Efficiency), а также инструкции по развертыванию высокодоступных кластеров.

## 1. Сравнительный анализ

| Критерий | Apache Kafka | NATS JetStream |
| :--- | :--- | :--- |
| **Availability (Доступность)** | Высокая. Основана на механизме Leader/Follower для каждой партиции. При отказе лидера происходит перевыборы (Election). В режиме KRaft используется протокол Raft для управления метаданными. | Высокая. NATS спроектирован как легковесный кластер. JetStream обеспечивает высокую доступность через репликацию потоков (Streams). Переключение между узлами происходит практически мгновенно. |
| **Reliability (Надежность)** | **Очень высокая.** Поддерживает гарантии *At-least-once* и *Exactly-once* (через транзакции). Использование `acks=all` и `min.insync.replicas` гарантирует сохранность данных на нескольких узлах. | **Высокая.** JetStream обеспечивает персистентность сообщений. Поддерживает подтверждения (ACKs) и повторные попытки. Гарантии доставки зависят от настроек конкретного Stream (например, `AckPolicy`). |
| **Efficiency (Эффективность)** | **Максимальная пропускная способность.** Идеально подходит для обработки огромных потоков данных (Big Data, Log Aggregation). Требует значительных ресурсов (RAM, Disk I/O) и сложной настройки. | **Низкие задержки (Low Latency).** Намного легче Kafka. Идеально подходит для микросервисов, IoT и real-time систем. Требует значительно меньше ресурсов и проще в эксплуатации. |

## 2. Архитектурные требования для HA

### Для Kafka (KRaft режим)
1.  **Количество узлов:** Минимум 3 брокера/контроллера.
2.  **Репликация:** `replication.factor = 3`.
3.  **Минимальный кворум:** `min.insync.replicas = 2`. Это позволяет кластеру продолжать работу при отказе одного узла.
4.  **Размещение:** Узлы должны находиться в разных зонах доступности (Multi-AZ).

### Для NATS JetStream
1.  **Количество узлов:** Минимум 3 узла для формирования кворума.
2.  **Репликация:** Настройка `Replicas: 3` для конкретных потоков (Streams).
3.  **Балансировка:** Использование внешнего Load Balancer (например, HAProxy или NLB) для распределения входящих соединений по портам 4222 (TLS) и 4223.

## 3. Инструкция по установке Kafka в HA (KRaft)

*Примечание: Инструкция подразумевает установку на Linux (Ubuntu/Debian).*

### Шаг 1: Подготовка системы
Установите Java (рекомендуется OpenJDK 11 или 17):
```bash
sudo apt update
sudo apt install default-jdk -y
```

### Шаг 2: Скачивание и распаковка
Загрузите последнюю версию Kafka и распакуйте её в `/opt/kafka`.

### Шаг 3: Генерация конфигурации
Для KRaft необходимо сгенерировать уникальный Cluster ID и конфигурации для каждого узла.
1.  **Сгенерируйте ID:**
    `KAFKA_CLUSTER_ID=$(bin/kafka-storage.sh random-uuid)`
2.  **Настройте `server.properties` для каждого узла:**
    Укажите уникальные `node.id`, `process.roles=controller,broker`, `listeners` и `controller.quorum.voters`.

### Шаг 4: Форматирование хранилища
Выполните команду на каждом узле (замените `<ID>` на ваш):
```bash
bin/kafka-storage.sh format -t <ID> -c config/kraft/server.properties
```

### Шаг 5: Запуск
Запустите сервис на каждом узле:
```bash
bin/kafka-server-start.sh config/kraft/server.properties
```

## 4. Инструкция по установке NATS в HA (JetStream)

### Шаг 1: Установка
Установите бинарный файл NATS:
```bash
curl -sfL https://raw.githubusercontent.com/nats-io/nats-server/master/nats-server-build.sh | sh
```

### Шаг 2: Конфигурация кластера
Создайте файл `cluster.conf` на всех 3 узлах. Пример базовой конфигурации:
```hocon
# cluster.conf
cluster {
  name: "ha-cluster"
  nodes: [
    {host: "node1_ip:4222"},
    {host: "node2_ip:4222"},
    {host: "node3_ip:4222"}
  ]
}

jetstream {
  stan_dynamic_config: true
  store_dir: "/data/nats_jetstream"
}

port: 4222
port_tcp: 4223
```

### Шаг 3: Запуск кластера
Запустите сервер с указанием конфига:
```bash
nats-server -c /etc/nats/cluster.conf
```

### Шаг 4: Проверка JetStream
Проверьте состояние кластера и доступность JetStream:
```bash
nats --server=node1_ip:4222 info
```

### Шаг 5: Балансировка (Load Balancer)
Настройте HAProxy для работы с NATS (проксирование TCP):
```haproxy
listen nats_cluster
    bind *:4222
    mode tcp
    balance roundrobin
    server node1 node1_ip:4222 check
    server node2 node2_ip:4222 check
    server node3 node3_ip:4222 check
```
