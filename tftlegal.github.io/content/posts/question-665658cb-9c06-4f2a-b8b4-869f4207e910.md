## Существенные ошибки (требуют доработки)

| # | Проблема | Пояснение |
|---|---|---|
| 12 | **Глоссарий: Upstream** | «исходный проект (source code)» — неточно. Upstream — это *первоисточник*, *верхневый репозиторий*, от которого форкнут. Source code — это просто исходный код. |
| 13 | **Глоссарий: Fork** | «копирование проекта» — неточно. Fork — это *копия репозитория* (операция в GitHub), а не «копирование проекта» в абстрактном смысле. |
| 14 | **Глоссарий: PR** | «заявление об изменении» — неверный перевод. PR = Pull Request = *запрос на слияние* / *pull request*. «Заявление» ассоциируется с документом, а не с механизмом VCS. |
| 15 | **Глоссарий: Maintainers** | «обслуживающий персонал проекта» — калька с английского, звучит как «уборщики». Корректно: *мейнтейнеры* / *кураторы проекта* / *ответственные разработчики*. |
| 16 | **Глоссарий: Good first issue** | «первая проблема, которую можно решить новичom» — тавтология и стилистическая ошибка. Корректно: *задача для новичка* / *первая задача для начинающего*. |
| 17 | **Дублирование секций** | «Создание руководства» и «Наконец» — практически идентичны. Одна из них избыточна. |
| 18 | **Отсутствие конкретных ссылок** | Указаны источники без URL. Для плана перевода это критично — нужно зафиксировать точные версии/разделы. |
| 19 | **Нет критериев качества перевода** | Не указано: кто проверяет, какой стиль (формальный/неформальный), как обрабатывать термины (транслит vs. перевод). |
| 20 | **Нет плана по лицензиям** | Перевод чужого контента требует проверки лицензии оригинала (CC BY-SA, MIT, etc.) и указания атрибуции. |

## OWASP-соображения (при публикации)

Поскольку итоговый артефакт — публичный репозиторий с issue tracker:

| OWASP Категория | Риск | Рекомендация |
|---|---|---|
| **A03:2021 – Injection** | Issue/PR body rendering (Markdown → HTML) | Использовать sanitizing (e.g. `marked` + `DOMPurify`), не render raw HTML. |
| **A05:2021 – Security Misconfiguration** | Public repo with no `.gitignore` for secrets | Add `.gitignore`, enable branch protection, require PRs for main. |
| **A07:2021 – Identification & Auth Failures** | If guide includes auth examples (OAuth, tokens) | Ensure examples use placeholder credentials, never real tokens. |
| **A08:2021 – Software & Data Integrity** | Third-party links in the guide | Validate all outbound URLs; avoid redirect chains; prefer HTTPS. |
| **A02:2021 – Cryptographic Failures** | If guide includes CI/CD examples | Use signed commits, avoid hardcoded secrets in workflow examples. |
| **A04:2021 – Insecure Design** | Community contribution channel (issues/PRs) | Implement moderation workflow, label system, and CODE_OF_CONDUCT. |
| **A06:2021 – Vulnerable & Outdated Components** | If guide includes code snippets with dependencies | Pin versions in examples; add note about checking for CVEs. |
