**Настоятельно recommended: Долгосрочная оценка и ajustment настраиваемых настроек для optimalizirovki обрабатывающих heavy POST/PUT запросов**

**Шаг 1: Определить реалистичный максимальный размер тела для `/ai/models/v1/message/async/v1`**

*   **Анализ логированных данных и метрик**: отслеживайте размер тела для `/ai/models/v1/message/async/v1` и определите максимально возможный размер тела.
*   **Анализ ограничений приложения**: учитывайте ограничения приложения, такие как размеры JSON-документов, которые можно скачивать.
*   **Примечание:** Неправильные значения `client_max_body_size` и `client_body_buffer_size` могут привести к overflow или Memory/disk pressure, поэтому имеет смысл выполнять долгосрочную оценку и ajustment.

**Шаг 2: Set up Nginx настройки для heavy POST/PUT запросов**

*   `location` `/ai/models/v1/message/async/v1`:
    *   `client_max_body_size`: must be greater than `client_body_buffer_size`.
    *   `client_body_buffer_size`: значение, которое должно быть меньше `client_max_body_size`.
    *   `client_body_single_buffer`: bật или отключать для управления buffering body.
    *   `client_body_temp_path`: путь для temporary storing buffer bodies.
*   **Примечание:** Use a buffer size that balances between memory usage and disk space.

```nginx
location /ai/models/v1/message/async/v1 {
    client_max_body_size 40m;
    client_body_buffer_size 32m;
    client_body_single_buffer on;
    client_body_temp_path /var/lib/nginx/body 1 2;
}
```

**Шаг 3: Configure overflow storage**

*   `/var/lib/nginx/body` с следующими настройками:
    *   `/var/lib/nginx/body`: путь для temporary storing buffer bodies.
    *   `1`: количество temporary files, которые можно создать.
    *   `2`: размер temporary files (в KB).
*   **Примечание:** Use a temporary storage size that is large enough to handle the expected amount of data.

```nginx
client_body_temp_path /var/lib/nginx/body 1 2;
```

**Шаг 4: Validate and reload**

*   Используйте `nginx -t` для проверки конфигурации и перезагрузите Nginx с помощью `nginx -s reload` или `systemctl reload nginx`.
*   **Примечание:** Use a secure password for the nginx user.

```bash
nginx -t
nginx -s reload
```

**Шаг 5: Monitor after reload**

*   Memory usage на Nginx хосте.
*   Disk usage и I/O на `/client_body_temp_path`.
*   Nginx error log.
*   Upstream success/latency для async endpoint.
*   **Примечание:** Monitor the Nginx logs for any errors or warnings.

```bash
tail -f /var/log/nginx/error.log
```

**Шаг 6: Adjust if needed**

*   Если все еще происходит overflow или memory/disk pressure, мы можем:
    *   Увеличить размер buffer.
    *   Снижать размер buffer или увеличить temporary disk capacity.
    *   Рассмотреть limitation concurrency или применять body-size limits на aplikационном уровне.
*   **Примечание:** Monitor the performance and adjust the configuration as needed.

```bash
tail -f /var/log/nginx/access.log
```

*   **Настройка client_body_single_buffer**:
    *   `client_body_single_buffer`: bật или отключать для управления buffering body.
    *   Recommended value: `on`.
*   **Настройка client_body_temp_path**:
