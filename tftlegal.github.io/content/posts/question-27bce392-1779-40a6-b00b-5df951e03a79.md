# Полный гайд по запуску LLM с MTP на GTX 1050 через Docker

## Введение

Multi-Token Prediction (MTP) — это технология спекулятивного декодинга, позволяющая ускорить генерацию токенов в **1.4–2.2 раза** без потери качества. Благодаря тому, что PR с MTP был объединён с основной веткой llama.cpp, теперь можно использовать официальные сборки и готовые Docker-образы.

В этом гайде мы развернём Qwen3.6 с поддержкой MTP на хосте с видеокартой NVIDIA GTX 1050 (2 ГБ VRAM). Учитывая скромный объём видеопамяти, будем использовать **максимально лёгкие квантования** и оптимизации.

---

## 1. Подготовка хоста

### 1.1 Установка драйверов NVIDIA и CUDA

Для GTX 1050 подойдут драйверы версии 535 или новее. Убедитесь, что `nvidia-smi` работает:

```bash
nvidia-smi
```

Если драйверы не установлены:

```bash
sudo apt update
sudo apt install nvidia-driver-535 nvidia-utils-535
sudo reboot
```

### 1.2 Установка Docker и NVIDIA Container Toolkit

```bash
# Установка Docker
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER

# Установка NVIDIA Container Toolkit
distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/$distribution/libnvidia-container.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

sudo apt update
sudo apt install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

Проверка:

```bash
docker run --rm --gpus all nvidia/cuda:12.0-base nvidia-smi
```

## 2. Выбор модели

Для GTX 1050 с 2 ГБ VRAM подойдут только **самые лёгкие квантования**:

| Модель | Размер файла | Ориентировочная VRAM |
|--------|-------------|---------------------|
| Qwen3.6-27B-UD-Q2_K_XL | ~9–10 ГБ | >2 ГБ (не влезет) |
| Qwen3.6-27B-UD-Q3_K_XL | ~14.8 ГБ | >2 ГБ |
| **Qwen3.6-35B-A3B-MTP-UD-Q2_K_XL** | ~12.6 ГБ | >2 ГБ |

**Важное замечание**: ни одна из этих моделей **не поместится целиком** в 2 ГБ VRAM. Однако llama.cpp умеет оффлоадить часть слоёв в системную память (RAM) — это будет медленно, но работать будет.

**Рекомендация**: для комфортной работы с GTX 1050 лучше рассмотреть **более маленькие модели** (например, Qwen2.5-7B или Phi-3-mini). Если вы всё же хотите попробовать Qwen3.6 с MTP, выбирайте **Q2_K_XL** — самый лёгкий квантификат.

### Загрузка модели

```bash
mkdir -p ./models

# Вариант 1: Qwen3.6-27B Q2 (если доступен)
aria2c -x 16 -s 16 -k 1M \
  -o Qwen3.6-27B-UD-Q2_K_XL.gguf \
  "https://huggingface.co/unsloth/Qwen3.6-27B-MTP-GGUF/resolve/main/Qwen3.6-27B-UD-Q2_K_XL.gguf"

# Вариант 2: Qwen3.6-35B-A3B Q2
aria2c -x 16 -s 16 -k 1M \
  -o Qwen3.6-35B-A3B-MTP-UD-Q2_K_XL.gguf \
  "https://huggingface.co/havenoammo/Qwen3.6-35B-A3B-MTP-GGUF/resolve/main/Qwen3.6-35B-A3B-MTP-UD-Q2_K_XL.gguf"
```

> 💡 Если скачивание с Hugging Face медленное, используйте зеркало: замените `huggingface.co` на `hf-mirror.com`.

## 3. Запуск через Docker

Используем готовый образ `havenoammo/llama:cuda12-server`:

```bash
docker run --gpus all --rm \
  -p 8080:8080 \
  -v ./models:/models \
  havenoammo/llama:cuda12-server \
  -m /models/Qwen3.6-27B-UD-Q2_K_XL.gguf \
  --port 8080 \
  --host 0.0.0.0 \
  -n -1 \
  --parallel 1 \
  --ctx-size 4096 \
  --mmap \
  -ngl 10 \
  --flash-attn on \
  --temp 1.0 \
  --min-p 0.0 \
  --top-p 0.95 \
  --top-k 20 \
  --jinja \
  --chat-template-kwargs '{"preserve_thinking":true}' \
  --ubatch-size 512 \
  --batch-size 512 \
  --cache-type-k q4_0 \
  --cache-type-v q4_0 \
  --spec-type draft-mtp \
  --spec-draft-n-max 3
```

### Разбор ключевых параметров

| Параметр | Значение | Пояснение |
|----------|----------|-----------|
| `--gpus all` | — | Проброс всех GPU в контейнер |
| `-p 8080:8080` | — | Проброс порта для API |
| `-v ./models:/models` | — | Монтирование папки с моделями |
| `-ngl 10` | 10 слоёв на GPU | **Критично для GTX 1050** — загружаем только 10 слоёв в VRAM, остальные в RAM |
| `--ctx-size 4096` | 4096 токенов | Уменьшенный контекст для экономии VRAM |
| `--cache-type-k q4_0` | Q4 для кэша ключей | Экономия VRAM |
| `--cache-type-v q4_0` | Q4 для кэша значений | Экономия VRAM |
| `--spec-type draft-mtp` | — | Включает MTP (в новых версиях используется `draft-mtp`) |
| `--spec-draft-n-max 3` | 3 токена | Максимум токенов за шаг (соответствует 3 MTP-слоям модели) |

> ⚠️ **Важно**: в новых версиях llama.cpp флаг `--spec-type` изменился с `mtp` на `draft-mtp`.

```yaml
      - "-n"
      - "-1"
      - "--parallel"
      - "1"
      - "--ctx-size"
      - "4096"
      - "--mmap"
      - "-ngl"
      - "10"
      - "--flash-attn"
      - "on"
      - "--temp"
      - "1.0"
      - "--min-p"
      - "0.0"
      - "--top-p"
      - "0.95"
      - "--top-k"
      - "20"
      - "--jinja"
      - "--chat-template-kwargs"
      - '{"preserve_thinking":true}'
      - "--ubatch-size"
      - "512"
      - "--batch-size"
      - "512"
      - "--cache-type-k"
      - "q4_0"
      - "--cache-type-v"

      - "--spec-type"
      - "draft-mtp"
      - "--spec-draft-n-max"
```

Запуск:

```bash
docker-compose up -d
```

## 6. Оптимизация для GTX 1050

### 6.1 Настройка количества слоёв на GPU

Параметр `-ngl` определяет, сколько слоёв модели загружается в VRAM. Для GTX 1050:

```bash
-ngl 5   # Минимум — только 5 слоёв в VRAM
-ngl 10  # 10 слоёв — хороший баланс
-ngl 15  # Если VRAM позволяет (маловероятно)
```

### 6.2 Уменьшение контекста

```bash
--ctx-size 2048   # Ещё сильнее экономия VRAM
--ctx-size 1024   # Минимальный рабочий контекст
```

### 6.3 Кэширование KV в низком качестве

```bash
--cache-type-k q4_0 --cache-type-v q4_0   # Экономия ~50% VRAM на кэше
--cache-type-k q2_K --cache-type-v q2_K   # Максимальная экономия
```

### 6.4 Отключение MTP при нехватке памяти

Если MTP вызывает ошибки из-за нехватки памяти, отключите его:

```bash
# Удалите из команды:
--spec-type draft-mtp --spec-draft-n-max 3
```

## 7. Устранение неполадок

### 7.1 "CUDA out of memory"

**Решение**: уменьшите `-ngl`, `--ctx-size` или используйте более лёгкое квантование.

### 7.2 "error loading model: missing tensor"

**Решение**: убедитесь, что используете правильную версию llama.cpp. Образ `havenoammo/llama:cuda12-server` уже содержит поддержку MTP.

### 7.3 MTP не даёт прироста скорости

**Возможные причины**:
- Слишком мало слоёв загружено в GPU (`-ngl` слишком низкий)
- Модель плохо квантована — используйте Unsloth Dynamic 2.0 GGUFs
- Проверьте параметр `--spec-type draft-mtp` (не `mtp`)

### 7.4 Низкая скорость генерации

Для GTX 1050 с оффлодингом в RAM скорость будет невысокой. Рассмотрите:
- Использование более лёгкой модели (например, Qwen2.5-7B)
- Увеличение `-ngl` (если позволяет VRAM)
- Использование `--numa` для оптимизации работы с памятью
