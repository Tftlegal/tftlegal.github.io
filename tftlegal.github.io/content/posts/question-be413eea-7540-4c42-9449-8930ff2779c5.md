# Сравнение основных команд PowerShell и Bash

PowerShell и Bash — две самые распространённые оболочки, с которыми работают системные администраторы, DevOps-инженеры и разработчики. PowerShell «из коробки» установлена в Windows, а Bash (а также его наследники — Zsh, Ash, Dash и другие) — в мире Linux и macOS. На первый взгляд они выполняют похожие задачи, но под капотом это принципиально разные инструменты.

Главное отличие, о котором стоит помнить на протяжении всей статьи:

- **Bash** оперирует **текстом**: команды принимают строки, передают строки дальше и преобразуют их регулярными выражениями, разделителями и подстановками.
- **PowerShell** оперирует **объектами** (в первую очередь объектами .NET): каждая команда возвращает список объектов со свойствами и методами, которые можно сортировать, фильтровать и группировать без «жонглирования» строками.

Из этого фундаментального различия вытекает большая часть синтаксических и стилистических отличий двух оболочек. В этой статье мы пройдём по основным группам команд и покажем, как одна и та же задача решается в обеих оболочках.
**Примечание:** в Windows по умолчанию установлена PowerShell 5.1 (Windows PowerShell, работающая поверх .NET Framework). Начиная с версии 7 оболочка переписана на .NET Core и работает кросс-платформенно (Windows, Linux, macOS). Команды и примеры ниже актуальны для обеих ветвей, но для Windows-сценариев ориентируйтесь на 5.1, если вы не установили PowerShell 7 отдельно.

## 1. Какую версию я использую?

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Показать версию оболочки | `echo $BASH_VERSION` | `$PSVersionTable.PSVersion` |
| Показать информацию о системе | `uname -a` | `$PSVersionTable.OS` или `[System.Environment]::OSVersion` |

В Bash версия доступна через переменную окружения `$BASH_VERSION`. В PowerShell это свойство автоматической переменной `$PSVersionTable`, которая представляет собой таблицу с множеством полей: `PSVersion`, `PSEdition`, `CLRVersion`, `GitCommitId` и другими.

```bash
# Bash
$ echo $BASH_VERSION
5.2.21(1)-release
```

```powershell
# PowerShell
PS> $PSVersionTable.PSVersion

Major  Minor  Build  Revision
-----  -----  -----  --------
7      4      0      -1
```

## 2. Работа с текущим каталогом и вывод списка файлов

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Вывести список файлов | `ls` | `Get-ChildItem` (алиас `ls` / `gci` / `dir`) |
| Подробный вывод | `ls -l` | `Get-ChildItem -Force` или `ls -l` |
| Скрытые файлы | `ls -a` | `Get-ChildItem -Force` |
| Рекурсивный вывод | `ls -R` | `Get-ChildItem -Recurse` |
| Перейти в каталог | `cd /var/log` | `cd C:\Logs` (или `Set-Location`) |
| Показать текущий каталог | `pwd` | `Get-Location` (алиас `pwd` / `gl`) |
| Вывести только путь | `pwd` | `(Get-Location).Path` |
| Файлы по маске | `ls *.log` | `Get-ChildItem *.log` |

```bash
# Bash
$ cd /var/log
$ ls -la *.log | head
```

```powershell
# PowerShell
PS> Set-Location C:\Logs
PS> Get-ChildItem -Filter *.log -Force | Select-Object -First 10
```

В Bash `ls` — это одна команда с множеством флагов. В PowerShell `Get-ChildItem` — это команда формата «Глагол-Существительное» (Verb-Noun), которую можно комбинировать с параметрами и конвейером. Обе оболочки предоставляют алиасы (`ls`, `cd`, `pwd`, `cat`, `rm` и т. д.), так что мускульная память переносится почти один-в-один. Однако под капотом объекты разные: `ls` печатает удобную для человека таблицу, а `Get-ChildItem` возвращает объекты `System.IO.FileInfo`.

## 3. Чтение, запись и копирование файлов

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Показать содержимое файла | `cat file.txt` | `Get-Content file.txt` (алиас `cat` / `gc`) |
| Показать первые N строк | `head -n 20 file.txt` | `Get-Content file.txt -TotalCount 20` |
| Показать последние N строк | `tail -n 20 file.txt` | `Get-Content file.txt -Tail 20` |
| Скопировать файл | `cp a.txt b.txt` | `Copy-Item a.txt b.txt` (алиас `copy`) |
| Скопировать рекурсивно | `cp -r src/ dst/` | `Copy-Item src\* -Recurse -Destination dst\` |
| Переместить / переименовать | `mv a.txt b.txt` | `Move-Item a.txt b.txt` |
| Удалить файл | `rm a.txt` | `Remove-Item a.txt` (алиас `rm` / `del` / `ri`) |
| Удалить каталог рекурсивно | `rm -r dir/` | `Remove-Item dir -Recurse` |
| Создать пустой файл | `touch a.txt` | `New-Item a.txt -ItemType File` |
| Создать каталог | `mkdir dir` | `New-Item dir -ItemType Directory` (алиас `md`) |
| Создать вложенные каталоги | `mkdir -p a/b/c` | `New-Item a\b\c -ItemType Directory -Force` |

Небольшая, но важная разница: в Bash `cat file.txt` — это одна команда, принимающая имя файла. В PowerShell `Get-Content` — это команда «Глагол-Существительное», где файл является *существительным-объектом*. Обе принимают маски и глобы:

```bash
# Bash: вывести первые 50 строк всех .log-файлов в каталоге
head -n 50 /var/log/*.log
```

```powershell
# PowerShell
Get-ChildItem C:\Logs\*.log | Get-Content -TotalCount 50
```

## 4. Поиск файлов и текста

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Найти файлы по имени (рекурсивно) | `find / -name "app.log"` | `Get-ChildItem -Path / -Recurse -Filter app.log` |
| Найти файлы, изменённые за N дней | `find . -mtime -7 -name "*.log"` | `Get-ChildItem -Recurse -Filter *.log \| Where-Object { $_.LastWriteTime -gt (Get-Date).AddDays(-7) }` |
| Поиск по содержимому (grep) | `grep "error" app.log` | `Select-String -Path app.log -Pattern "error"` (алиас `sls`) |
| Рекурсивный поиск по содержимому | `grep -R "TODO" src/` | `Get-ChildItem src -Recurse -File \| Select-String "TODO"` |
| Без учёта регистра | `grep -i "warn" file` | `Select-String -Pattern "warn" -CaseSensitive:$false` |
| С номерами строк | `grep -n "pattern" file` | `Select-String -Pattern "pattern" file \| Select-Object LineNumber, Line` |
| Подсчитать строки | `wc -l file` | `(Get-Content file).Count` |
| Подсчитать совпадения | `grep -c "x" file` | `(Select-String "x" file).Count` |

`Select-String` в PowerShell концептуально ближе к `grep`, но поскольку она возвращает объекты `SelectStringInfo` (а не просто текст), вы можете продолжать использовать конвейер для просмотра имени файла, номера строки и совпавшей строки:

```bash
# Bash
grep -rn "TODO" src/ | awk -F: '{print $1": "$2}'
```

```powershell
# PowerShell
Get-ChildItem src -Recurse -File |
    Select-String -Pattern "TODO" |
    Select-Object Path, LineNumber, Line
```

## 5. Переменные и окружение

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Задать переменную | `NAME="John"` | `$Name = "John"` |
| Прочитать переменную | `echo $NAME` | `Write-Output $Name` или `$Name` |
| Прочитать переменную окружения | `echo $HOME` | `Write-Output $env:HOME` |
| Установить переменную окружения | `export PATH="$PATH:./bin"` | `$env:PATH = "$env:PATH;.\bin"` |
| Вывести все переменные окружения | `env` или `printenv` | `Get-ChildItem Env:` (или `dir env:`) |
| Удалить переменную | `unset NAME` | `Remove-Variable Name` |
| Интерполяция строки | `echo "Hello $NAME"` | `Write-Output "Hello $Name"` |
| Экранировать `$` | `echo '\$HOME'` | `` Write-Output '`$HOME' `` |

В Bash каждая переменная по сути является строкой, а `$` — префикс для раскрытия переменной. В PowerShell префикс `$` обязателен для любого имени переменной, а переменные — это типизированные объекты:

```bash
# Bash
CITY="Berlin"
POP=3700000
echo "В городе $CITY проживают $POP человек."
```

```powershell
# PowerShell
$City = "Berlin"
$Pop  = 3700000
"В городе $City проживают $Pop человек."
```

Одно из самых полезных отличий: в PowerShell `$env:` — это *привод* (drive). Вы можете перечислять, фильтровать и изменять переменные окружения как обычное коллекцию объектов:

```powershell
Get-ChildItem Env: | Where-Object { $_.Name -like "PATH*" }
```

В Bash эквивалент — `env | grep -i path`.

## 6. Условия и логические операторы

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Если / иначе | `if [ -f file ]; then …; fi` | `if (Test-Path file) { … }` |
| Файл существует | `[ -f file.txt ]` | `Test-Path file.txt` |
| Каталог существует | `[ -d dir ]` | `Test-Path -PathType Container dir` |
| Строки равны | `[ "$x" = "yes" ]` | `$x -eq "yes"` |
| Численное сравнение | `[ $n -gt 5 ]` | `$n -gt 5` |
| Регулярное выражение | `[[ $str =~ ^[0-9]+$ ]]` | `$str -match '^[0-9]+$'` |
| Логическое И | `&&` или `[ … ] && [ … ]` | `-and` |
| Логическое ИЛИ | `\|\|` или `[ … ] \|\| [ … ]` | `-or` |
| Логическое НЕ | `!` | `-not` / `!` |
| Тернарный оператор (Bash 4+) | `cond ? a : b` | `$(if (cond) { a } else { b })` (PS 7: `$cond ? $a : $b`) |

```bash
# Bash
if [ -d /tmp/app ] && [ -f /tmp/app/config.yml ]; then
    echo "OK"
else
    echo "Не найдено"
fi
```

```powershell
# PowerShell
if (Test-Path -Path C:\app -PathType Container -and (Test-Path C:\app\config.yml)) {
    Write-Output "OK"
} else {
    Write-Output "Не найдено"
}
```

В PowerShell команда `Test-Path` инкапсулирует проверки файловой системы в чистый предикат, а операторы сравнения (`-eq`, `-ne`, `-gt`, `-lt`, `-ge`, `-le`, `-like`, `-match`, `-contains`) — это *операторы языка*, поэтому они работают с любым типом объекта, а не только со строками.

## 7. Циклы

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Цикл for по списку | `for f in a b c; do …; done` | `foreach ($f in "a","b","c") { … }` |
| C-стиль for | `for ((i=0; i<10; i++)); do …; done` | `for ($i=0; $i -lt 10; $i++) { … }` |
| Foreach по файлам | `for f in *.log; do …; done` | `foreach ($f in (Get-ChildItem *.log)) { … }` |
| While-цикл | `while [ … ]; do …; done` | `while (…) { … }` |
| Do-while | `do …; done` | `do { … } while (…)` |
| Параллельный цикл (PS 7) | нет встроенного | `ForEach-Object -Parallel { … }` |
| Выход из цикла | `break` | `break` |
| Пропустить итерацию | `continue` | `continue` |

```bash
# Bash
for i in 1 2 3 4 5; do
    echo "Итерация $i"
done
```

```powershell
# PowerShell
foreach ($i in 1..5) {
    Write-Output "Итерация $i"
}
```

Обратите внимание на **оператор диапазона** `1..5` в PowerShell — это встроенная языковая конструкция, генерирующая коллекцию целых чисел. В Bash прямого эквивалента нет (нужно использовать `seq 1 5` или C-стиль `for`).

## 8. Преобразование текста

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Перевести в верхний регистр | `echo "$x" \| tr 'a-z' 'A-Z'` | `$x.ToUpper()` |
| Перевести в нижний регистр | `tr 'A-Z' 'a-z'` | `$x.ToLower()` |
| Заменить подстроку | `sed 's/old/new/g'` | `$x -replace 'old','new'` |
| Обрезать пробелы | `xargs` / `sed 's/^ *//;s/ *$//'` | `$x.Trim()` |
| Разделить по разделителю | `IFS=',' read -ra parts <<< "$x"` | `$x.Split(',')` |
| Объединить массив | `IFS=,; echo "${arr[*]}"` | `$arr -join ","` |
| Перечислить свойства объекта | N/A (нет объектов) | `Get-Member` |

```bash
# Bash
name="  john.Doe  "
echo "$(echo "$name" | tr '[:lower:]' '[:upper:]' | tr -d '[:space:]')"
# JOHNDOE
```

```powershell
# PowerShell
$name = "  john.Doe  "
$name.Trim().ToUpper() -replace '\s', ''
# JOHNDOE
```

Строки в PowerShell — это полноценные экземпляры `System.String`, поэтому вы получаете доступ ко всему классу `String`: `Substring`, `IndexOf`, `Split`, `Replace`, `ToUpper`, `ToCharArray` и так далее. В Bash такого нет — нужно вызывать внешние утилиты или использовать параметрическое раскрытие вида `${x//old/new}`.

## 9. Сортировка, фильтрация и группировка

Здесь объектно-ориентированная природа PowerShell проявляется в полной мере.

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Отсортировать строки | `sort` | `Sort-Object` (алиас `sort`) |
| Числовая сортировка | `sort -n` | `Sort-Object -Property Number` |
| Сортировка по столбцу таблицы | `sort -k2,2n table.csv` | `Import-Csv table.csv \| Sort-Object -Property ([2])` |
| Убрать дубликаты | `sort \| uniq` | `Sort-Object -Unique` |
| Фильтрация по свойству | `awk '$3 > 100' data` | `Where-Object { $_.Col3 -gt 100 }` (алиас `where`) |
| Выбрать столбцы | `awk '{print $1, $3}'` или `cut -f1,3` | `Select-Object -Property Col1, Col3` (алиас `select`) |
| Группировка по полю | `awk '{a[$1]++} END{for (k in a) print k, a[k]}'` | `Group-Object -Property Status` |
| Первые / последние N | `head -n 3` / `tail -n 3` | `Select-Object -First 3` / `-Last 3` |

Пример — топ-3 процесса по занимаемой памяти:

```bash
# Bash
ps aux --sort=-rss | head -4 | awk '{print $11, $2, $6}'
```

```powershell
# PowerShell
Get-Process | Sort-Object WorkingSet64 -Descending | Select-Object -First 3 Name, Id, WorkingSet64
```

В Bash вы работаете со **столбцами текстовой таблицы** (отсюда `awk` с `$1`, `$2`, `$6` и лишняя `head -4`, чтобы пропустить строку заголовка). В PowerShell вы работаете с **объектами** — сортируете по свойству `WorkingSet64` напрямую и выбираете нужные свойства по имени.

Пример группировки:

```bash
# Bash: подсчитать, сколько процессов запущено каждым пользователем
ps -eo user= | sort | uniq -c | sort -rn
```

```powershell
# PowerShell
Get-Process | Group-Object ProcessName |
    Sort-Object Count -Descending |
    Select-Object Name, Count
```

В PowerShell `Group-Object` — это полноценная команда, тогда как в Bash канонический паттерн — конвейер `sort | uniq -c`.

## 10. Конвейер (pipe) и поток данных

Обе оболочки используют символ `|` для конвейера, но то, что по нему течёт, принципиально различается:

- В Bash конвейер передаёт **текст** (байты / строки).
- В PowerShell конвейер передаёт **объекты**.

```bash
# Bash: классический конвейер
ps aux | grep -i node | awk '{print $2, $6}'
```

```powershell
# PowerShell: эквивалентный объектный конвейер
Get-Process | Where-Object { $_.Name -like "*node*" } | Select-Object Id, WorkingSet64
```

Несколько практических следствий:

1. **Нет проблем с кавычками.** В Bash конвейеры полны «гимнастики» с кавычками в `awk '{…}'`, потому что вы встраиваете мини-программу в строку. В PowerShell стадия конвейера — это обычная команда с обычными параметрами.
2. **Нет хрупкости при парсинге текста.** Если имя столбца меняется или формат сдвигается, `awk '{print $6}'` молча ломается. В PowerShell переименование свойства объекта или смена источника приводит к явной ошибке.
3. **Не нужны `head`/`tail` для отбора.** `Select-Object -First N` и `-Last N` встроены.
4. **В конвейер можно передать любой объект PowerShell**: массивы, хеш-таблицы, .NET-типы и результат произвольных методов.

Вы также можете использовать `|`, чтобы передать объекты в `foreach` или `Where-Object` без промежуточного `xargs` или `for`.

## 11. Процессы и службы

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Список процессов | `ps aux` | `Get-Process` |
| Убить процесс по PID | `kill 1234` | `Stop-Process -Id 1234` |
| Убить по имени | `pkill firefox` | `Stop-Process -Name firefox` |
| Найти процесс по имени | `ps aux \| grep chrome` | `Get-Process -Name chrome` |
| CPU/память процесса | `top -p 1234` | `Get-Process -Id 1234 \| Select-Object CPU, WorkingSet64` |
| Список служб | `systemctl list-units --type=service` | `Get-Service` |
| Запустить службу | `systemctl start nginx` | `Start-Service nginx` |
| Остановить службу | `systemctl stop nginx` | `Stop-Service nginx` |
| Перезапустить службу | `systemctl restart nginx` | `Restart-Service nginx` |
| Мониторинг в реальном времени | `top` / `htop` | `Get-CimInstance Win32_PerfFormattedData_PerfOS_Processor` (Windows) |

```bash
# Bash
pkill -f "python3 server.py"
```

```powershell
# PowerShell
Get-Process python* -ErrorAction SilentlyContinue |
    Where-Object { $_.Path -like "*server.py*" } |
    Stop-Process
```

`Get-Process`, `Stop-Process`, `Start-Process` — это глаголы, работающие с объектами процессов. Та же конвенция «Глагол-Существительное» (`Get-*`, `Set-*`, `Add-*`, `Remove-*`, `Start-*`, `Stop-*`, `New-*`, `Test-*`, `Find-*`) — это самый важный паттерн PowerShell, который нужно выучить. Зная набор глаголов, вы можете предсказать название большинства команд.

## 12. Сеть

| Задача | Bash | PowerShell |
| --- | --- | --- |
| HTTP GET | `curl http://example.com` | `Invoke-WebRequest http://example.com` (алиас `iwr`) |
| Скачать файл | `curl -o out file.url` | `Invoke-WebRequest file.url -OutFile out` |
| Отправить JSON | `curl -H "Content-Type: application/json" -d '{…}' url` | `Invoke-RestMethod -Uri url -Method Post -ContentType 'application/json' -Body $json` |
| DNS-запрос | `dig example.com` / `nslookup` | `Resolve-DnsName example.com` (Windows) |
| Пинг | `ping host` | `Test-Connection host` |
| Проверить порт | `nc -zv host 80` | `Test-NetConnection host -Port 80` |
| Слушающие порты | `ss -tlnp` / `netstat -tlnp` | `Get-NetTCPConnection -State Listen` |
| Сетевые интерфейсы | `ip addr` | `Get-NetIPInterface` / `Get-NetAdapter` |

```bash
# Bash
curl -s -X POST https://api.example.com/v1/items \
     -H "Content-Type: application/json" \
     -d '{"name":"widget"}'
```

```powershell
# PowerShell
$body = @{ name = "widget" } | ConvertTo-Json
Invoke-RestMethod -Uri https://api.example.com/v1/items `
                  -Method Post `
                  -ContentType "application/json" `
                  -Body $body
```

Обратите внимание: в PowerShell для переноса строки используется обратная кавычка (`` ` ``), а в Bash — обратный слэш `\`. `Invoke-RestMethod` также автоматически десериализует JSON-ответы в объекты PowerShell, поэтому вы можете продолжать конвейер на результате без вызова `jq`.

## 13. Работа с JSON, CSV и другими форматами данных

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Парсинг JSON | `jq '.field' data.json` | `Get-Content data.json \| ConvertFrom-Json` |
| Объект в JSON | `echo "$x" \| jq .` | `$x \| ConvertTo-Json` |
| Импорт CSV | `awk -F, '…' file.csv` | `Import-Csv file.csv` |
| Экспорт в CSV | `… > out.csv` | `… \| Export-Csv out.csv -NoTypeInformation` |
| Фильтрация строк CSV | `awk -F, '$3=="done"' file.csv` | `Import-Csv file.csv \| Where-Object { $_.Status -eq "done" }` |
| Сумма столбца CSV | `awk -F, '{s+=$2} END{print s}' file.csv` | `Import-Csv file.csv \| Measure-Object -Property Amount -Sum` |

```bash
# Bash
jq '.items[] | select(.price > 100) | .name' orders.json
```

```powershell
# PowerShell
Get-Content orders.json | ConvertFrom-Json |
    Select-Object -ExpandProperty items |
    Where-Object { $_.price -gt 100 } |
    Select-Object name
```

`ConvertFrom-Json` и `ConvertTo-Json` в PowerShell работают симметрично с `Import-Csv`/`Export-Csv`, а результат — это объект, который можно передать в любой конвейер. В Bash эквивалент требует вызова `jq` (или Python/Perl).

## 14. Дата и время

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Текущая дата | `date` | `Get-Date` |
| Форматированная дата | `date +%Y-%m-%d` | `Get-Date -Format "yyyy-MM-dd"` |
| Unix-время戳 (timestamp) | `date +%s` | `[DateTimeOffset]::Now.ToUnixTimeSeconds()` |
| Timestamp → дата | `date -d @1690000000` | `[DateTimeOffset]::FromUnixTimeSeconds(1690000000).LocalDateTime` |
| 7 дней назад | `date -d "7 days ago"` | `(Get-Date).AddDays(-7)` |
| Разница между датами | ручной расчёт | `(Get-Date "2025-01-01") - (Get-Date "2024-01-01")` |

```bash
# Bash
echo "7 дней назад: $(date -d '7 days ago' +'%F')"
```

```powershell
# PowerShell
"7 дней назад: $((Get-Date).AddDays(-7).ToString('yyyy-MM-dd'))"
```

В PowerShell даты — это объекты `System.DateTime` / `DateTimeOffset` с богатым набором свойств и методов: `AddDays`, `AddHours`, `DayOfWeek`, `Year`, `ToString(format)`, арифметические операторы и многое другое. В Bash нет встроенного типа даты — нужно обращаться к утилите `date`.

## 15. Обработка ошибок

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Код выхода последней команды | `$?` | `$?` (True/False) или `$LASTEXITCODE` |
| Остановка при ошибке | `set -e` | `$ErrorActionPreference = "Stop"` |
| Try / catch | `if ! cmd; then …; fi` | `try { … } catch { … } finally { … }` |
| Сообщение об ошибке | `echo "err" >&2` | `Write-Error "message"` |
| Список ошибок | N/A | `$Error` (автоматическая переменная) |
| Подавить ошибки | `2>/dev/null` | `-ErrorAction SilentlyContinue` или `-EA 0` |

```bash
# Bash
set -euo pipefail
if ! result=$(ping -c 1 host); then
    echo "Хост недоступен" >&2
    exit 1
fi
```

```powershell
# PowerShell
$ErrorActionPreference = "Stop"
try {
    Test-Connection -ComputerName host -Count 1 | Out-Null
    Write-Output "Хост доступен"
}
catch {
    Write-Error "Хост недоступен: $_"
    exit 1
}
```

В PowerShell есть полноценная модель исключений первого класса (наследованная от .NET): `try`/`catch`/`finally`, пользовательские типы исключений, потоки неостанавливающих ошибок и переключатель `$ErrorActionPreference`, который меняет реакцию команд на ошибки. В Bash нет настоящего механизма исключений — только коды возврата и несколько специальных опций (`-e`, `-u`, `-o pipefail`).

## 16. Функции

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Объявление | `fn() { …; }` | `function fn { … }` или `fn { … }` |
| Параметры | позиционные: `$1`, `$2` | именованные и позиционные: `param($x, [switch]$Force)` |
| Возврат значения | stdout последней команды | объекты через `return` или `Write-Output` |
| Код возврата | `return 0` / `return 1` | `return 0` / `exit 1` |

```bash
# Bash
greet() {
    local name="$1"
    echo "Привет, $name"
}
greet John
```

```powershell
# PowerShell
function Get-Greeting {
    param(
        [Parameter(Mandatory)] [string]$Name,
        [switch]$Loud
    )
    $msg = "Привет, $Name"
    if ($Loud) { $msg = $msg.ToUpper() }
    Write-Output $msg
}
Get-Greeting -Name John -Loud
```

В PowerShell функции писать *удобнее*, потому что:

- Параметры **типизированы и именованные**, могут нести атрибуты `Mandatory`, `ValidateRange`, `ValidateSet`.
- Функция может возвращать **объекты**, а не только текст.
- Можно использовать блоки `param`, `begin`/`process`/`end` (что делает функцию естественной в конвейере), а также `[CmdletBinding()]` для наследования общих параметров: `-Verbose`, `-ErrorAction`, `-WhatIf`.

## 17. Модули и расширяемость

| Задача | Bash | PowerShell |
| --- | --- | --- |
| Установка пакетов | `apt install …` / `brew install …` | `Install-Module …` (PowerShell Gallery) или `winget` для приложений |
| Подключение модуля | `source ./lib.sh` | `Import-Module Name` |
| Список установленных | зависит от ОС | `Get-Module -ListAvailable` |
| Алиасы | `alias ll='ls -la'` | `Set-Alias ll Get-ChildItem` |
| Настройка промпта | правка `~/.bashrc`, переменная `PS1` | правка `$PROFILE`, функция `Prompt` |

Расширения Bash существуют в виде shell-функций, алиасов или отдельных исполняемых файлов. Расширения PowerShell существуют в виде **модулей**: пакетированных, версионируемых и доступных для обмена через PowerShell Gallery (похоже на `pip`/`npm` для PowerShell). Вы можете установить целый набор инструментов одной строкой:

```powershell
Install-Module -Name posh-git -Scope CurrentUser
```

## 19. Когда что использовать

**Выбирайте Bash, если:**

- Вы работаете в Linux/Unix, и всё нужное уже существует в виде текстовых утилит (`grep`, `awk`, `sed`, `find`, `xargs`).
- Вам нужны максимально компактные и переносимые скрипты, работающие на множестве Unix-систем.
- Ваша работа в значительной степени связана с преобразованием текста.

**Выбирайте PowerShell, если:**

- Вы администрируете Windows-системы или смешанную парку Windows/Linux.
- Вы работаете с .NET, Azure, Active Directory, Exchange, IIS или другими экосистемами Microsoft.
- Вам нужны строгая типизация, настоящие исключения и последовательный API в формате «Глагол-Существительное» для сотен команд.
- Ваши задачи имеют объектную природу (процессы, службы, ключи реестра, пользователи AD), а не строковую.

Поскольку PowerShell 7+ кросс-платформенна и распространяется как `pwsh` для Linux и macOS, вы также можете использовать **один язык на всех трёх ОС** — и это одно из его самых привлекательных преимуществ на сегодняшний день.

## 20. Итоги

Две оболочки решают одни и те же задачи с принципиально разной моделью мышления:

- **Bash** — это *текстовый конвейер* вокруг небольшого набора универсальных инструментов. Уверенное владение означает знание того, как комбинировать `grep`, `sed`, `awk`, `find` и другие утилиты, а также комфорт с позиционными столбцами, `$1`/`$2` и кодами возврата.

- **PowerShell** — это *типизированный объектно-ориентированный скриптовый язык* вокруг .NET-рантайма. Уверенное владение означает изучение паттерна «Глагол-Существительное», модели `param`/конвейер/свойства и мышление в терминах свойств, а не столбцов.

Как только вы осмыслите это фундаментальное различие — **Bash = текст, PowerShell = объекты** — почти все остальные синтаксические отличия между двумя языками становятся предсказуемыми.
