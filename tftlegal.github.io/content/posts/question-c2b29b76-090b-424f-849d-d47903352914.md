# Полное руководство по Multi-Token Prediction (MTP)

## 1. Введение в концепцию
**Multi-Token Prediction (MTP)** — это современный подход к обучению языковых моделей, при котором нейросеть обучается предсказывать не один следующий токен (как в классическом Next-Token Prediction), а последовательность из нескольких будущих токенов одновременно.

**Почему это важно?**
Классический подход заставляет модель делать «короткие прыжки», что может приводить к потере глобального контекста. MTP заставляет модель учитывать долгосрочные зависимости и планировать структуру предложения на несколько шагов вперед. Это аналогично тому, как шахматист планирует не только следующий ход, но и комбинацию из трех ходов.

## 2. Архитектурные особенности
Архитектура MTP базируется на принципе разделения ответственности между общим представлением и специализированными задачами.

*   **Shared Backbone (Общая основа):** Мощный трансформер (например, архитектура Llama или GPT), который извлекает контекстуальные эмбеддинги из входной последовательности.
*   **Specialized Prediction Heads (Специализированные головы):** Набор независимых линейных слоев (или небольших сетей), каждая из которых отвечает за предсказание конкретной позиции в будущем ($t+1, t+2, \dots, t+n$).

**Преимущество:** Общий бэкбон получает более богатый градиентный сигнал, так как он вынужден предоставлять информацию, достаточную для предсказания всей цепочки токенов сразу.

## 3. Методы обучения и функции потерь

Для эффективного обучения MTP используются следующие механизмы:

### Функции потерь (Loss Functions)
1.  **CrossEntropyLoss:** Основная функция для оценки точности предсказания каждого токена в последовательности.
2.  **Weighted Multi-Task Loss:** Поскольку предсказание токена через 5 шагов сложнее, чем через 1, часто применяется взвешивание:
    $$L_{total} = \sum_{i=1}^{n} \lambda_i \cdot \text{CrossEntropy}(y_{t+i}, \hat{y}_{t+i})$$
    где $\lambda$ — коэффициенты важности для каждой головы.

### Стратегии оптимизации
*   **Multi-Task Learning:** Модель обучается как на основной задаче (Next Token), так и на вспомогательных (Multi-Step Prediction).
*   **Curriculum Learning:** На ранних этапах обучения модель фокусируется на ближних токенах, постепенно переключая внимание на более далекие позиции.

## 4. Преимущества и сценарии применения

### Ускорение инференса (Inference Acceleration)
MTP позволяет генерировать несколько токенов за один проход через бэкбон. Это значительно сокращает количество обращений к модели, что критически важно для высоконагруженных систем.

### Улучшение логического планирования
Модель лучше справляется с задачами, требующими структурной целостности:
*   Написание программного кода (где важны скобки и структура блоков).
*   Математические вычисления.
*   Сложные логические цепочки (Chain-of-Thought).

## 5. Сложности и ограничения
*   **Баланс градиентов:** Слишком сильный акцент на далеких токенах может ухудшить качество предсказания ближайшего токена.
*   **Вычислительная сложность:** Обучение требует больше памяти для хранения градиентов нескольких голов одновременно.
*   **Деградация точности:** При неправильной настройке весов $\lambda$ модель может начать «галлюцинировать» последовательностями, которые грамматически верны, но контекстуально неверны.

## 6. Практическая реализация (Python/PyTorch)

Ниже представлен исправленный и рабочий пример архитектуры MTP.

```python
import torch
from torch import nn
import torch.nn.functional as F

class MultiTokenPrediction(nn.Module):
    def __init__(self, hidden_size, num_heads, dropout_rate):
        super(MultiTokenPrediction, self).__init__()

        # Shared Backbone (упрощенная модель для примера)
        self.shared_backbone = nn.Sequential(
            nn.Linear(hidden_size, hidden_size),
            nn.ReLU(),
            nn.Dropout(dropout_rate)
        )

        # Специализированные головы для предсказания n токенов
        # Каждая голова предсказывает свой будущий токен
        self.prediction_heads = nn.ModuleList([
            nn.Linear(hidden_size, hidden_size) for _ in range(num_heads)
        ])

        # Финальные слои для словаря (Vocabulary Projection)
        # В реальных моделях это обычно один большой слой, но здесь для ясности разделен
        self.vocab_size = 50000
        self.output_projections = nn.ModuleList([
            nn.Linear(hidden_size, self.vocab_size) for _ in range(num_heads)
        ])

    def forward(self, x):
        # x shape: (batch_size, seq_len, hidden_size)
        # Проход через общую основу
        backbone_output = self.shared_backbone(x)

        # Берем последнее скрытое состояние для предсказания будущего
        # В трансформерах это обычно выход последнего слоя на последнем токене
        last_hidden_state = backbone_output[:, -1, :]

        outputs = []
        for i in range(len(self.prediction_heads)):
            # Каждая голова обрабатывает скрытое состояние и выдает вероятности
            head_out = self.prediction_heads[i](last_hidden_state)
            logits = self.output_projections[i](head_out)
            outputs.append(logits)

        # Возвращаем список логгитов для каждой позиции
        return outputs

# Параметры модели
HIDDEN_SIZE = 512
NUM_HEADS = 4  # Предсказываем 4 токена вперед
DROPOUT = 0.1

# Инициализация
model = MultiTokenPrediction(HIDDEN_SIZE, NUM_HEADS, DROPOUT)

# Пример входных данных (Batch=2, Seq_len=10, Hidden=512)
dummy_input = torch.randn(2, 10, HIDDEN_SIZE)
logits_list = model(dummy_input)

print(f"Количество голов: {len(logits_list)}")
print(f"Размер логгитов первой головы: {logits_list[0].shape}")
```

# Multi-Token Prediction (MTP)


**Multi-Token Prediction (MTP)** — это инновационная техника спекулятивного декодирования, которая позволяет большим языковым моделям генерировать текст в **1.4–2.2 раза быстрее** без потери качества ответов. В отличие от стандартного подхода, где модель предсказывает по одному токену за раз, MTP учит модель предсказывать несколько будущих токенов одновременно, а затем основной моделью проверяет их параллельно.

Технология получила широкое распространение благодаря интеграции в семейство моделей **Qwen3.6** от Alibaba, а также в экосистему **Unsloth** и **llama.cpp**.


## Как работает MTP: техническая реализация

### Принцип спекулятивного декодирования

В стандартном авторегрессивном генерации модель совершает **один forward-проход на каждый токен**. Это медленно, особенно на локальных устройствах.

MTP использует подход **«draft-then-verify»**:

1. **Draft-модель** (легковесная версия или специальный головной слой) предсказывает N будущих токенов.
2. **Основная модель** параллельно проверяет эти токены, принимая или отвергая их.
3. Если токены верны, они принимаются мгновенно; если нет — они заменяются корректными предсказаниями.

Это сокращает количество необходимых forward-проходов, так как один проход основной модели проверяет сразу несколько токенов.

### Ключевые параметры MTP

| Параметр | Описание | Рекомендуемое значение |
|----------|----------|------------------------|
| `--spec-type draft-mtp` | Включает MTP в llama.cpp | Обязателен |
| `--spec-draft-n-max` | Количество предсказываемых токенов за раз | 2 (оптимально) |
| `speculative_num_steps` | Аналог в SGLang/vLLM | 3 |
| `speculative_num_draft_tokens` | Количество токенов для проверки | 4 |

**Важно:** Не стоит полагать, что `2` — всегда оптимально. Производительность зависит от вашего оборудования. Рекомендуется тестировать значения от 1 до 6 и выбирать лучшее для вашей системы.

## Режимы мышления: Thinking vs Non-Thinking

Qwen3.6 поддерживает два режима работы, и MTP работает в обоих:

### Thinking Mode (режим размышления)

Подходит для сложных задач, требующих глубокого анализа.

| Тип задач | Температура | Top-P | Top-K |
|-----------|-------------|-------|-------|
| **Общие** | 1.0 | 0.95 | 20 |
| **Программирование** | 0.6 | 0.95 | 20 |

### Non-Thinking Mode (инструктивный режим)

Быстрый режим без явного "размышления" модели.

| Параметр | Значение |
|----------|----------|
| Температура | 0.7 |
| Top-P | 0.8 |
| Top-K | 20 |
| Presence Penalty | 1.5 |

Отключить мышление в llama.cpp:

```bash
--chat-template-kwargs '{"enable_thinking":false}'
```

### Preserve Thinking

Новая функция Qwen3.6 — сохранение цепочки размышлений в диалоге. Это увеличивает количество токенов, но улучшает качество в многошаговых беседах.

```bash
--chat-template-kwargs '{"preserve_thinking":true}'
```

## Частые проблемы и их решение

### 1. Абракадабра на выходе
- **Причина:** Использование CUDA 13.2.
- **Решение:** Используйте CUDA ≤13.1 или ≥13.3.

### 2. Медленная работа MTP
- **Причина:** Неправильный `--spec-draft-n-max`.
- **Решение:** Протестируйте значения от 1 до 6, выберите максимальную скорость на вашем оборудовании.

### 3. Нехватка памяти
- **Причина:** MTP требует +1 ГБ VRAM.
- **Решение:** Скачайте квант на уровень ниже (например, 3-bit вместо 4-bit).

### 4. Не работает MTP в llama.cpp
- **Решение:** Убедитесь, что используете **самую свежую** версию llama.cpp (MTP-поддержка добавлена в июле 2026).

## Итог: когда использовать MTP?

| Сценарий | Рекомендация |
|----------|--------------|
| **Локальный чат-бот** | Включайте MTP всегда — ускорение ощутимо. |
| **Кодинг-ассистент** | MTP + Thinking Mode (temp=0.6) — идеально. |
| **Высоконагруженный сервер** | Используйте NVFP4 + MTP на Blackwell. |
| **MacBook / ноутбук** | MTP через llama.cpp или Unsloth Studio. |
| **Ограниченная память** | Выбирайте 3-bit квант с MTP (экономия 2 ГБ). |

**MTP — это не просто «ещё один метод ускорения».** Это практический инструмент, который делает локальные LLM (27B–35B параметров) удобными для повседневного использования на потребительском оборудовании. Комбинация MTP с динамическими GGUF-квантами и NVFP4 даёт беспрецедентную производительность без потери качества.
