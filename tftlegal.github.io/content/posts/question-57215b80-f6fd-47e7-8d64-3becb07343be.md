# Разбор проблемы с исчерпанием ephemeral-портов NGINX

## Определение проблемы

Исчерпание ephemeral-портов NGINX происходит из-за большого количества соединений в статусе `TIME_WAIT`. Это обусловлено тем, что серверы закрывают соединения, но все еще ожидают ACK от клиента, что продолжает время жизни соединения до `2 * MSRTT + 2 * TCP_РТТ`, что может привести к истощению доступных портов.

## Анализ текущей конфигурации

Для начала необходимо проверить настройки NGINX для `location /ai/models/в1/message/async/1`, особенно параметры:

- `client_body_buffer_size`
- `client_body_single_buffer`
- `client_max_body_size`
- `client_body_temp_path`

Эти параметры отвечают за обработку больших тел запросов.

## Подтверждение конфигурации

Выполнить проверку синтаксиса конфигурации:

```bash
nginx -t
```

Затем перезагрузить NGINX:

```bash
service nginx reload
```

## Мониторинг системы

Необходимо настроить мониторинг памяти, дискового I/O, журналов ошибок и поведение приёмчиков (upstreams). Это поможет определить, потребуется ли дополнительное настройку буферов или увеличение конкурентности.

## Адаптация размеров буферов

Если потребуется, увеличить `client_body_buffer_size` до максимального ожидаемого размера тела запроса. Включить `client_body_single_buffer` и настроить `client_max_body_size` соответственно.

Пример настройки:

```nginx
location /ai/models/v1/message/async/1 {
    client_body_buffer_size 10m;
    client_body_single_buffer on;
    client_max_body_size 10m;
}
```

## Настройка хранилища буферов

Установить `client_body_temp_path` на диск с достаточно много свободной памятью для перенаправления больших буферов.

Пример:

```nginx
client_body_temp_path /var/tmp/nginx_body_buffers;
```

## Размеры swap/zram

При необходимости настроить размеры `swap` (swap) или `zram` (zram) на основе объема RAM и работы. Тонко настроить параметры `vm.` в `sysctl`, и отслеживать использование памяти и моментальные снимки для выбора между `zram` и дисковым `swap`.

Пример настройки `sysctl`:

```bash
echo "vm.swappiness = 10" >> /etc/sysctl.conf
echo "vm.dirty_ratio = 85" >> /etc/sysctl.conf
echo "vm.dirty_background_ratio = 75" >> /etc/sysctl.conf
```

## Проверка и роллбак

Готовить резервные планы, используя команды для проверки конфигурации и системных параметров, и быть готовыми к роллбаку в случае возникновения проблем.

## Определение эффективности

После изменений повторно проверить статистику памяти и I/O, чтобы убедиться, что ситуация времени ожидания разрешена и что система работает эффективно под высокой нагрузкой.

