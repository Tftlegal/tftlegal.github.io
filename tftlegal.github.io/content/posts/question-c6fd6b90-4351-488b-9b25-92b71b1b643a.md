# Гайд по развертыванию LLM-инференса на GTX 1050 (2GB) в Kubernetes

> **Важное примечание:** Из-за крайне малого объема видеопамяти (2GB) стандартный движок **vLLM не пригоден** для этой задачи (требуется минимум 4-8GB для работы PagedAttention). В данном руководстве мы развертываем **llama.cpp** с поддержкой CUDA, который предоставляет **OpenAI-совместимый API**, что позволяет использовать любые стандартные библиотеки (LangChain, AutoGPT и др.) так, будто вы используете vLLM.

## 1. Подготовка узла (Worker Node)

Чтобы Kubernetes мог использовать GPU, на физическом сервере должны быть установлены драйверы и рантайм.

### Установка драйверов и Toolkit
1. **Драйверы NVIDIA:** Установите версию 470+ (для архитектуры Pascal).
2. **NVIDIA Container Toolkit:**
   ```bash
   curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
   curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
     sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
     sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
   sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
   ```
3. **Настройка Containerd:**
   Отредактируйте `/etc/containerd/config.toml`, убедившись, что `default_runtime__name` установлен в `nvidia`, или добавьте соответствующий конфиг для `containerd`. Перезапустите службу: `systemctl restart containerd`.

### Развертывание Device Plugin
Для того чтобы ресурсы `nvidia.com/gpu` появились в кластере:
```bash
kubectl apply -f https://raw.githubusercontent.com/NVIDIA/nvidia-device-plugin/v0.14.0/deployments/static_gpu_device_plugin.yaml
```
*Проверка:* `kubectl get nodes -o custom-columns=NAME:.metadata.name,GPU:.status.allocatable` (должно быть `nvidia.com/gpu: 1`).

## 2. Выбор модели (Hardware-Specific)

На 2GB VRAM невозможно запустить модели 7B и выше даже с сильным квантованием.

*   **Рекомендуемые модели:**
    *   `Qwen2-0.5B` (Лучшее соотношение веса и качества).
    *   `TinyLlama-1.1B` (Если нужно чуть больше "интеллекта").
*   **Формат:** **GGUF** (обязательно).
*   **Квантование:** `Q4_K_M` или `Q3_K_L`.

## 3. Создание Docker-образа (Multi-stage)

Используем многоэтапную сборку для уменьшения размера образа и оптимизации бинарника.

**Dockerfile:**
```dockerfile
# Stage 1: Build
FROM nvidia/cuda:12.1.1-devel-ubuntu22.04 AS builder
RUN apt-get update && apt-get install -y git build-essential cmake libcurl4-openssl-dev
RUN git clone https://github.com/ggerganov/llama.cpp && \
    cd llama.cpp && mkdir build && cd build && \
    cmake .. -DGGML_CUDA=ON -DCMAKE_BUILD_TYPE=Release && \
    cmake --build . --config Release --parallel $(nproc)

# Stage 2: Runtime
FROM nvidia/cuda:12.1.1-runtime-ubuntu22.04
RUN apt-get update && apt-get install -y libcurl4 && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY --from=builder /llama.cpp/build/bin/llama-server /app/llama-server
# Копируйте модели в папку /app/models заранее или через InitContainer
EXPOSE 8080
ENTRYPOINT ["/app/llama-server"]
```

## 4. Развертывание в Kubernetes

Ключевой момент — выделение **Shared Memory** и ограничение **Context Size**.

**Deployment.yaml:**
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: llm-worker
spec:
  replicas: 1
  selector:
    matchLabels:
      app: llm-worker
  template:
    metadata:
      labels:
        app: llm-worker
    spec:
      containers:
      - name: llm-container
        image: your-registry/llm-gpu-image:latest
        resources:
          limits:
            nvidia.com/gpu: 1
          requests:
            nvidia.com/gpu: 1
        env:
        - name: NVIDIA_VISIBLE_DEVICES
          value: "0"
        - name: MODEL_PATH
          value: "/app/models/qwen2-0.5b-q4_k_m.gguf"
        args:
        - "--host"
        - "0.0.0.0"
        - "--port"
        - "8080"
        - "-m"
        - "/app/models/qwen2-0.5b-q4_k_m.gguf"
        - "-ngl"
        - "32"         # Количество слоев на GPU (для 0.5B хватит всех)
        - "-c"
        - "512"         # Ограничение контекста (критично для 2GB!)
        - "--ctx-size"
        - "512"
        - "-fa"         # Flash Attention (если поддерживается бинарником)
        livenessProbe:
          exec:
            command: ["/app/llama-server", "--help"] # Упрощенная проверка
          initialDelaySeconds: 30
          periodSeconds: 10
        volumeMounts:
        - name: shm
          mountPath: /dev/shm
      volumes:
      - name: shm
        emptyDir:
          medium: Memory
          sizeLimit: "2Gi"
```

## 5. Оптимизация и Траблшутинг

### Если возникает ошибка "Out of Memory" (OOM):
1.  **Уменьшите `-c` (Context Size):** Это самый быстрый способ освободить VRAM. Попробуйте `256`.
2.  **Уменьшите `-ngl` (Number of GPU Layers):** Если модель не влезает целиком, уменьшите число слоев (например, до `15`). Остальные слои будут обрабатываться на CPU.
3.  **Проверьте Shared Memory:** Убедитесь, что `sizeLimit` в `emptyDir` соответствует объему памяти.

### Мониторинг:
Для проверки загрузки GPU в реальном времени:
```bash
kubectl exec -it <pod-name> -- nvidia-smi
```
*Норма:* Использование памяти должно быть стабильным (не прыгать до 100% и не вызывать падения).

Используйте стандартный `Service` и `Ingress` для получения OpenAI-совместимого эндпоинта. Пример запроса:
```bash
curl http://llm.example.com/v1/chat/completions \
  -H "Content-Type: application/json" \

  }'
```
