🧠 Мульти-Агентный ответ:

Conventional Commits — это набор правил, как оформлять сообщения к коммитам в системе контроля версий (например, Git). Их цель — сделать историю изменений понятной как людям, так и программам, чтобы можно было автоматически генерировать changelog, определять новые версии и настраивать CI/CD‑процессы.

Сообщение коммита состоит из трёх частей:
1. Тип изменений — короткое слово, которое показывает, что именно сделано (например, feat для новой функции, fix для исправления бага).
2. Область — необязательная часть в скобках, указывающая, в какой части проекта произошли изменения (например, auth для модуля авторизации).
3. Тема — краткое описание самого изменения в повелительном наклонении.

Пример сообщения: fix(auth): исправить ошибку входа.

Основные типы:
- feat — добавление новой функции.
- fix — исправление ошибки.
- docs — изменения только в документации.
- style — правки форматирования кода, не влияющие на логику.
- refactor — рефакторинг, улучшение структуры без новых функций.
- test — добавление или изменение тестов.
- chore — рутинные задачи, связанные с поддержкой проекта (обновление зависимостей, настройка инструментов и т.д.).
- Есть и другие типы для специфичных случаев: build, ci, revert и т.п.

Важно, что тип сообщения описывает *что* изменилось, а не *как* это сделано. Благодаря этому можно:
- Автоматически формировать changelog, анализируя типы коммитов.
- Определять версию релиза (major, minor, patch) в соответствии с семантическим версионированием.
- Настраивать пайплайны CI/CD, например, запускать публикацию только при коммитах типа feat или fix.

Преимущества использования Conventional Commits:
- История проекта становится прозрачной и легко читаемой.
- Инструменты вроде conventional-changelog или semantic-release могут работать без дополнительной настройки.
- Просто искать нужные изменения по типу (например, показать только коммиты с типом fix).
- Стандарт совместим с популярными сервисами и плагинами, что упрощает интеграцию в существующие workflows.

Короче говоря, Conventional Commits — это простой и единый формат написания сообщений к коммитам, который помогает автоматизировать выпуск версий, вести changelog и делает работу с кодом более предсказуемой и удобной.
