### 🚩 Критические ошибки (Требуют немедленной доработки):

1.  **Ошибка в выборе модели (Логическая):** Вы пишете, что *Qwen2-0.5B* требует много VRAM, а *Phi-3 Mini* — "relatively lightweight". **Это неверно.** Qwen2-0.5B — это крошечная модель, которая идеально подходит для 2 ГБ VRAM. Phi-3 Mini (3.8B) в стандартном виде **не влезет** в 2 ГБ видеопамяти даже с квантованием, если не использовать экстремальное сжатие (например, 4-bit или ниже).
2.  **Ошибка в Dockerfile (Архитектурная):**
    *   Вы пытаетесь выполнить `rmmod nvidia` и `modprobe nvidia` внутри Dockerfile. **Это невозможно.** Контейнер не имеет прав на управление модулями ядра хоста.
    *   Вы устанавливаете `nvidia-cuda-toolkit` внутри образа, который уже базируется на `nvidia/cuda`. Это избыточно и раздувает образ.
    *   Команда `FROM` стоит в конце. В Dockerfile инструкции должны идти *после* `FROM`.
3.  **Ошибка в Docker Compose:** Вы пробрасываете `/dev/nvidia0` и `/dev/nvidia1`, но у пользователя только одна карта (GTX 1050). Это вызовет ошибку при запуске.

5.  **Отсутствие квантования:** Запустить любую современную LLM на 2 ГБ VRAM без использования `bitsandbytes` (4-bit/8-bit) или `llama.cpp` (GGUF) невозможно.

# Полный гайд по запуску LLM (Qwen2-0.5B) с поддержкой GPU на GTX 1050 через Docker

Данное руководство описывает процесс развертывания легковесной языковой модели в изолированном контейнере с использованием аппаратного ускорения NVIDIA.

## Шаг 1: Анализ ресурсов и выбор модели
**Ограничение:** GTX 1050 имеет всего 2 ГБ VRAM.
*   **Выбор:** **Qwen2-0.5B**. Она занимает около 1.5 ГБ VRAM в режиме FP16 или значительно меньше в квантованном виде.
*   **Почему не Phi-3 Mini?** Phi-3 Mini (3.8B) требует минимум 3-4 ГБ VRAM для работы в 4-битном квантовании, что превышает возможности вашей карты.

## Шаг 2: Подготовка хост-системы
Перед запуском Docker необходимо подготовить драйверы:
1.  **NVIDIA Driver**: Установите последнюю стабильную версию для вашей ОС.
2.  **NVIDIA Container Toolkit**: Это критически важный компонент. Он позволяет Docker "видеть" вашу видеокарту.
    *   *Ubuntu/Debian:* `sudo apt-get install -y nvidia-container-toolkit`
    *   *После установки:* `sudo systemctl restart docker`

## Шаг 3: Создание Docker-образа
Мы будем использовать базовый образ от NVIDIA, который уже содержит необходимые библиотеки CUDA.

Создайте файл `Dockerfile`:
```dockerfile
# Используем официальный образ с поддержкой PyTorch
FROM nvcr.io/nvidia/pytorch:23.10-py3

# Установка системных зависимостей
RUN apt-get update && apt-get install -y \
    git \
    && rm -rf /var/lib/apt/lists/*

# Установка библиотек для работы с LLM
# Мы используем bitsandbytes для квантования, если потребуется
RUN pip install --no-cache-dir \
    transformers \
    accelerate \
    sentencepiece \
    bitsandbytes \
    scipy

# Рабочая директория
WORKDIR /app

# Команда по умолчанию (запуск скрипта инференса)
ENTRYPOINT ["python3", "inference.py"]
```

## Шаг 4: Настройка инференса (MTP и модель)
Поскольку MTP (Multi-Token Prediction) — это архитектурная особенность, для стандартного запуска мы будем использовать библиотеку `transformers`.

Создайте файл `inference.py`:
```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_name = "Qwen/Qwen2-0.5B"

# Загрузка токенизатора и модели
# device_map="auto" автоматически распределит веса на GPU
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,
    device_map="auto"
)

prompt = "Explain what is a Large Language Model in one sentence."
inputs = tokenizer(prompt, return_tensors="pt").to("cuda")

with torch.no_grad():
    outputs = model.generate(**inputs, max_new_tokens=50)

print(tokenizer.decode(outputs[0], skip_special_tokens=True))
```

## Шаг 5: Контейнеризация и запуск
Создайте файл `docker-compose.yml`. Мы используем правильный синтаксис для проброса одной GPU.

```yaml
version: '3.8'
services:
  llm-service:
    build: .
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
    environment:
      - CUDA_VISIBLE_DEVICES=0
    volumes:
      - ./models:/app/models
```

## Шаг 6: Запуск и мониторинг
1.  **Сборка и запуск:**
    ```bash
    docker-compose up --build
    ```
2.  **Мониторинг памяти:**
    Откройте второй терминал и введите:
    ```bash
    nvidia-smi -l 1
    ```
    *Это позволит вам видеть в реальном времени, сколько VRAM потребляет контейнер.*

## Шаг 7: Оптимизация (если памяти не хватает)
Если вы столкнетесь с ошибкой `Out of Memory (OOM)`:
1.  Измените `torch_dtype=torch.float16` на использование 4-битного квантования (потребуется установка `bitsandbytes`).
2.  Уменьшите `max_new_tokens`.
3.  Убедитесь, что на хосте не запущены другие тяжелые приложения (браузеры с аппаратным ускорением и т.д.).
