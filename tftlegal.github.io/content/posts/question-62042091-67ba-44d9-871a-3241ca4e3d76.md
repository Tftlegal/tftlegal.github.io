🧠 Мульти-Агентный ответ:

Шаг 1. Создать Docker‑образ с Ansible и зависимостями

1.1. Создать директорию проекта и перейти в неё
mkdir ansible-docker-test
cd ansible-docker-test

1.2. Создать Dockerfile
Dockerfile
FROM alpine:latest

# Установим необходимые пакеты
RUN apk add --no-cache \
python3 py3-pip py3-cffi gcc musl-dev libffi-dev openssl-dev \
&& pip3 install --no-cache-dir ansible==9.* \
&& rm -rf /var/cache/apk/*

# Дополнительные плагины (например, ansible‑vault)
RUN pip3 install --no-cache-dir ansible-vault

# Установим рабочую директорию
WORKDIR /workspace

1.3. Собрать образ
docker build -t ansible-test:latest .

1.4. Проверить, что Ansible доступен
docker run --rm ansible-test:latest ansible --version

2.5. Проверить локально (без Docker‑Compose)

ansible-test:latest ansible-playbook -i /workspace/inventory/hosts.ini /workspace/playbooks/site.yml

Шаг 3. Настроить изоляцию среды через Docker‑Compose

3.1. Создать docker-compose.yml
docker-compose.yml
version: "3.8"

services:
ansible:
image: ansible-test:latest
container_name: ansible_test
volumes:
- ./ansible:/workspace
working_dir: /workspace
command: >
sh -c "
ansible-playbook -i /workspace/inventory/hosts.ini /workspace/playbooks/site.yml &&
echo '✅ Playbook executed successfully'
"
tty: true
stdin_open: true

# Опциональный тестовый хост
testhost:
image: alpine:latest
container_name: testhost
command: ["sh", "-c", "apk add --no-cache openssh-client && sleep infinity"]
networks:
- testnet
cap_add:

### - net_admin

networks:
testnet:
driver: bridge

3.2. Запустить изоляцию
docker-compose up --build

3.3. После завершения работы контейнера ansible_test можно посмотреть логи
docker logs ansible_test

Шаг 4. Автоматизировать тестирование в CI/CD

4.1. Пример GitHub Actions (.github/workflows/ansible-ci.yml)
name: Ansible CI

on:
push:
branches: [ main ]
pull_request:

jobs:
lint:
runs-on: ubuntu-latest
steps:
- uses: actions/checkout@v4
- name: Build image for lint
run: docker build -t ansible-test:lint .
- name: Run ansible-lint
run: |
docker run --rm -v ${{ github.workspace }}/ansible:/workspace -w /workspace \
ansible-test:lint ansible-lint roles/**/*.yml

test:
runs-on: ubuntu-latest
needs: lint
steps:
- uses: actions/checkout@v4
- name: Build image for test
run: docker build -t ansible-test:ci .
- name: Run playbook with docker-compose
run: |
docker-compose -f docker-compose.yml up --abort-on-container-exit

4.2. Пример GitLab CI (.gitlab-ci.yml)
stages:
- build
- test

build_image:
stage: build
image: docker:latest
services:
- docker:dind
script:
- docker build -t ansible-test:gitlab .

test_playbook:
stage: test
image: docker:latest
services:
- docker:dind
script:
- docker-compose up --abort-on-container-exit
only:
- main

4.3. Сохранение логов при падении (GitHub Actions)
- name: Save logs on failure
if: failure()
run: |
mkdir -p artifacts
docker logs ansible_test > artifacts/docker.log
- name: Upload logs
uses: actions/upload-artifact@v4
with:
name: ansible-logs
path: artifacts/

Шаг 5. Добавить проверку Lint и unit‑тесты для ролей

5.1. Добавить ansible-lint и molecule в Dockerfile (опционально)
Dockerfile (добавить в конец)
RUN pip3 install --no-cache-dir ansible-lint molecule docker==7.*

5.2. Запуск линтинга в CI (уже показано в шаге 4.1)

5.3. Molecule конфигурация для роли test_role
ansible/roles/test_role/molecule/default/molecule.yml
---
dependency:
name: galaxy
driver:
name: docker
platforms:
- name: instance
image: alpine:latest
pre_build_image: true
command: apk add --no-cache python3 py3-pip
provisioner:
name: ansible
verifier:
name: testinfra

ansible/roles/test_role/molecule/default/converge.yml
---
- hosts: all
become: true
roles:
- role: test_role

5.4. Запуск Molecule теста в CI (пример для GitHub Actions)
- name: Run Molecule test
run: |
docker run --rm -v ${{ github.workspace }}/ansible:/workspace -w /workspace \
ansible-test:ci bash -c "cd /workspace/roles/test_role && molecule test"
