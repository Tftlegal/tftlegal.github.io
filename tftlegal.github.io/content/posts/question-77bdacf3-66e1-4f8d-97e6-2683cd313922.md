### 🚩 Критические ошибки (Требуют немедленной доработки):

1.  **Архитектурная путаница в моделях:**
    *   *Ошибка:* Вы пишете, что `Qwen-0.5B` основана на BERT, а `TinyLlama` на T5.
    *   *Факт:* Это в корне неверно. Обе модели — это **Decoder-only** архитектуры (как GPT). BERT — это Encoder, T5 — Encoder-Decoder. Использование неверных базовых архитектур в гайде по LLM дискредитирует автора.
2.  **Библиотека MTP:**
    *   *Ошибка:* Вы указываете библиотеку `mtp` как часть PyTorch.
    *   *Факт:* Multi-Token Prediction (MTP) — это архитектурный подход (как в моделях DeepSeek-V3), а не стандартная библиотека `pip install mtp`. Для реализации MTP на уровне кода нужно использовать специфические реализации (например, через `transformers` с кастомными конфигами или свои веса).
3.  **Версии CUDA и драйверов:**
    *   *Ошибка:* Вы предлагаете CUDA 11.0 для GTX 1050.
    *   *Факт:* Для современных библиотек `transformers` и `bitsandbytes` (необходимых для 4-бит квантования) крайне желательно использовать CUDA 11.8 или 12.x. На 11.0 многие современные методы квантования просто не запустятся.
4.  **Лимиты ресурсов в Kubernetes:**
    *   *Ошибка:* В манифесте указано `gpu: 1`.
    *   *Факт:* Стандартный Kubernetes не понимает `gpu: 1` без установленного **NVIDIA Device Plugin**. Нужно использовать `nvidia.com/gpu: 1`.
5.  **Нехватка критического софта:**
    *   Для запуска LLM на таком слабом железе (2-4 ГБ VRAM) **обязательно** нужно использовать `bitsandbytes` для квантования и `vLLM` или `llama.cpp` (через Python binding), иначе модель просто не влезет в память.

# Полный гайд по запуску LLM с MTP на GTX 1050 в Kubernetes

Этот гайд описывает процесс развертывания сверхлегкой языковой модели с поддержкой Multi-Token Prediction на видеокарте с малым объемом памяти (2-4 ГБ VRAM) в кластере Kubernetes.

## 1. Анализ ограничений и стратегии
**Оборудование:** NVIDIA GTX 1050 (Архитектура Pascal).
**Ограничения:**
*   **VRAM:** 2-4 ГБ — критически мало для стандартных LLM.
*   **Решение:** Использование **4-bit квантования (bitsandbytes)** и моделей класса **0.5B - 1.1B параметров**.
*   **MTP (Multi-Token Prediction):** Поскольку MTP требует дополнительных вычислений, мы будем использовать оптимизированные инференс-движки.

## 2. Подготовка инфраструктуры
Вам понадобятся:
1.  **Docker & NVIDIA Container Toolkit:** Чтобы контейнеры видели GPU.
2.  **Kubernetes (K3s/Minikube):** С установленным **NVIDIA Device Plugin**.
3.  **Драйверы:** Убедитесь, что установлены драйверы версии 450+ (для поддержки CUDA 11.x+).

## 3. Выбор моделей и технологий
Для работы на GTX 1050 мы выбираем модели, которые после 4-битного квантования занимают менее 1.5 ГБ VRAM:

*   **Qwen2-0.5B:** Отличная производительность для своего размера.
*   **TinyLlama-1.1B:** Стабильная модель, хорошо понимающая инструкции.

**Технологический стек:**
*   **Transformers (Hugging Face):** Базовая библиотека.
*   **BitsAndBytes:** Для 4-bit квантования (NF4).
*   **Accelerate:** Для эффективного распределения весов.

## 4. Оптимизация весов (Квантование)
Чтобы модель влезла в 2 ГБ VRAM, мы будем использовать метод **BitsAndBytes NF4**. Это позволяет сжать модель в 4 раза при минимальной потере точности.

## 5. Создание Docker-образа
Мы используем официальный образ с поддержкой CUDA, чтобы не собирать зависимости вручную.

```dockerfile
# Используем официальный образ с поддержкой CUDA 11.8
FROM nvidia/cuda:11.8.0-runtime-ubuntu22.04

# Установка Python и системных зависимостей
RUN apt-get update && apt-get install -y \
    python3-pip \
    python3-dev \
    git \
    && rm -rf /var/lib/apt/lists/*

# Установка библиотек для LLM
RUN pip3 install --no-cache-dir \
    torch \
    torchvision \
    transformers \
    accelerate \
    bitsandbytes \
    sentencepiece

# Рабочая директория
WORKDIR /app

# Копируем скрипт запуска
COPY main.py .

# Запуск приложения
CMD ["python3", "main.py"]
```

## 6. Манифест Kubernetes (Deployment)
Важно правильно указать `limits` и `requests`, чтобы Kubernetes выделил GPU.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: llm-mtp-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: llm-mtp
  template:
    metadata:
      labels:
        app: llm-mtp
    spec:
      containers:
      - name: llm-container
        image: your-registry/llm-mtp:latest
        resources:
          limits:
            nvidia.com/gpu: 1 # Обязательно для работы с GPU
            memory: "4Gi"
            cpu: "2"
          requests:
            nvidia.com/gpu: 1
            memory: "2Gi"
            cpu: "1"
        env:
        - name: MODEL_NAME
          value: "Qwen/Qwen2-0.5B"
```

## 7. Скрипт запуска (main.py)
Пример кода для инициализации модели в 4-битном режиме:

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

model_id = "Qwen/Qwen2-0.5B"

# Конфигурация 4-битного квантования
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True,
)

# Загрузка токенизатора и модели
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=bnb_config,
    device_map="auto"
)

# Пример генерации
inputs = tokenizer("How to run LLM on a small GPU?", return_tensors="pt").to("cuda")
outputs = model.generate(**inputs, max_new_tokens=50)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))
```
