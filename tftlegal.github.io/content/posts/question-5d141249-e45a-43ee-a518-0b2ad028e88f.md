# PLAN.md — План разработки TurtleVerse 3D

## 1. Цель и ожидаемый результат

**Цель:** Разработать **TurtleVerse 3D** — интерактивное веб-приложение на базе Three.js, представляющее реалистичный 3D-аквариум с управляемыми черепахами, системой кормления, динамического освещения и полного цикла обслуживания (слив/наполнение воды).

**Ожидаемый результат:**
1.  Рабочее локальное приложение (Vite + React + TypeScript).
2.  Реалистичная 3D-сцена: стеклянный аквариум, вода с анимацией поверхности, грунт, камни, растения.
3.  2–4 процедурных 3D-черепахи с ИИ (конечный автомат), анимацией плавания и избеганием столкновений.
4.  Интерактивные системы: Кормление (система частиц), Освещение (пресеты цвета/интенсивности), Обслуживание (уровень воды с визуальной обратной связью).
5.  Надежный UI/UX: Русский интерфейс, боковая панель управления, индикаторы состояния, управление камерой.
6.  Автоматизированные тесты: Unit-тесты для логики (Zustand stores, AI states) и E2E-тесты (Playwright) для проверки ключевых сценариев.
7.  Production-ready сборка с оптимизированной производительностью (цель: 60 FPS).

## 2. Источники требований и приоритеты (AGENTS.md)

*Основной источник требований: `AGENTS.md` (Master Prompt).*

**Приоритеты:**
1.  **Реализм и Интерактивность:** Сцена должна быть визуально премиальной, а не статичной. Управление должно влиять на реальное 3D-состояние (освещение, уровень воды, поведение черепах).
2.  **Стабильность:** Отсутствие крашей WebGL, утечек памяти или координат NaN.
3.  **Полнота функционала:** Все кнопки должны работать. Запрещены «декоративные» UI-элементы без функционала.
4.  **Производительность:** 60 FPS на десктопе, 30 FPS на мобильных/слабых устройствах. Использовать инстансинг и delta-time.
5.  **Тестируемость:** Модульная архитектура, позволяющая юнит-тестировать логику и E2E-тестировать пользовательские флоу.

**Ключевые требования:**
*   **Стек:** TypeScript, Vite, Three.js, React, React Three Fiber (R3F), Drei, Zustand, Vitest, Playwright.
*   **Визуал:** Стеклянные стенки (корректная сортировка прозрачности), объем и поверхность воды, процедурные модели черепах (панцирь, голова, лапы), вариативные камни/растения.
*   **Логика:**
    *   FSM черепахи: `idle`, `swimming`, `exploring`, `resting`, `seeking_food`, `eating`, `selected`, `being_removed`, `outside_tank`.
    *   FSM обслуживания: `normal`, `preparing`, `draining`, `empty`, `cleaning`, `filling`, `restoring`, `completed`.
    *   Водная система: Уровень, прозрачность, течение, пузырьки.
*   **Ограничения:** Нет серверной инфраструктуры. Только локальные ресурсы. Нет CDN-зависимостей для ядра приложения.

**Уточнения и разрешения конфликтов:**
*   *Конфликт:* «Если доступна подходящая 3D-модель...». *Решение:* Внешние модели не предполагаются. **Обязательно:** Процедурная генерация геометрии черепах с использованием примитивов Three.js/кастомной геометрии для обеспечения офлайн-совместимости и защиты лицензии.
*   *Уточнение:* «Не использовать дорогие пост-эффекты без необходимости». *Решение:* Использовать стандартные PBR-материалы, прозрачные меши для воды/стекла и простые системы частиц. Избегать полного-скрин bloom/refraction, если это влияет на производительность.

## 3. Область работ и ограничения

**Область работ (Scope):**
*   Только Frontend-приложение.
*   Ядро 3D-сцены: Аквариум, Вода, Декор, Черепахи, Частицы (пузырьки, еда).
*   Управление состоянием: Глобальный стор для состояния приложения, данных черепах, параметров воды.
*   UI: Панели управления, статус-бары, модальные подтверждения.
*   Тестирование: Unit (логика) + E2E (взаимодействие с UI/Сценой).

**Ограничения:**
*   Нет backend-базы данных. Состояние сбрасывается при обновлении (опционально: сохранение настроек в localStorage).
*   Зависимость от WebGL. Необходимо обрабатывать корректный fallback, если WebGL недоступен.
*   Процедурные модели черепах должны выглядеть как черепахи, а не просто «блобы». Требует тщательного построения геометрии.
*   Коллизии камеры: Камера не должна легко проваливаться сквозь стеклянные стенки.

## 4. Архитектура и технологический стек

**Технологический стек:**
*   **Язык:** TypeScript (strict mode).
*   **Инструмент сборки:** Vite.
*   **UI Framework:** React 18+.
*   **3D Engine:** Three.js + React Three Fiber (R3F) + Drei.
*   **Управление состоянием:** Zustand (глобальное состояние, данные черепах, параметры воды).
*   **Стилизация:** Plain CSS с CSS Variables для единообразия темы (минимизация зависимостей).
*   **Тестирование:** Vitest (Unit), Playwright (E2E).

**Паттерн архитектуры:**
*   **Однонаправленный поток данных:** UI Components → Actions (Zustand) → Изменение состояния → R3F Components обновляются.
*   **Разделение ответственности (Separation of Concerns):**
    *   `src/app/`: React root, Store, Config.
    *   `src/scene/`: R3F компоненты (Tank, Water, Lighting, Camera).
    *   `src/turtle/`: Модель черепахи, логика ИИ, хуки анимации.
    *   `src/systems/`: Чистые логические модули (Кормление, Обслуживание, Коллизии), обновляющие стор.
    *   `src/ui/`: React UI компоненты (Панели, Кнопки).

**Ключевые модули:**
1.  **Store (`store.ts`):** Хранит `turtles[]`, `water`, `lighting`, `maintenanceState`, `selectedTurtleId`.
2.  **AI Engine (`TurtleAI.ts`):** Чистая функция/класс, принимающая состояние черепахи + окружение, возвращающая следующее состояние/скорость.
3.  **Scene Components:** Оборачивают объекты Three.js, подписываются на стор через R3F хуки.

## 6. Этапы реализации

### Этап 1: Настройка проекта и каркас
*   **Требование:** Vite + React + TS + R3F + Zustand.
*   **Задачи:**
    1.  Инициализация Vite проекта.
    2.  Установка зависимостей: `three`, `@react-three/fiber`, `@react-three/drei`, `zustand`, `vitest`, `playwright`.
    3.  Создание базового `App.tsx` с `<Canvas>`.
    4.  Создание начального Zustand store с заглушкой состояния.
*   **Результат:** Рендерится пустая 3D-сцена. Сборка проходит успешно.
*   **Файлы:** `package.json`, `src/app/App.tsx`, `src/app/store.ts`.

### Этап 2: Аквариум и окружение
*   **Требование:** Стеклянный аквариум, вода, субстрат, камни, растения.
*   **Задачи:**
    1.  Создание `Tank.tsx`: Box geometry с прозрачным материалом (physical material, transmission если возможно, иначе opacity + hack рефракции).
    2.  Создание `Water.tsx`: Plane для поверхности (анимированная normal map), Box для объема (прозрачный синий).
    3.  Создание `Decor.tsx`: Instanced meshes для камней (рандомизированный масштаб/поворот) и растений (простые конусы/плоскости).
    4.  Добавление ambient + directional света.
*   **Результат:** Визуально завершенный пустой аквариум.
*   **Файлы:** `src/scene/Tank.tsx`, `src/scene/Water.tsx`, `src/scene/Decor.tsx`.

### Этап 3: Модель черепахи и анимация
*   **Требование:** Процедурная черепаха, анимация плавания.
*   **Задачи:**
    1.  `TurtleModel.ts`: Сборка группы мешей (панцирь: сегмент сферы, тело: капсула, голова: сфера, лапы: боксы/капсулы).
    2.  `TurtleMesh.tsx`: R3F компонент, использующий модель.
    3.  `TurtleAnimation.ts`: Использование `useFrame` для вращения лап на основе времени и скорости.
    4.  Добавление 2 черепах в сцену со случайными позициями.
*   **Результат:** Две анимированные черепахи случайно плавают.
*   **Файлы:** `src/turtle/TurtleModel.ts`, `src/turtle/TurtleMesh.tsx`.

### Этап 4: ИИ и управление (Steering)
*   **Требование:** FSM, коллизии, границы.
*   **Задачи:**
    1.  Определение типов `TurtleState`.
    2.  Реализация `TurtleAI.ts`:
        *   Обновление скорости на основе состояния.
        *   Проверка границ: Разворот при ударе в стенку.
        *   Разделение: Отдаление от других черепах.
    3.  Интеграция с `TurtleMesh.tsx` через `useFrame`.
    4.  Обновление стора позициями черепах (с троттлингом) для UI-выбора.
*   **Результат:** Черепахи плавают реалистично, избегают стенок и друг друга.
*   **Файлы:** `src/turtle/TurtleAI.ts`, `src/systems/CollisionSystem.ts`.

### Этап 5: Взаимодействие и выбор
*   **Требование:** Клик для выбора, UI панель.
*   **Задачи:**
    1.  Добавление `onClick` в `TurtleMesh.tsx` -> обновление `selectedTurtleId` в сторе.
    2.  Создание `TurtlePanel.tsx`: Отображение ID, Состояния, Кнопок (Забрать/Вернуть).
    3.  Реализация логики «Забрать»: Установить состояние `being_removed`, анимация вверх, затем `outside_tank`.
    4.  Реализация логики «Вернуть»: Анимация в воду, установка состояния `swimming`.
*   **Результат:** Пользователь может выбрать черепаху и переместить ее в/из аквариума.
*   **Файлы:** `src/ui/TurtlePanel.tsx`, `src/app/store.ts`.

### Этап 6: Система кормления
*   **Требование:** Частицы еды, поведение поедания.
*   **Задачи:**
    1.  `FeedingSystem.ts`: Управление пулом частиц еды (маленькие сферы).
    2.  UI: Кнопка «Покормить» -> спавн N частиц со случайным X/Z, Y=поверхность воды.
    3.  Обновление ИИ: Если есть еда, ближайшая черепаха переходит в `seeking_food`.
    4.  Поедание: Если черепаха близко к еде, удалить еду, перейти в `eating`, затем `idle`.
*   **Результат:** Кормление работает, черепахи реагируют на еду.
*   **Файлы:** `src/systems/FeedingSystem.ts`, `src/ui/FeedingPanel.tsx`.

### Этап 7: Система освещения
*   **Требование:** Пресеты, интенсивность, цвет.
*   **Задачи:**
    1.  `Lighting.tsx`: Подписка на состояние `lighting` в сторе.
    2.  Интерполяция цвета/интенсивности света с помощью `lerp` в `useFrame`.
    3.  UI: `LightingPanel.tsx` со слайдерами и кнопками пресетов.
*   **Результат:** Освещение меняется плавно и влияет на сцену.
*   **Файлы:** `src/scene/Lighting.tsx`, `src/ui/LightingPanel.tsx`.

### Этап 8: Обслуживание (Уровень воды)
*   **Требование:** Цикл слива/наполнения, FSM.
*   **Задачи:**
    1.  `MaintenanceSystem.ts`: Логика FSM.
    2.  `Water.tsx`: Масштабирование Y объема/меши воды на основе `waterLevel` (0.0–1.0).
    3.  UI: `MaintenancePanel.tsx`.
    4.  Логика: «Слить» -> `waterLevel` уменьшается со временем. «Наполнить» -> увеличивается.
    5.  Ограничение: Нельзя слить воду, если черепахи внутри (нужно вынести их или авто-извлечение).
    6.  Визуал: Интенсивность системы частиц пузырьков зависит от потока.
*   **Результат:** Уровень воды анимируется вверх/вниз. Черепахи блокируются, если вода низкая.
*   **Файлы:** `src/systems/MaintenanceSystem.ts`, `src/ui/MaintenancePanel.tsx`.

### Этап 9: Полировка UI и адаптивность
*   **Требование:** Русский UI, чистый макет, обработка ошибок.
*   **Задачи:**
    1.  Перевод всех меток на русский язык.
    2.  Стилизация панелей: Dark mode, эффект glassmorphism.
    3.  Добавление `StatusBar.tsx`: Отображение FPS, % воды, количества черепах.
    4.  Обработка потери контекста WebGL.
    5.  Мобильная адаптивность: Сворачивание панелей на маленьких экранах.
*   **Результат:** Профессионально выглядящий UI.
*   **Файлы:** `src/ui/*.tsx`, `src/styles/*.css`.

### Этап 10: Тестирование и оптимизация
*   **Требование:** Vitest, Playwright, 60 FPS.
*   **Задачи:**
    1.  Unit-тесты:
        *   Действия стора (добавление/удаление черепахи, смена состояния).
        *   Логика ИИ (коллизия с границей).
    2.  E2E-тесты (Playwright):
        *   Загрузка приложения.
        *   Клик «Кормить» -> Увеличение количества еды.
        *   Выбор черепахи -> Появление панели.
        *   Начало слива -> Уменьшение уровня воды.
    3.  Производительность: Проверка на утечки памяти (dispose геометрий при unmount).
*   **Результат:** Все тесты проходят. Нет критических ошибок в консоли.
*   **Файлы:** `src/tests/**`, `vitest.config.ts`.

## 7. Тестирование и валидация

**Unit-тесты (Vitest):**
*   **Store:**
    *   `addTurtle()` увеличивает количество.
    *   `removeTurtle(id)` уменьшает количество.
    *   `setWaterLevel(0)` обновляет состояние.
*   **ИИ:**
    *   Черепаха у стенки + вектор вперед -> Новый вектор направлен внутрь.
    *   Есть еда + Черепаха idle -> Состояние становится `seeking_food`.
*   **FSM Обслуживания:**
    *   Переход `normal` -> `draining` требует `turtlesInTank === 0` (или логика авто-извлечения).
    *   Завершение `draining` -> Состояние становится `empty`.

**E2E-тесты (Playwright):**
*   **Сценарий 1: Базовое взаимодействие**
    1.  Навигация на `/`.
    2.  Ожидание 2 черепах в DOM (или сцене).
    3.  Клик кнопки «Покормить».
    4.  Ожидание появления частиц еды (визуальная проверка или проверка состояния).
*   **Сценарий 2: Цикл обслуживания**
    1.  Выбрать все черепахи, нажать «Вынести».
    2.  Нажать «Слить воду».
    3.  Дождаться, пока полоса уровня воды достигнет 0%.
    4.  Нажать «Наполнить воду».
    5.  Дождаться, пока уровень воды достигнет 100%.
*   **Валидация:**
    *   Нет ошибок JavaScript в консоли.
    *   FPS держится выше 30.

**Ручные проверки:**
*   Орбитальная камера не проваливается сквозь стекло.
*   Черепахи не застревают в углах.
*   Пресеты освещения заметно меняют цвет сцены.

## 8. Критерии приёмки (Definition of Done)

1.  **Сборка:** `npm run build` завершается успешно без ошибок.
2.  **Визуал:**
    *   Аквариум выглядит как стеклянный.
    *   Поверхность воды анимирована.
    *   Черепахи выглядят как черепахи (не как блобы).
    *   Изменения освещения влияют на сцену.
3.  **Функционал:**
    *   Можно добавлять/удалять черепах (1-4).
    *   Можно кормить черепах.
    *   Можно выбрать черепаху и увидеть информацию.
    *   Можно слить/наполнить воду.
    *   Черепахи реагируют на уровень воды (не могут плавать при пустом аквариуме).
4.  **Качество кода:**
    *   Включен strict mode TypeScript.
    *   Нет типов `any` в ядре логики.
    *   Компоненты модульные.
5.  **Тесты:**
    *   Все Unit-тесты проходят.

## 9. Риски, зависимости и допущения

**Риски:**
1.  **Сортировка прозрачности:** Стекло и вода могут рендериться некорректно (z-fighting или невидимые объекты).
    *   *Митигация:* Использовать `depthWrite: false` для воды, корректировать `renderOrder` для стекла/воды/черепах.
2.  **Производительность:** Слишком много частиц или сложные шейдеры.
    *   *Митигация:* Использовать инстансинг для камней/растений. Ограничить количество пузырьков до 100. Использовать простые шейдеры.
3.  **Баги ИИ:** Черепахи застревают или дрожат.
    *   *Митигация:* Использовать демпфирование/lerp для изменения скорости. Добавить детекцию «залипания» (низкая скорость + высокий шум) для принудительной смены состояния.
4.  **Нестабильность Playwright:** Проблемы с таймингом в 3D-сцене.
    *   *Митигация:* Использовать `waitForFunction` для проверки переменных состояния в объекте window (экспортировать стор в window для тестирования).

**Зависимости:**
*   `three`, `@react-three/fiber`, `@react-three/drei`, `zustand`.
*   `vite`, `react`, `typescript`.
*   `vitest`, `@playwright/test`.

**Допущения:**
*   Пользователь использует современный браузер с поддержкой WebGL2.
*   Нет внешних API-вызовов.
*   Размер аквариума по умолчанию: 8x4x5 единиц.
*   Начальное количество черепах: 2.
