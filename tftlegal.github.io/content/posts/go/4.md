# SQL

## Что такое Транзакции?

Представьте, что у вас есть сложная операция, которую нужно выполнить в системе. Допустим, вы хотите, чтобы ваши деньги пошли с одного счёта на другой, или вы хотите обновить несколько данных в базе.

**Транзакция — это набор связанных операций, которые должны выполняться как единое целое.**

Проще говоря, транзакция гарантирует, что вы либо **успешно** сделаете всё, что запланировали, либо **ничего** не сделаете, если что-то пошло не так.

Это принцип **Атомарности** (Atomicity):

*   **Если всё ОК:** Все операции применяются и сохраняются в базе данных (COMMIT).
*   **Если что-то пошло не так:** Все уже выполненные операции отменяются (ROLLBACK), и данные остаются прежними.

**Пример с деньгами:** Если вы пытаетесь перевести 100 рублей, но во время операции произошёл сбой, вы не хотите, чтобы часть денег ушло, а другая часть — не успела списаться. Транзакция гарантирует, что либо **списание + зачисление** произойдут, либо **ничего не произойдет**.

## 🛒 Пример с Заказом (Сложная логика)

Ваш сценарий — это классический пример, где транзакции незаменимы:

**Ситуация:** Несколько пользователей одновременно оформляют заказ на одну услугу. Система должна:
1.  Записать новый `Order` в таблицу `orders`.
2.  Обновить таблицу `inventory` (уменьшить количество товара).
3.  Обновить таблицу `user_balance` (списать средства).

Если бы вы просто выполняли эти три действия по очереди, и после успешного `INSERT` в `orders` возникла бы ошибка при попытке `UPDATE` `inventory`, вы бы получили **частичный успех**, а данные в системе были бы "сломанными".

**Как это решает Транзакция:**

Вместо того чтобы выполнять три отдельных команды, вы оборачиваете всё в одну транзакцию, которая выглядит так:

1.  **НАЧАЛО:** `BEGIN TRANSACTION`
2.  **Шаг 1 (Заказ):** `INSERT INTO orders...`
3.  **Шаг 2 (Списание):** `UPDATE inventory SET stock = stock - 1 WHERE item_id = X`
4.  **Шаг 3 (Погашение):** `UPDATE user_balance SET balance = balance - 100 WHERE user_id = Y`
5.  **ЗАВЕРШЕНИЕ:** `COMMIT TRANSACTION`

**Результат:**
*   Если все 3 шага прошли успешно $\rightarrow$ **COMMIT**. Данные сохранены корректно.
*   Если на любом шаге произошла ошибка $\rightarrow$ **ROLLBACK**. Все изменения, сделанные до этого момента, отменяются.

## 🖥️ Как микросервис использует это в Go

В вашем Go-сервисе (в слое репозитория) вы будете использовать клиент базы данных (например, `pgx`):

```go
func (r *Repository) ProcessOrder(userID int, itemID int, amount float64) error {
    // 1. Устанавливаем транзакцию
    tx, err := r.dbConn.BeginTx() // Получение начальной транзакции
    if err != nil {
        return err
    }
    
    // 2. Оборачиваем всю логику в контексте транзакции
    defer tx.Commit() // Если всё прошло успешно, фиксируем изменения

    // 3. Операция 1: Добавить заказ (CREATE)
    // Здесь мы используем tx, чтобы гарантировать, что это часть транзакции
    orderID, err := r.insertOrder(tx, userID, itemID) 
    if err != nil {
        // Если ошибка, defer.Commit() не сработает, но tx.Rollback() (в случае ошибки)
        // или просто выход из функции по ошибке отменяет изменения.
        return err
    }

    // 4. Операция 2: Уменьшить инвентарь (UPDATE)
    err = r.updateInventory(tx, itemID)
    if err != nil {
        // Если здесь ошибка, мы не доходим до Commit(), и всё откатится!
        return err 
    }
    
    // 5. Операция 3: Списать средства (UPDATE)
    err = r.updateBalance(tx, userID, amount)
    if err != nil {
        return err
    }

    // Если все успешно, tx.Commit() будет вызван в конце, фиксируя все изменения.
    return nil
}
```

**Суть:** Транзакция позволяет вам объединить несколько логических действий в одну атомарную операцию, гарантируя, что ваш заказ либо *полностью* зафиксирован, либо *полностью* отменен.
