# AWS Восстановление данных Vault из бэкапа (перенос между aws аккаунтами с разными KMS ключами)

## Краткое содержание

Восстановление снапшота Vault полностью заменяет текущее хранилище данными из снимка. После этого снова становятся валидными root-токен и recovery-ключи исходного кластера. Если исходный кластер использовал AWS KMS, для расшифровки данных во время восстановления нужен доступ к старому KMS-ключу. Это особенно важно при переносе между AWS-аккаунтами с разными KMS-ключами. В процессе seal migration система показывает соответствующее сообщение о миграции. Текст описывает процедуру восстановления данных Vault из бэкапа.

## Полная статья

Thank you for reading this post, don't forget to subscribe!

- 

Восстановление снапшота**полностью заменяет**текущее хранилище Vault содержимым снапшота.

- 

После восстановления снова становятся валидными**root-токен**и**recovery-ключи**от**исходного**кластера (того, где снимали снапшот).

- 

Если исходный кластер использовал**AWSKMS**(возможно, в другом регионе), на время восстановления понадобится доступ к**старому KMS-ключу**, чтобы расшифровать данные.

- 

Во время**миграции типа seal**вы увидите`Seal Migration in Progress: true`— это**нормально**, пока вы не завершите миграцию на**каждом**pod’е.

## 1) Поднимите пустой кластер (или один узел)

Разверните «чистый» Vault (в примере — деплой из инфраструктурного репозитория через Terragrunt). Пока кластер**не инициализирован**, pod’ы будут перезапускаться (проверы падают) —**это ожидаемо**.

> 

Временная рекомендация (опционально):**выключить probes на время восстановления**
