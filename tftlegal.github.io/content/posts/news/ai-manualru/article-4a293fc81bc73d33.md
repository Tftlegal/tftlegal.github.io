# Anthropic создала Scion: почему Git не выдержал объёмов кода от Claude

## Краткое содержание

Anthropic представила Scion — собственную систему контроля версий, разработанную для работы с огромными репозиториями. Система создана в ответ на проблему, которую Git не может решить: объём изменений, генерируемых Claude, превышает возможности Git. Scion предназначена для управления кодовыми базами, где классические инструменты контроля версий перестают справляться с масштабом автоматизированных правок.

## Полная статья

## Что случилось: Anthropic сделала свою систему контроля версий

Anthropic представила[Scion](https://kod.ru/anthropic-scion-vmesto-git)- собственную систему контроля версий. Причина простая: Git перестал справляться с объёмом изменений, который генерирует Claude.

Масштаб виден по цифрам самой компании. В мае 2026 года в общий репозиторий Anthropic вливали около 2500 изменений в день, к сентябрю - больше 30 000. История главной ветки весит почти 100 ГБ. Системы автоматической проверки кода скачивают этот код около 25 млн раз в день. Если бы всё это шло через обычный Git, объём трафика превысил бы 600 петабайт в сутки.

Рамку зафиксирую сразу: Scion не замена Git и не продукт, который откроют для всех. Это внутренний инструмент под конкретный класс нагрузок - огромные репозитории, где клиентами выступают AI-агенты.

Немного базы, чтобы дальше было проще. Система контроля версий хранит историю изменений в коде: кто, что и когда поменял. Самая популярная из них - Git, на нём работает GitHub.

О том, почему рост объёма кода от агентов не всегда ускоряет разработку, разбирали в отдельном материале:[код подешевел, а разработка не ускорилась](https://ai-manual.ru/article/ya-bolshe-ne-pishu-kod-rukami-pochemu-razrabotka-s-ii-agentami-stala-tyazhelee-a-ne-legche).

## Почему Git не выдержал: три ограничения, которые вылезли на агентной разработке

### Полная копия репозитория у каждого клиента

Git задуман так, что у каждого разработчика есть полная копия репозитория и он может работать без интернета. Для распределённой команды людей это разумное решение. В Anthropic почти все клиенты - ИИ-агенты и задачи, которые всегда в сети. Держать полную копию истории у каждого агента дорого, и смысла в этом нет: агент всё равно работает с сервером.

### История на 100 ГБ и 25 млн скачиваний в день

Вторая проблема - объём. Только история главной ветки занимает почти 100 ГБ, и её нужно клонировать или фетчить при каждой операции, которой нужен полный контекст.

Третья - частота. Больше 30 000 изменений в день и около 25 млн скачиваний кода в сутки системами автопроверки означают, что репозиторий дёргают не несколько разработчиков за день, а поток машинных операций. Каждое такое скачивание работает с историей, а не с одним файлом. Через обычный Git это вылилось бы в больше чем 600 петабайт трафика в сутки. Узкое место здесь не диск, а постоянные операции чтения и передачи.

Проблема не в багах Git. Модель использования просто не совпала с тем, под что Git проектировали. Как кризис код-ревью проявляется на практике и почему git worktree стал частью обходных решений, разбирали здесь:[пет-проект на Java с Claude Code](https://ai-manual.ru/article/pet-proekt-na-java-s-claude-code-kak-razrabotchik-avtomatiziroval-svoyu-rabotu-orkestratorom-zadach).

## Как устроен Scion: серверное хранение и загрузка только нужных файлов

### Что именно перенесли на сервер

В Scion всё хранится и считается на сервере, а клиент загружает только нужные файлы. История остаётся на сервере. Операции, связанные с историей, выполняются на сервере. Клиент получает те файлы, которые нужны ему для текущей задачи.

Сравнение с Git очевидное: там клон - это полная копия, а здесь клиент тонкий. Деталей реализации в источнике нет: как устроен протокол, формат хранения и API, не раскрывается. Поэтому не додумываю.

### Откуда берётся выигрыш в 200 раз

Логика простая. Если клиент не хранит и не обрабатывает полную историю, нагрузка на CPU и память падает кратно. По[словам Anthropic](https://kod.ru/anthropic-scion-vmesto-git), инфраструктура стала в 200 раз скромнее по нагрузке на процессоры и память, а код скачивается за секунды вместо минут.

> Все цифры в статье - объёмы изменений, вес истории, темп скачиваний, выигрыш Scion - приводятся по данным Anthropic. Независимых измерений нет, контекст замеров компания не раскрывает.

Такой подход ближе к модели тонкого клиента и хорошо ложится на сценарии, где клиент всегда онлайн. Ровно тот случай, когда клиентами выступают агенты.

## Antique и семь инженеров: как Claude помогал строить Scion

Scion и инструмент для ревью кода Antique за пять месяцев сделали семь инженеров с помощью Claude. В Anthropic говорят, что все семь инженеров считают Claude лучшим программистом, чем они сами.

Роль людей при этом не исчезла. Их задача - продумывать архитектуру и часто говорить Claude «нет», когда агент нарушает важные ограничения системы. То есть AI ускоряет написание кода, а ответственность за архитектуру и границы остаётся на людях. Этот кейс не про рекламу Claude, а про разделение ролей.

Как список того, чего в системе не будет, влияет на архитектуру сильнее любых технических решений, показывает[отдельный кейс про постановку задачи и ограничения](https://ai-manual.ru/article/spisok-togo-chego-v-sisteme-ne-budet-kak-postanovka-zadachi-opredelila-arhitekturu-ai-sistemyi-upravleniya-korporativnoj-arhitekturoj): измеримые требования там привели к отказу от графовой СУБД в пользу PostgreSQL. Для агента список ограничений часто важнее, чем стек.

## Что это значит для команд, которые пока не сталкиваются с такими объёмами

Scion не открывают для всех. По словам компании, система нужна только для огромных репозиториев, и Git она не заменит. Anthropic ожидает, что другие столкнутся с похожими проблемами в ближайшие 6-12 месяцев. Прогноз относится к будущему, гарантий за ним нет.

### Признаки, что вы приближаетесь к пределам Git

- Агенты генерируют сотни и тысячи изменений в день, а не единицы.
- История главной ветки растёт до десятков гигабайт.
- CI и автопроверки массово клонируют репозиторий, счёт идёт на миллионы операций в сутки.
- Клоны и фетчи становятся узким местом, время клонирования заметно растёт.

Это ориентиры, привязанные к данным Anthropic, а не универсальные пороги. Для большинства команд такие значения пока недостижимы.

### Что делать сейчас, если объёмы ещё небольшие

Свою систему контроля версий строить не нужно. Практичные шаги другие. Следите за тем, какие идеи Scion Anthropic переносит в Git, GitHub и GitLab. Оптимизируйте текущий workflow: shallow clone и sparse checkout, кэш репозитория и зависимостей в CI, разумная политика веток. Это общие практики, а не проверенные на кейсе Anthropic решения: гарантий, что они дадут кратный выигрыш, нет.

Как оркестрация моделей и разгрузка кодовой базы помогают укладываться в лимиты и держать процессы под контролем, разбирали в[материале про подписки на кодинг-агенты](https://ai-manual.ru/article/kak-vyizhat-maksimum-iz-podpiski-na-koding-agentyi-orkestratsiya-modelej-i-optimizatsiya-kodovoj-bazyi).

Честная рамка: для подавляющего большинства команд Git остаётся рабочим инструментом, и менять его пока не на что.

## Заменит ли Scion Git и что будет дальше

Anthropic не планирует открывать Scion для всех. По[словам компании](https://kod.ru/anthropic-scion-vmesto-git), система нужна только для огромных репозиториев и Git она не заменит. Вместо этого Anthropic хочет вместе с GitHub, GitLab и сообществом разработчиков перенести удачные идеи Scion в Git.

Компания ожидает, что похожие проблемы у других появятся в ближайшие 6-12 месяцев. Сроки интеграции и её формат не раскрываются, строить предположения здесь не на чем.

Ждать Scion как замену Git не стоит. Смотреть нужно за изменениями в самом Git, GitHub и GitLab: именно туда переедут рабочие идеи. Если ваши агенты уже генерируют тысячи изменений в день и CI задыхается на клонах, стоит заранее измерять время клонирования и объём истории - это даст ранний сигнал, что пора оптимизировать workflow.
