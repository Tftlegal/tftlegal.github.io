## Как использовать Claude Opus 5.5: общие принципы работы

Три вещи решают, получится ли результат с первого захода.

- Креативность промпта. Модель не рисует картинку, она пишет код, который её рисует. Чем точнее описаны сцена, движение и тайминг, тем осмысленнее ролик.
- Версия библиотеки. Для Three.js рекомендуется зафиксировать версию и добавить документацию в контекст.
- Версия инструмента. Скрипты для Blender опираются на Blender Python API, а он меняется между релизами редактора.

Формулировки в кейсах звучат буднично. Кевин Нго попросил сгенерировать 28-секундную анимационную историю, где каждый кадр создан с помощью JavaScript. Райан Сэл попросил интерактивную лабораторию объектива, чтобы понять принцип фокусировки камеры. Специальных фреймворков для промптов в этих запросах нет.

## Пример 1: 28-секундная JavaScript-анимация без изображений и видеомоделей

Кевин Нго попросил Opus 5.5 сгенерировать 28-секундную анимационную историю, в которой каждый кадр создан с помощью JavaScript. В ролике город под звёздным небом, бумажные самолётики, улыбающееся существо, похожее на звезду, девочка, пишущая у окна, собаки и чай. Эстетика вырезок из бумаги сочетается с движением, которое сгенерировано кодом.

Для повторения не нужны ни исходные изображения, ни видеомодели. Модель, которая не способна генерировать картинки или видео, делает такие ролики за счёт креативности промпта: сцены описываются текстом, а рисует их браузер.

Практический вывод: самое сложное здесь — не запуск, а раскадровка. Таймлайн на 28 секунд придётся разложить на эпизоды и описать переходы между ними.

## Пример 2: Анимация жизни с рождения до настоящего момента

Другой креатор попросил Claude сделать анимацию своей жизни от рождения до текущего момента с помощью мазков JavaScript, снова без изображений и видеомоделей. Таймлайн личной истории собирается из тех же кирпичей, что и вымышленный сюжет: последовательность сцен, движение, смена палитры и темпа.

Кейс показывает, что подход масштабируется. История с произвольным числом эпизодов раскладывается на кадры и описывается промптом, а не превращается в ручную работу с графическим редактором.

## Пример 3: Интерактивная лаборатория объектива за одну итерацию

Райан Сэл попросил Opus 5.5 создать интерактивную лабораторию объектива, чтобы разобраться, как работает фокусировка камеры. При вращении кольца фокусировки стёкла внутри объектива сдвигаются, а область чёткости перемещается по сцене. Приложение было создано за одну итерацию продолжительностью 1, при этом единицу времени источник не называет.

Смысл кейса в скорости прототипирования: интерактивная обучающая модель с настоящей механикой движения собралась без серии уточняющих правок. Для повторения достаточно описать саму механику: что вращается, что смещается, как меняется резкость и на какую область сцены она падает.

## Пример 5: Игры на Three.js

Three.js появляется в подборке как инструмент для игр, которые генерирует модель. Ограничение здесь важнее самого примера. Версию библиотеки рекомендуется зафиксировать, а актуальную документацию добавить в контекст: API библиотеки меняется, и код, написанный под одну сборку, легко ломается на другой.

Конкретные игры источник не называет, поэтому ориентироваться стоит на свой проект: сцена, управление, физика и интерфейс описываются текстом, а проверка совместимости ложится на разработчика.

## Пример 6: Стоп-моушн-анимация в Blender по одному промпту

Claude Opus 5.5 способен создать стоп-моушн-анимацию в Blender по одному промпту: модель пишет Python-скрипт, который расставляет объекты, камеру и ключевые кадры. Ручная анимация по кадрам в этом сценарии не нужна.

Ограничение — Blender Python API. Он меняется между версиями, и скрипт, работающий в одной сборке, может не запуститься в другой. Версию редактора стоит зафиксировать и проверить скрипт на простой сцене, прежде чем строить на нём большой проект.

В подборке есть 3D-проект Architect's Model. Деталей в источнике нет: известно только то, что модель справляется с задачами трёхмерного моделирования в этом сценарии.

Разумный порядок действий для такого проекта: начать с простой геометрии, проверить ориентацию объектов, масштаб и камеру, и только потом наращивать детализацию. Так ошибки в координатах не накапливаются до состояния, когда сцену проще пересобрать с нуля.

## Пример 8: Создание 3D-сайтов и интерфейсов

Создание 3D-сайтов и интерфейсов тоже есть в списке. Стек в источнике не уточняется, но если проект строится на Three.js, действует то же правило, что и с играми: фиксируйте версию библиотеки и передавайте документацию в контекст.

Для интерфейсов добавляется ещё один фактор: анимации и переходы нужно проверять на слабом железе. Тяжёлая сцена в браузере выглядит эффектно на демо и тормозит на ноутбуке.

## Технические ограничения и как их обойти

Список проблем короткий, но предсказуемый: версии инструментов, отсутствие генерации изображений и видео, а также необходимость самостоятельно проверять результат.

- Модель не создаёт картинки и видеоряд, поэтому любой визуал собирается кодом.
- Blender Python API нестабилен между версиями редактора.
- Для Three.js нужна фиксация версии и документация в контексте.
- Сгенерированный код и презентации требуют проверки человеком.

### Нестабильность Blender Python API

Скрипты, сгенерированные Claude, опираются на функции Blender Python API, а набор и поведение этих функций отличаются от версии к версии. Что делать: зафиксировать конкретную сборку Blender, проверить импорты и вызовы на тестовой сцене, а расхождения править вручную. Источник упоминает эту нестабильность как ограничение, но не называет конкретные версии.

### Фиксация версии Three.js и добавление документации

У Three.js похожая природа проблемы: код под одну версию библиотеки может не работать в другой. Рекомендация из источника — зафиксировать версию в проекте и добавить документацию в контекст, чтобы модель писала код под конкретный API, а не по усреднённой памяти. Похожие вопросы совместимости и доступа разбирает материал[про Claude Fable 5.1 в AWS Bedrock](https://ai-manual.ru/article/claude-fable-51-v-aws-chto-menyaetsya-dlya-bedrock-enterprise-stsenariev-i-bezopasnoj-rabotyi-s-dannyimi).

## Стоит ли использовать Claude Opus 5.5: выводы

Для задач, где визуал решается кодом, модель подходит хорошо. JavaScript-анимации, интерактивные обучающие приложения, игры на Three.js, стоп-моушн в Blender, 3D-проекты, 3D-сайты и презентации повторяются при минимальном стеке: сама модель плюс инструмент, под который она пишет скрипт.

Ограничения, которые нужно держать в голове:

- изображения и видео модель не генерирует, весь визуал собирается кодом;
- Blender Python API расходится между версиями, скрипт может потребовать адаптации;
- для Three.js нужна фиксация версии и документация в контексте;
- презентации и код требуют вычитки, ответственность за результат остаётся на человеке.
