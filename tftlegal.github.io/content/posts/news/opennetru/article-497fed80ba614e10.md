# Уязвимость в пакетном менеджере APT, позволяющая совершить MITM-атаку для получения прав root

## Краткое содержание

В APT (инструмент управления пакетами) устранена уязвимость CVE-2026-109518, позволяющая обходить проверку при загрузке файлов и выполнять произвольный код с root-правами. Выпущено 13 обновлений, покрывающих все ветки APT, существующие за последние 10 лет (начиная с 1.2.x). Соответствующие исправления уже доступны для различных версий Debian и Ubuntu. По умолчанию уязвимость затрагивает Debian 12 и Ubuntu 22.04. Для более старых версий эксплуатация возможна лишь при условии, что параметр Acquire::Retries установлен в значение больше нуля.

## Полная статья

[Опубликованы](https://salsa.debian.org/apt-team/apt/-/tags)корректирующие выпуски инструментария для управления пакетами[APT](https://github.com/Debian/apt), в которых устранена[уязвимость](https://lists.debian.org/deity/2026/11/msg00005.html)([CVE-2026-109518](https://security-tracker.debian.org/tracker/CVE-2026-109518)), дающая возможность обойти проверку при загрузке файлов и добиться выполнения своего кода с правами root. Всего сформировано 13 выпусков, охватывающих все сформированные за последние 10 лет ветки APT, начиная с[1.2.x](https://www.opennet.ru/opennews/art.shtml?num=43683). Обновления пакетов с устранением уязвимости также уже сформированы для различных версий[Debian](https://security-tracker.debian.org/tracker/CVE-2026-109518),[Ubuntu](https://ubuntu.com/security/CVE-2026-109518)и[Deepin](https://www.deepin.org/en/cve-2026-109518-vulnerability-fix/). В конфигурации по умолчанию проблема затрагивает все выпуски начиная с Debian 12 и Ubuntu 22.04. Эксплуатация более старых версий возможна в случае выставления в параметр Acquire::Retries значения больше 0.

Атакующий, способный во время установки пакета вклиниться в HTTP-трафик между пользователем и репозиторем пакетов, может добиться установки подменённого неверифицированого варианта пакета, что позволяет ему получить привилегии root в системе. Атака может быть произведена, например, через компрометацию зеркал, прокси-серверов, беспроводных точек доступа или провайдерских шлюзов. В отчёте об уязвимости детали не упоминаются, указано лишь, что проблема вызвана некорректной работой с жёсткими ссылками. Судя по[патчу](https://salsa.debian.org/apt-team/apt/-/commit/5af16a8ad0f155233dfb10b7c92ad1903112ef79), в котором открытие файла с флагом FileFd::Empty (O_TRUNC) заменено на FileFd::Exclusive (O_EXCL), при возобновлении прерванной загрузки атакующий мог добиться перезаписи данных, для которых при первой загрузке уже была выполнена проверка по хэшу.
