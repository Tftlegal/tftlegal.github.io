# Уязвимости в Rust-библиотеках zip-rs и librsvg

## Краткое содержание

В популярной Rust-библиотеке zip-rs (~10 млн загрузок в неделю) обнаружена уязвимость CVE-2026-115905 с максимальной оценкой опасности 10 из 10. Злоумышленник может создать архив, в котором часть файлов размещена вне структуры «Central Directory», что делает их невидимыми при просмотре списка содержимого. При фактическом распаковке через API ZipStreamReader извлекаются эти скрытые файлы, отличные от те, что отображались в списке. Таким образом, архив выглядит безобидным, но при извлечении выдаёт непредвиденный набор файлов. Проблема устранена в версии zip-rs 9.0.5.

## Полная статья

В библиотеке[zip-rs](https://github.com/zip-rs/zip2), написанной на языке Rust и[насчитывающей](https://crates.io/crates/zip)около 10 млн загрузок в неделю, выявлена[уязвимость](https://github.com/zip-rs/zip2/security/advisories/GHSA-m665-v7pm-7grj)([CVE-2026-115905](https://security-tracker.debian.org/tracker/CVE-2026-115905)), позволяющая создавать архивы, которые выглядят безобидными, но при распаковке из них извлекаются другие, изначально не показанные в списке, файлы. Файлы могут быть размещены в архиве вне структуры "Central Directory", из-за чего при просмотре списка файлов показывается одно содержимое, но при распаковке через API ZipStreamReader извлекаются другие файлы. Проблеме присвоен уровень опасности 10 из 10. Уязвимость исправлена в версии[zip-rs 9.0.5](https://github.com/zip-rs/zip2/releases/tag/v9.0.5).

Уязвимость вызвана использованием разных заголовков при произвольном доступе к архиву при помощи API ZipArchive и при извлечении данных в потоковом режиме при помощи API ZipStreamReader. Обработчик ZipArchive полагается на заголовок CDFH (Central Directory File Header), а ZipStreamReader при извлечении файлов считает более приоритетным заголовок LFH (Local File Header) без синхронизации дублирующихся метаданных.

Уязвимость может использоваться для обхода почтовых фильтров, антивирусных сканеров и прочих систем проверки безопасности. Атакующий может разместить в видимой части архива документ или изображение, а в скрытую поместить исполняемый файл с вредоносным кодом, который не будет замечен антивирусом, но будет сохранён на диск при распаковке пользователем. В качестве примеров приводятся атаки на микросервисы, SaaS-платформы и системы контейнерной изоляции, в ходе которых при распаковке в каталогах с рабочими проектами не представляющих опасности архивов, например, с наборами стилей, текстовых файлов или изображений, могут быть перезаписаны скрипты и исполняемые файлы.

Дополнительно можно отметить[уязвимость](https://rustsec.org/advisories/RUSTSEC-2026-0305.html)([CVE-2026-96889](https://security-tracker.debian.org/tracker/CVE-2026-96889)) в библиотеке[librsvg](https://gitlab.gnome.org/GNOME/librsvg), развиваемой проектом GNOME на языке Rust. Библиотека применяется в GTK и приложениях GNOME для отрисовки SVG, а также задействована в популярном NPM-пакете[sharp](https://www.npmjs.com/package/sharp), насчитывающем 80 млн загрузок в неделю и используемом в качестве зависимости у почти 11 тысяч проектов. Уязвимость позволяет организовать выполнение своего кода при обработке специально оформленных SVG-изображений. Проблема[устранена](https://gitlab.gnome.org/GNOME/librsvg/-/commit/8a1b0cd319e9af2d1e9cf878081dd77f227a0504)в версиях[librsvg 2.56.6, 2.60.3, 2.62.4 и 2.63.1](https://gitlab.gnome.org/GNOME/librsvg/-/tags), а также в NPM-пакете[sharp 0.35.5](https://github.com/lovell/sharp/releases/tag/v0.35.5). Среди пострадавших проектов оказалась платформа PeerTube (зависимость обновлена в сегодняшнем выпуске[PeerTube 8.3.2](https://github.com/Chocobozzz/PeerTube/releases/tag/v8.3.2)).

Для разбора XML-разметки, используемой в SVG-файлах, в librsvg задействованы функции из Си-библиотеки libxml2. Уязвимость вызвана тем, что при наличии в SVG вложенных XML-конструкций Xincludes, включающих дублирующиеся элементы с повторяющимися именами, происходит обращение к памяти после её освобождения. Сбой возникает так как библиотека librsvg освобождает память под XML-элементы, которые ещё продолжают использоваться в парсере libxml2.
