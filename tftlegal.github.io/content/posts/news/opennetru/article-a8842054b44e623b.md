# Новые версии Wine 11.21, Wine-staging 11.21 и D7VK 2.4. Реализация 3Dfx Glide поверх Vulkan

## Краткое содержание

Опубликован экспериментальный выпуск Wine 11.21. Wine — это открытая реализация Win32 API, позволяющая запускать Windows-приложения на других платформах. С момента выхода предыдущей версии 11.20 разработчиками было закрыто 20 отчётов об ошибках. За тот же период в проект внесено 260 изменений. Таким образом, обновление сочетает исправление дефектов с существенным набором правок в коде.

## Полная статья

[Опубликован](https://www.winehq.org/news/2026103001)экспериментальный выпуск открытой реализации Win32 API -[Wine 11.21](https://www.winehq.org/). С момента выпуска[11.20](https://www.opennet.ru/opennews/art.shtml?num=66496)был закрыто 20 отчётов об ошибках и внесено 260 изменений.

Наиболее важные[изменения](https://gitlab.winehq.org/wine/wine/-/releases/wine-11.21):

- Повышена производительность OpenGL при использовании прослойки WoW64 (64-bit Windows-on-Windows), позволяющей выполнять 32-разрядные Windows-приложения в 64-разрядных Unix-системах (WoW64 обеспечивает запуск 32-разрядного кода внутри 64-разрядного процесса). Работа[оптимизирована](https://gitlab.winehq.org/wine/wine/-/merge_requests/12444)через реализацию маппинга буферов для WoW64 при помощи расширения MESA_map_buffer_client_pointer.
- Добавлена начальная версия DLL-библиотеки c реализацией API[Voice Capture DSP](https://learn.microsoft.com/en-us/previous-versions/dd464608(v=vs.85))для обработки данных с микрофона в режиме реального времени.
- Улучшена поддержка API для работы с учётными записями пользователей. Добавлена функция LogonUserW().
- Решены проблемы с обработкой комбинаций клавиш "Ctrl + Tab" и "Shift + Ctrl + Tab".
- Закрыты отчёты об ошибках, связанные с работой приложений: FL Studio 26.1.5, Cinebench 2026, .NET Framework 4.8.
- Закрыты отчёты об ошибках, связанные с работой игр: World of Tanks, Tron 2.0, I Love Science!, Skyrim, BioShock 2 Remastered, Zeus: Master of Olympus, Skyrim SE, No One Lives Forever 2.

Параллельно[сформирован](https://list.winehq.org/hyperkitty/list/wine-devel@list.winehq.org/thread/NCKPR3EI2OHUK6VAAYL65H67XNJO6PJ3/)выпуск проекта[Wine Staging 11.21](https://github.com/wine-staging/wine-staging/), предоставляющего расширенные сборки Wine, включающие не полностью готовые или рискованные патчи, пока непригодные для принятия в основную ветку Wine. По сравнению с Wine в Wine Staging предоставляется[275 дополнительных патчей](https://github.com/wine-staging/wine-staging/tree/master/patches). В новом выпуске Wine Staging осуществлена синхронизация с кодовой базой Wine 11.21 и обновлён код vkd3d.

Дополнительно можно отметить[выпуск](https://github.com/WinterSnowfall/d7vk/releases/tag/v2.4)проекта[D7VK 2.4](https://github.com/WinterSnowfall/d7vk), развивающего реализацию графических API[Direct3D 3, 5, 6 и 7](https://en.wikipedia.org/wiki/Direct3D), предложенных компанией Microsoft в 1996, 1997, 1998 и 1999 годах. D7VK работает через трансляцию вызовов в API Vulkan и позволяет при помощи Wine запускать в Linux ретро игры, завязанные на API Direct3D 3, 5, 6 и 7. Код проекта написан на языке C++ и[распространяется](https://github.com/WinterSnowfall/d7vk)под лицензией Zlib. В качестве основы при разработке использован код бэкенда d3d9 от проекта[DXVK](https://github.com/doitsujin/dxvk/)- D7VK преобразует API Direct3D 3, 5, 6 и 7 в вызовы Direct3D 9, которые затем транслируются в API Vulkan. Разработчик не намерен добиваться включения D7VK в состав DXVK, как это было с реализациями[Direct3D 8](https://www.opennet.ru/opennews/art.shtml?num=61503)и[Direct3D 9](https://www.opennet.ru/opennews/art.shtml?num=52042)поверх Vulkan.

В новой версии D7VK:

- Реализовано принудительное[ограничение](https://github.com/WinterSnowfall/d7vk#does-d7vk-support-4k-resolutions)разрешения экрана значением 1080p для того чтобы соответствовать лимитам старых API, превышение которых приводило к аварийному завершению или откату на разрешение 640×480 в играх.
- Отключено по умолчанию масштабирование буфера отрисовки в зависимости от размера экрана, так как разница в размерах поверхностей приводила к сбоям в играх, копирующих данные между буферами DDraw и D7VK. Для возвращения масштабирования предусмотрена настройка "ddraw.backBufferResize = True", при выставлении которой теперь по умолчанию сохраняется исходное соотношение сторон (отключается через ddraw.preserveAspectRatio = False).
- Кодовая база синхронизирована с последней версией DXVK.
- Для совместимости с некоторыми старыми играми, такими как Earth 2150, добавлена опция для возвращения приложению только коэффициентов соотношения сторон 4:3 и 5:4.
- Для исключения проблем во время переключений между DDraw и Vulkan реализована опция для принудительной прокси-обработки цветности (gamma) через буферы отображения DDraw.
- Для снижения потребления памяти унифицированы все структуры описания поверхностей.
- Ускорены операции загрузки кубических текстур, создания объектов и инициализации через IClassFactory.

Отдельно в анонсе D7VK 2.4 представлен проект[GXVK](https://github.com/CkNoSFeRaTU/gxvk), развивающий реализацию графического API[3Dfx Glide](https://ru.wikipedia.org/wiki/Glide), работающую поверх Vulkan и использующую DXVK в качестве бэкенда. Проект пока находится на стадии ранней[альфа-версии](https://github.com/CkNoSFeRaTU/gxvk/releases), но уже позволяет запускать в Linux при использовании Wine некоторые старые 3D-игры и приложения, завязанные на API Glide. Развиваются транслирующие в Vulkan прослойки для трёх 32-разрядных вариантов API Glide 2.00-2.11 (glide.dll), Glide 2.30-2.60 (glide2x.dll) и Glide 3.00-3.10 (glide3x.dll), выпускавшихся компанией 3Dfx для Windows.
