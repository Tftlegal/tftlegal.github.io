# Переполнение буфера в OpenSSL при работе с Base64

## Краткое содержание

В криптографической библиотеке OpenSSL обнаружена уязвимость CVE-2026-121481, связанная с переполнением буфера. Причина — целочисленное переполнение при обработке больших объёмов данных в функции EVP_EncodeBlock(), используемой для кодирования в формате Base64. На момент публикации исправление находится лишь на стадии обсуждения и ещё не внесено в кодовую базу OpenSSL. Статус устранения уязвимости в конкретных дистрибутивах Linux можно отслеживать на официальных страницах Debian, Ubuntu, SUSE, RHEL, Gentoo и Arch.

## Полная статья

В криптографической библиотеке OpenSSL выявлена[уязвимость](https://github.com/advisories/GHSA-83xj-7xh4-4p7x)([CVE-2026-121481](https://security-tracker.debian.org/tracker/CVE-2026-121481)), приводящая к переполнению буфера из-за целочисленного переполнения при обработке большого объёма данных в функции[EVP_EncodeBlock()](https://docs.openssl.org/1.0.2/man3/EVP_EncodeInit/), предназначенной для кодирования в формате[Base64](https://ru.wikipedia.org/wiki/Base64). Исправление пока[находится](https://github.com/openssl/openssl/pull/33652)на стадии обсуждения и не принято в кодовую базу OpenSSL. Статус устранения уязвимости в дистрибутивах можно оценить на данных страницах:[Debian](https://security-tracker.debian.org/tracker/CVE-2026-121481),[Ubuntu](https://people.canonical.com/~ubuntu-security/cve/CCVE-2026-121481),[SUSE](https://bugzilla.suse.com/show_bug.cgi?id=CVE-2026-121481),[RHEL](https://bugzilla.redhat.com/show_bug.cgi?id=CVE-2026-121481),[Gentoo](https://bugs.gentoo.org/show_bug.cgi?id=CVE-2026-121481),[Arch](https://security.archlinux.org/package/openssl),[Fedora](https://koji.fedoraproject.org/koji/packageinfo?packageID=109),[FreeBSD](https://www.freebsd.org/security/advisories/).

Проблема вызвана тем, что функция EVP_EncodeBlock() использует тип int при вычислении размера итогового буфера на основе размера входных данных (в base64 каждые 3 байта на входе кодируются 4 символами на выходе), не проверяя возможность целочисленного переполнения. Переполнение возникает при передаче более 1.5 ГБ входных данных и приводит к возвращение некорректного значения и выделению буфера, заведомо меньшего размера, чем необходимо для сохранения результата.

В случае обработки в EVP_EncodeBlock() внешних данных не исключается эксплуатация уязвимости для удалённого выполнения кода, но насколько уязвимость применима в реальных условиях пока не ясно, учитывая огромный размер данных, приводящих к переполнению. Из сценариев атаки пока упоминается эксплуатация через скрипты, использующие команду "openssl s_client" с опцией "-proxy_pass". Например, показано, что при использовании движка GOST, OpenSSL не ограничивает размер вводимых паролей, которые для совершения атаки могут передаваться через переменную окружения.
