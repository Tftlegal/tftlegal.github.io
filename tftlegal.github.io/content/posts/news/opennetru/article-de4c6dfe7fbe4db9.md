# Qwenputer - редакция AI-модели Qwen3.5, способная симулировать RISC-V CPU для выполнения кода на C и MicroPython

## Краткое содержание

В рамках проекта Qwenputer исследователи расширили модель Qwen3.5-4B, встроив в неё симулятор полноценного 32-разрядного CPU на архитектуре RISC-V (RV32IM) с расширением Zba и сопроцессором для арифметики больших чисел. Ядро этого CPU было скомпилировано непосредственно в набор весов нейросети. Интеграция реализована путём добавления 11 дополнительных слоёв трансформеров перед основными слоями модели Qwen. Все вычисления выполняются прямо в процессе прямого прохода (forward pass) сети. Внешние инструменты или плагины для этого не требуются. Таким образом, языковая модель получает способность выполнять полноценные CPU-операции «внутри себя».

## Полная статья

В рамках проекта[Qwenputer](https://divagr.com/blog/qwenputer)исследователи[подготовили](https://github.com/divagr18/qwenputer)расширенный[вариант](https://huggingface.co/divagr1925/Qwen3.5-4B-Qwenputer)AI-модели Qwen3.5-4B, в котором реализован встроенный симулятор полноценного 32-разрядного CPU на базе архитектуры RISC-V (RV32IM), поддерживающего расширение[Zba](https://docs.riscv.org/reference/isa/v20260120/unpriv/b-st-ext.html#zba)и оснащённого сопроцессором bignum для арифметических операций с большими числами. Реализация ядра CPU скомпилирована в набор весов и интегрирована в большую языковую модель в виде 11 дополнительных слоёв трансформеров, добавленных перед основными слоями Qwen. Вычисления выполняются непосредственно в процессе прямого прохода (forward pass) нейросети, без подключения внешних инструментов или плагинов.

Реализация успешно проходит все проверки из официального набора тестов[riscv-tests](https://github.com/riscv-software-src/riscv-tests)и способна выполнять скомпилированный код на C и MicroPython. При выполнении арифметических вычислений с большими числами Qwenputer обеспечивает точность 97.5-100%, что сопоставимо или превосходит результаты базовой модели Qwen3.5 с подключённым внешним интерпретатором Python.

[

![](/news/opennetru/article-de4c6dfe7fbe4db9/image-01.png)

](https://github.com/divagr18/qwenputer/raw/main/docs/benchmarks-arith.png)

Для симуляции оперативной памяти в модели задействованы отдельные слои[Gated DeltaNet](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch04/08_deltanet/README.md)(линейные[RNN](https://ru.wikipedia.org/wiki/%D0%A0%D0%B5%D0%BA%D1%83%D1%80%D1%80%D0%B5%D0%BD%D1%82%D0%BD%D0%B0%D1%8F_%D0%BD%D0%B5%D0%B9%D1%80%D0%BE%D0%BD%D0%BD%D0%B0%D1%8F_%D1%81%D0%B5%D1%82%D1%8C)), применяемые в штатной AI-модели Qwen для сохранения изменённого состояния при работе с большими контекстными окнами. Путём фиксации состояния гейта и применения[унитарного кодирования](https://ru.wikipedia.org/wiki/%D0%A3%D0%BD%D0%B8%D1%82%D0%B0%D1%80%D0%BD%D1%8B%D0%B9_%D0%BA%D0%BE%D0%B4)(one-hot) каждый запрос на запись перезаписывает ровно одну строку матрицы состояния, что позволяет использовать состояние DeltaNet как адресуемую память фиксированного размера, избегая линейного роста KV-кэша (Key-Value) при увеличении длины контекста. В подобной памяти размещаются регистры CPU, данные и выполняемый машинный код.

[

![](/news/opennetru/article-de4c6dfe7fbe4db9/image-02.png)

](https://github.com/divagr18/qwenputer/raw/main/docs/gdn-ram.png)

Инструкции процессора, такие как чтение регистров, арифметические операции и условные переходы, компилируются непосредственно в веса слоёв трансформера. С каждой инструкцией сопоставляются специальные токены (ADDR, VAL, STEP), которые слои AI-модели интерпретируют как логику работы CPU. Для инициализации CPU и загрузки прошивки применяется небольшой внешний драйвер RvChat, но сам машинный код обрабатывается полностью внутри весов модели.

Из ограничений проекта упоминается примерно двухкратное по сравнению с исходной моделью Qwen увеличение размера (18.8 ГБ) при сохранении срезов состояния (checkpoint), возникающее в основном из-за добавочного заполнения дополнительных слоёв. Также отмечается относительно низкая скорость вычислений (порядка 3200 токенов в секунду на GPU L4), из-за чего сложные расчёты могут занимать секунды, а не миллисекунды.

Дополнительно[реализован](https://huggingface.co/divagr1925/Qwen3.5-4B-Qwenputer-Filesystem)вариант AI-модели с экспериментальной файловой системой, позволяющей хранить внутри весов AI-модели до 512 файлов с 53 тысячами токенов текста. Как и в реализации оперативной памяти хранение организовано в привязке к состояниям DeltaNet, но отличается тем, что ФС обеспечивает постоянное хранение, не теряющее состояние между сеансами.

Наработки Qwenputer также легли в основу исследования новых потенциальных проблем с безопасностью в AI. На примере Qwenputer[показано](https://divagr.com/blog/hybrid-models-can-hide-reasoning-in-their-rnn-state)как специально модифицированная AI-модель может скрывать свои рассуждения в RNN-состоянии и обходить механизмы мониторинга рассуждений модели (CoT, Chain-of-Thought). Также[продемонстрирована](https://divagr.com/blog/building-oversight-tools-into-a-models-weights)возможность создания механизмов контроля и мониторинга безопасности, встроенных в веса AI-модели, которые сама модель не может отключить или изменить.
