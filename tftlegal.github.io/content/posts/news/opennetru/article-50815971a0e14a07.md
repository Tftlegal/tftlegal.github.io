# Выпуск Rust 1.99.0. Microsoft перевёл Rust в число первичных языков

## Краткое содержание

Вышел новый релиз языка программирования Rust — версия 1.99. Изначально проект принадлежал компании Mozilla, однако сейчас его развитием занимается независимая некоммерческая организация Rust Foundation. Ключевая особенность языка — безопасная работа с памятью без необходимости использования сборщика мусора. Rust также предлагает инструменты для обеспечения высокого уровня параллелизма при выполнении задач. При этом язык обходится без полноценного рантайма. Его «рантайм» сводится лишь к базовой инициализации и сопровождению стандартной библиотеки.

## Полная статья

[Опубликован](https://blog.rust-lang.org/2026/10/01/Rust-1.99.0/)релиз языка программирования[Rust 1.99](http://www.rust-lang.org), основанного проектом Mozilla, но ныне[развиваемого](https://www.opennet.ru/opennews/art.shtml?num=54555)под покровительством независимой некоммерческой организации Rust Foundation. Язык сфокусирован на безопасной работе с памятью и предоставляет средства для достижения высокого параллелизма выполнения заданий, при этом обходясь без использования[сборщика мусора](https://prev.rust-lang.org/en-US/faq.html#is-rust-garbage-collected)и[runtime](https://prev.rust-lang.org/en-US/faq.html#does-rust-have-a-runtime)(runtime сводится к базовой инициализации и сопровождению стандартной библиотеки).

Методы работы с памятью в Rust нацелены на исключение ошибок при манипулировании указателями и защиту от проблем, возникающих из-за низкоуровневой работы с памятью, таких как обращение к области памяти после её освобождения, разыменование нулевых указателей, выход за границы буфера и т.п. Для распространения библиотек, обеспечения сборки и управления зависимостями проектом развивается пакетный менеджер[Cargo](http://blog.rust-lang.org/2014/11/20/Cargo.html). Для размещения библиотек поддерживается репозиторий[crates.io](https://crates.io/).

Безопасная работа с памятью обеспечивается в Rust во время компиляции через проверку ссылок, отслеживание владения объектами, учёт времени жизни объектов (области видимости) и оценку корректности доступа к памяти во время выполнения кода. Rust также предоставляет средства для защиты от целочисленных переполнений, требует обязательной инициализации значений переменных перед использованием, лучше обрабатывает ошибки в стандартной библиотеке, применяет концепцию неизменяемости (immutable) ссылок и переменных по умолчанию, предлагает сильную статическую типизацию для минимизации логических ошибок.

Основные[новшества](https://github.com/rust-lang/rust/blob/master/RELEASES.md):

- [Предоставлена](https://doc.rust-lang.org/reference/items/functions.html#c-variadic-functions)возможность создания на языке Rust функций с переменным числом аргументов (variadic), экспортируемых для вызова из проектов на языке Си (C ABI). В качестве последнего элемента списка параметров в подобных функциях может указываться конструкция "...", которая обрабатывается в Rust при помощи специального типа[VaList](https://doc.rust-lang.org/std/ffi/struct.VaList.html), работающего аналогично va_list в C.

```

   unsafe extern "C" fn sum(mut args: ...) -> i32 {
       let a = unsafe { args.next_arg::<i32>() };
       let b = unsafe { args.next_arg::<i32>() };
       a + b
   }

   fn foo() -> i32 {
       unsafe { sum(0i32, 2i32) }
   }
```

- В документацию добавлена рекомендация избегать освобождения памяти, на которую была получена статическая ссылка с неограниченным временем жизни (&'static) через вызов[Box::leak](https://doc.rust-lang.org/std/boxed/struct.Box.html#method.leak)(round-trip unleaking), так как подобное действие потенциально может привести к проблемам из-за несовместимости с будущими оптимизациями компилятора и подключаемыми механизмами выделения памяти. Вместо создания статической ссылки для временной передачи владения рекомендуется использовать сырые указатели, например, через вызов Box::into_non_null.

Дополнительно можно отметить недавно анонсированные проекты и события, связанные с Rust:

- Компания Microsoft[перевела](https://rustfoundation.org/media/guest-post-rust-is-tier-1-language-at-microsoft/)Rust в число языков первого уровня и обеспечит его полную поддержку на всех этапах разработки внутри компании. Среди прочего, компоненты на Rust уже применяются в таких продуктах, как Microsoft 365 и Copilot, а для компилятора MSVC подготовлен отдельный бэкенд rustc_codegen_utc для Rust, основанный на компиляторе rustc.

По словам технического директора Microsoft Azure около 70% всех уязвимостей в Windows вызваны проблемами при работе с памятью, которых можно избежать при использовании Rust.

- Компания Google[удалила](https://git.kernel.org/pub/scm/linux/kernel/git/gregkh/char-misc.git/commit/?id=fd2bc059ed466bdd95347a4f7891d150d94e7de2)из ядра Linux старую реализацию механизма межпроцессного взаимодействия Binder, написанную на языке Си, в пользу нового драйвера Binder IPC,[переписанного на Rust](https://www.opennet.ru/opennews/art.shtml?num=64092). Отмечается, что за 15 лет существования старого драйвера в нём накопились значительный технический долг и обилие усложнений, которые затрудняли поиск ошибок, сопровождение и добавление новых возможностей. Драйвер Binder IPC на Rust признан основным и больше не преподносится как экспериментальная разработка.
- [Опубликован](https://blog.torproject.org/arti_2_7_0_released/)выпуск[Arti 2.7.0](https://gitlab.torproject.org/tpo/core/arti/), реализации инструментария Tor, написанной на языке Rust. Когда код Arti достигнет уровня, способного полностью заменить вариант на Си, разработчики Tor намерены придать Arti статус основной реализации Tor и постепенно прекратить сопровождение реализации на Си. В[новой версии](https://gitlab.torproject.org/tpo/core/arti/-/blob/main/CHANGELOG.md#arti-270--01-october-2026)проложено развитие функциональности для релеев и серверов директорий (Directory Authority), связанной с парсингом документов, поддержкой зеркалирования серверов директорий и обработкой DNS-трафика. Добавлена реализация RPC для изменения и проверки конфигурации. Устранено несколько уязвимостей - администраторам onion-сервисов рекомендовано срочно обновить свои системы.
