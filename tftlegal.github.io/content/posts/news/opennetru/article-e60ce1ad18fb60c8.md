# В инсталляторе SUSE и openSUSE появится возможность использования AI для установки

## Краткое содержание

Разработчики инсталлятора Agama, используемого в SUSE и openSUSE, объявили о добавлении MCP-сервера (Model Context Protocol), позволяющего ИИ-ассистентам управлять процессом установки. Через этот протокол ИИ-агенты получат доступ к сведениям об оборудовании, инструментам для подготовки и проверки конфигурации, а также средствам отслеживания и контроля процесса установки. По умолчанию MCP-сервер будет отключён, поэтому работа инсталлятора для пользователей, не применяющих ИИ, останется неизменной. Средства для интеграции с ИИ-ассистентами поступят в следующем выпуске — Agama 26. До выхода релиза новый режим можно опробовать в предварительных ночных сборках.

## Полная статья

Разработчики инсталлятора[Agama](https://agama-project.github.io/), применяемого в SUSE и openSUSE,[объявили](https://agama-project.github.io/blog/2026/11/24/first-ai-ready-os-installer)о добавлении[MCP-сервера](https://github.com/agama-project/agama/tree/master/rust/agama-mcp)(Model Context Protocol), при помощи которого AI-ассистенты смогут управлять процессом установки. Через протокол MCP AI-агенты получат доступ к информации об оборудовании, возможностям для подготовки и проверки конфигурации, а также к инструментам отслеживания и управления процессом установки. По умолчанию MCP-сервер будет отключён и процесс работы пользователей, не применяющих AI, останется без изменений. Средства для интеграции с AI-ассистентами будут добавлены в[следующем выпуске](https://github.com/agama-project/agama/tags)Agama 26, а до его публикации AI-режим можно опробовать в предварительных[ночных сборках](https://agama-project.github.io/download).

Предполагается, что пользователь опишет AI-ассистенту желаемую конфигурацию на естественном языке, а AI-ассистент выполнит установку через подключение к инсталлятору по протоколу MCP. Например, пользователь может попросить установить на компьютер openSUSE Tumbleweed с рабочим столом GNOME, используя файловую систему Btrfs на диске NVMe и создав в системе пользователя с именем "tux" и паролем "123", после чего AI-ассистент выберет необходимый вариант дистрибутива, сформирует конфигурацию и создаст разделы на диске.

MCP-сервер будет поддерживать два режима работы:

- Режим конфигурации, в котором AI-ассистент ограничен формированием плана установки, который должен будет подтвердить пользователь. Самостоятельно AI-ассистент не сможет выполнять деструктивные операции, такие как форматирование, перезагрузка и запуск скриптов перед установкой.
- Полный режим, в котором AI-ассистент сможет автономно выполнять любые операции. Режим может применяться для автоматизированных установок или для установок без участия человека, инициируемых внешним оркестратором, таким как[Uyuni](https://github.com/uyuni-project/uyuni/).

Так как установка системы предусматривает выполнение деструктивных операций, а AI-модели склонны к галлюцинациям, AI-ассистент не получит доступа к командному интерпретатору и низкоуровневым утилитам для разбивки диска, а будет работать через прослойку. Все передаваемые AI-ассистентом профили будут проверяться на предмет полного соответствия JSON-схеме настроек и любые неизвестные или некорректные настройки будут блокироваться. При передаче некорректных параметров, например, выделении дискового пространства сверх имеющегося, Agama будет возвращать подробное описание ошибки. Обращения к MCP будут осуществляться только с использованием специального токена, не позволяющего использовать HTTP API.
