# Релиз коммуникационной платформы Asterisk 24

## Краткое содержание

Через год разработки была выпущена стабильная ветка открытой коммуникационной платформы Asterisk 24. Платформа предназначена для развёртывания программных АТС и систем голосовой связи. Среди её возможностей — создание VoIP-шлюзов, IVR-систем (голосовых меню), голосовой почты, телефонных конференций и колл-центров. Исходный код проекта написан на языке Си. Проект распространяется под лицензией GPLv2.

## Полная статья

После года разработки[состоялся](https://www.asterisk.org/asterisk-news/wp-email-announcement-24-0-0/)релиз стабильной ветки открытой коммуникационной платформы[Asterisk 24](https://www.asterisk.org/), используемой для развёртывания программных АТС, систем голосовой связи, VoIP-шлюзов, организации IVR-систем (голосовое меню), голосовой почты, телефонных конференций и call-центров. Исходный код проекта написан на языке Си и[доступен](https://github.com/asterisk/asterisk/)под лицензией GPLv2.

Asterisk 24[отнесён](https://wiki.asterisk.org/wiki/display/AST/Asterisk+Versions)к категории выпусков с расширенной поддержкой (LTS), обновления для которого[будут выпускаться](https://wiki.asterisk.org/wiki/display/AST/Asterisk+Versions)в течение пяти лет вместо свойственных для обычных выпусков двух лет. Поддержка прошлой LTS-ветки Asterisk 22 продлится до октября 2029 года, а ветки Asterisk 20 до октября 2027 года. При подготовке LTS-выпусков основное внимание уделяется обеспечению стабильности и оптимизации производительности, приоритетом же обычных выпусков является наращивание функциональности.

[Среди](https://downloads.asterisk.org/pub/telephony/asterisk/releases/ChangeLog-24.0.0.html)[изменений](https://downloads.asterisk.org/pub/telephony/asterisk/releases/ChangeLog-24.0.0.md)в Asterisk 24:

- В модуле[res_pjsip](https://docs.asterisk.org/Latest_API/API_Documentation/Module_Configuration/res_pjsip/), обеспечивающем поддержку VoIP-коммуникаций на базе протокола SIP, привязанные к DNS-именам контакты PJSIP теперь считаются доступными, если удалось отрезолвить хотя бы одну связанную с ними DNS-запись SRV, A или AAAA.
- В модуль res_prometheus добавлены опции "channels_detail_metrics_enabled" и "bridges_detail_metrics_enabled" для управления экспортом в систему мониторинга Prometheus дополнительных метрик[каналов](https://docs.asterisk.org/Fundamentals/Key-Concepts/Channels)('asterisk_channels_state', 'asterisk_channels_duration_seconds') и[мостов](https://docs.asterisk.org/Fundamentals/Key-Concepts/Bridges/)('asterisk_bridges_channels_count').
- В профиль моста для организации конференций ConfBridge добавлена опция "announcements", при помощи которой можно отключить общие анонсы конференции, что экономит один канал и один поток taskprocessor.
- В модуле chan_websocket реализован небуферизованный режим, отправляющий кадры по мере их получения из WebSocket и приложения.
- Добавлены примеры конфигурации для аутентификации ITSP по IP-адресу и использования TLS с SRTP.
- В websocket_client.conf добавлен параметр "write_timeout" для ограничения максимального времени операции записи перед возвратом ошибки.
- В средства для определения местоположения (res_geolocation) добавлен скрипт, использующий[Alembic](http://alembic.readthedocs.org)для создания таблиц geoloc_location и geoloc_profile.
- В структуру ast_websocket_client_options добавлено поле write_timeout для настройки таймаута операций записи в неблокирующем режиме.
- В событие MEDIA_START в chan_websocket добавлены поля passthrough и unbuffered, отражающие режим создания канала.
