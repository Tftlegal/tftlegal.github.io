# Релиз языка программирования PHP 8.6. Устранено семь критических уязвимостей в PHP

## Краткое содержание

Объявлено о выходе релиза языка программирования PHP версии 8.6. Разработка новой версии заняла один год. Обновление включает серию новых возможностей. Помимо новшеств, в релиз вошли изменения, нарушающие обратную совместимость. Это означает, что некоторый существующий код может потребовать доработки после перехода на новую ветку.

## Полная статья

После года разработки[опубликован](https://www.php.net/archive/2026.php#2026-11-19-5)релиз языка программирования[PHP 8.6](https://www.php.net/releases/8.6/en.php). Новая ветка включает серию новых возможностей, а также несколько изменений,[нарушающих совместимость](https://www.php.net/manual/en/migration86.incompatible.php).

Ключевые изменения в PHP 8.6 ([1](https://stitcher.io/blog/new-in-php-86),[2](https://www.php.net/manual/en/migration86.php),[3](https://www.php.net/releases/8.6/)):

- Реализована концепция[PFA](https://www.php.net/manual/en/functions.partial-application.php)(Partial Function Application), позволяющая создавать ссылки на замыкания (closure) с предварительным заполнением некоторых параметров и передачей остальных параметров в форме заполнителей "?" и "...".

```

   $makeSlug = str_replace(' ', '-', ?);
   $makeSlug('Hello World'); // эквивалент вызова  str_replace(' ', '-', 'Hello World');
   // результат "Hello-World"

   $output = 'Hello World' 
       |> str_replace(' ', '-', ?)
       |> strtolower(...); // вызов по цепочке
   // результат "hello-world"
```

- [Разрешено](https://www.php.net/manual/en/language.oop5.properties.php#language.oop5.properties.readonly-properties)назначение значений по умолчанию для свойств с атрибутом "readonly", а также свойств в классах с атрибутом "readonly". Подобное назначение позволяет обойтись без отдельного присвоения значения в конструкторе и обрабатывается как инициализация свойства (конструктор не может перезаписать свойство со значением по умолчанию).

```

   final class CreateBooksTable implements MigratesUp
   {
       public readonly string $name = '2026-11-19_create_books_table';
   }
```

- Добавлен API[Io\Poll](https://wiki.php.net/rfc/poll_api), позволяющий одновременно отслеживать множество потоков, используя оптимальный для текущей системы механизм мультиплексирования соединений (epoll, kqueue, event ports, WSAPoll). По сравнению с stream_select() новый API обеспечивает более высокую производительность и масштабируемость, и может использоваться для более эффективной реализации = цикла обработки событий (event loop) в таких фреймворках, как[ReactPHP](https://reactphp.org/)и[AMPHP](https://amphp.org/).

```

   use Io\Poll\Context;
   use Io\Poll\Event;
   use Io\Poll\StreamPollHandle;
   use Time\Duration;

   $context = new Context();
   $stream = stream_socket_server('tcp://0.0.0.0:8080', $errno, $errstr);
   stream_set_blocking($stream, false);
   $handle = new StreamPollHandle($stream);
   $context->add($handle, [Event::Read], ['type' => 'server']);
   while (true) {
       $watchers = $context->wait(new Duration::fromSeconds(1));
       //....
   }
```

- Добавлена функция[clamp(val, min, max)](https://www.php.net/manual/en/function.clamp.php), которая гарантирует, что значение находится в заданном диапазоне. Если значение попадает в диапазон, возвращается это значение, а если нет - ближайшее граничное значение диапазона.

```

   clamp(-5, min: 0, max: 100) // 0
   clamp(55, min: 0, max: 100) // 55
   clamp("a", "x", "z") //  "x"
   clamp(value: new DateTimeImmutable('2025-01-01'), min: new DateTimeImmutable('2026-01-01'), max: new DateTimeImmutable('2026-12-31')); // 2026-01-01
```

- Добавлен класс[\Time\Duration](https://www.php.net/manual/en/class.time-duration.php), определяющий время, прошедшее с определённого момента, с точностью до наносекунды (можно использоваться для таймаутов, измерения времени выполнения операций и т.п.).

```

   use Time\Duration;
   sleep(Duration::fromMilliseconds(500));
```

- Добавлены методы[ReflectionProperty::isReadable()](https://www.php.net/manual/en/reflectionproperty.isreadable.php)и[ReflectionProperty::isWritable()](https://www.php.net/manual/en/reflectionproperty.iswritable.php)для проверки возможности чтения и изменения свойств в указанной области видимости.

```

   final class Book
   {
       private(set) string $title;
   }
   $property = new ReflectionProperty(Book::class, 'title');
   $property->isReadable(scope: Book::class); // true
   $property->isWriteable(scope: null); // false
```

- Добавлен метод[ReflectionParameter::getDocComment()](https://wiki.php.net/rfc/parameter-doccomments)для доступа к документирующим комментариям к параметрам методов и функций. Комментарии могут задаваться непосредственно перед или после каждого параметра.

```

   function search(/** Terms to search  */ string $query) { /* … */ }
   var_dump(
       new ReflectionParameter([DB::class, 'search'], 'query')
          ->getDocComment(),
   );
```

- Реализовано встроенное перечисление (enum)[SortDirection](https://www.php.net/manual/en/enum.sortdirection.php), определяющее порядок сортировки (по возрастанию или по убыванию).

```

   SortDirection $direction = SortDirection::Ascending;
   SortDirection $direction = SortDirection::Descending;
```

- В перечислениях (enum) разрешено реализовывать метод __debugInfo() для создания собственных обработчиков вывода отладочной информации.

```

   enum Status: int
   {
       ... 
       public function __debugInfo() {
		return [__CLASS__ . '::' . $this->name . ' = ' . $this->value];
       }
   }
```

- Добавлены классы Uri\Rfc3986\UriBuilder и Uri\WhatWg\UrlBuilder для формирования URI из отдельных компонентов.
- Предоставлена возможность[обработки ошибок](https://www.php.net/manual/en/stream.errors.handling.php), возникающих при операциях с потоками. Например, можно организовать генерацию исключения StreamException или завершение с ошибкой.
- Добавлена настройка error_include_args для указания аргументов функций в сообщениях об ошибках.
- [Изменены](https://wiki.php.net/rfc/session_security_defaults#backward_incompatible_changes)значения по умолчанию для настроек:

- session.use_strict_mode=1 - запрещает обработку идентификаторов сеансов, для которых отсутствуют сессионные файлы на сервере (например, когда пользователь подключается с полученным извне идентификатором сеанса, который ранее не выдавался сервером). Если сеанс отсутствует, то PHP теперь не пытается повторной создать сеанс с указанным идентификатором, а всегда генерирует новый идентификатор. Изменение защищает от атак через[фиксацию сеансов](https://community.owasp.org/attacks/Session_fixation), но может нарушить работу конфигураций с общими идентификаторами сеансов для разных поддоменов.
- session.cookie_httponly=1 - приводит выставлению в отдаваемых сессионных Cookie атрибута HttpOnly, запрещающего браузеру показывать значение Cookie через JavaScript-свойство document.cookie. Изменение может нарушить работу фрондэндов, использующих сессионные Cookie, например, для встраивания в передаваемый при запросах HTTP-заголовок.
- session.cookie_samesite=Lax - запрещает отправлять сессионные Cookie при кросс-доменных POST-запросах и загрузке ресурсов (изображений, CSS, JavaScript-файлов) с других сайтов. Изменение может нарушить работу сайтов, в которых имеются web-формы, отправляющие POST-запросы на другой домен.

- Объявлены устаревшими: возможность выполнения "return" в блоках "finally", использование слов "let" и "is" в качестве идентификаторов, использование имени "namespace" в названии констант в классах, использование имени "readonly" в названиях функций, передача объектов вместо массивов в функции array_walk() и inflate_init(), использование функций is_double(), is_long(), doubleval(), is_integer(), metaphone(), spl_object_hash() и strcoll().
- Кодовая база PHP[переведена](https://www.opennet.ru/opennews/art.shtml?num=65372)на лицензию BSD-3 вместо собственной лицензии PHP License, которая выведена из обращения.

[Дополнительно][опубликованы](https://www.php.net/)корректирующие выпуски PHP 8.5.13, 8.4.28, 8.3.37 и 8.2.36, в которых[устранено](https://www.php.net/ChangeLog-8.php#8.5.13)17 уязвимостей, 7 из которых помечены как критические и могут привести к удалённому выполнению кода:

- [CVE-2026-129481](https://github.com/php/php-src/security/advisories/GHSA-g3vh-838c-65v7)и[CVE-2026-129182](https://github.com/php/php-src/security/advisories/GHSA-2fjv-p558-g82m)- блокируют дополнительные векторы атаки в стиле недавней уязвимости[PHP2Shell](https://www.opennet.ru/opennews/art.shtml?num=66520)([CVE-2026-109619](https://security-tracker.debian.org/tracker/CVE-2026-109619)), приводящей к обращению к памяти после её освобождения из-за некорректной очистки глобального состояния, привязанного к конкретному запросу, при прерывании запроса из-за фатальной ошибки, таймаута или нехватки памяти. CVE-2026-129481 проявляется в начиная с версии 8.3 (при указании разных значений max_memory_limit или zlib.output_compression в глобальной и локальной конфигурации), а CVE-2026-129182 - начиная с 8.5 (в системах с PHP-FPM с отключенным OPcache). Обходные меры защиты такие же как у уязвимостей[PHP2Shell](https://www.opennet.ru/opennews/art.shtml?num=66520), т.е. выставление настройки "fatal_error_backtraces=0" в php.ini и "pm.max_requests=1" в PHP-FPM.
- [CVE-2026-115560](https://github.com/php/php-src/security/advisories/GHSA-658j-r8rw-q6mx)- рассогласование форматов сериализации сессии в приложениях и функции отслеживания прогресса загрузки файлов (атакующий может добиться записи данных в формате сериализации сессии php_binary или php_serialize, а приложение попытается их десериализировать, используя формат php, что можно использовать для организации выполнения кода. Проблема проявляется во всех поддерживаемых ветках. Обходной путь защиты - выставление параметра "session.upload_progress.enabled=0".
- [CVE-2026-126714](https://github.com/php/php-src/security/advisories/GHSA-fm2m-fjf5-v3cp)- атакующий может частично перезаписать сессионные файлы через прерывание процесса обновления сессионного файла. Так как перед перезаписью сессионный файл не обнулялся, можно было добиться состояния, в котором начало файла содержит новые данные, а конец - хвост от старых данных. При десериализации подобных повреждённых сессионных файлов можно добиться образования нового сериализованного объекта и выполнения кода в системе. Прерывание записи осуществляется через манипуляцию с обработчиком прогресса загрузки, передачу большого объёма сессионных данных или исчерпание лимитов на размер памяти. Проблема проявляется начиная с PHP 4.1.0 при использовании настройки "session.save_handler = files" (по умолчанию). В качестве обходных путей защиты можно выставить параметр "session.upload_progress.enabled=0" и задействовать иной обработчик в session.save_handler.
- [CVE-2026-129289](https://github.com/php/php-src/security/advisories/GHSA-qc49-hpvq-g2w6)- атака класса "[HTTP Request Smuggling](https://www.opennet.ru/opennews/art.shtml?num=55601)" при взаимодействии с PHP-FPM, позволяющая вклиниться в содержимое других запросов и добиться выполнения PHP-кода с привилегиями рабочего процесса. Проблема возникает если приложение открывает поток php://input, но не читает его до конца из-за прерывания работы или ошибки, из-за чего непрочитанные данные при постоянном соединении с бэкендом, PHP-FPM ошибочно интерпретирует как новый FastCGI-запрос. Проблема проявляется начиная с PHP 5.6.
- [CVE-2026-129496](https://github.com/php/php-src/security/advisories/GHSA-gr4f-wgx5-jpfv)- обращение к памяти после её освобождения в коде работы с кэшем часовых поясов при записи диагностических сообщений (например, о некорректном значении date.timezone или устаревших настроек) в error-лог при запуске процесса одновременно с выводом другого диагностического сообщения. Проблема проявляется начиная с PHP 5.3.18. Обходной путь решения проблемы - устранение всех предупреждений о некорректных или устаревших настройках, выводимых во время запуска.
- [CVE-2026-129474](https://github.com/php/php-src/security/advisories/GHSA-8mjj-2r7p-4hg2)- обращение к памяти после её освобождения в коде формирования обратной трассировки в случае возникновения фатальной ошибки (например, исчерпания доступной памяти) в момент вызова метода __call() или __callStatic() в приложении. Проблема проявляется начиная с ветки PHP 8.5. В качестве обходных путей блокирования проблемы можно выставить настройки "zend.exception_ignore_args=1" и "fatal_error_backtraces=0".
