# Ошибка при генерации ключей удостоверяющего центра eMudhra позволяла получить TLS-сертификаты для любых сайтов

## Краткое содержание

Mozilla предупредила о скомпрометированных закрытых ключах, связанных с восемью промежуточными корневыми сертификатами удостоверяющего центра eMudhra. Злоумышленники, получившие доступ к этим ключам, могли выпускать поддельные TLS-сертификаты для произвольных сайтов. Такие сертификаты были бы автоматически доверенны всеми современными браузерами. Это создавало возможность для перехвата или модификации трафика между пользователями и веб-сайтами. По сути, атака позволяла обходить HTTPS-защиту на уровне самой цепочки доверия, а не конкретного сайта.

## Полная статья

Компания Mozilla[предупредила](https://groups.google.com/a/mozilla.org/g/dev-security-policy/c/0R3XLJL6FuE/m/0XofdebrAAAJ?pli=1)о[компрометации](https://emudhra.we-have-a-problem.com/)закрытых ключей, связанных с восемью[промежуточными](https://en.wikipedia.org/wiki/Intermediate_certificate_authorities)(вторичными) корневыми сертификатами удостоверяющего центра[eMudhra](https://emudhra.com/en-us/). Скомпрометированные ключи позволяли для любого сайта выпустить поддельные TLS-сертификаты, воспринимаемые как заслуживающие доверия во всех браузерах, и использовать их для перехвата или модификации транзитного трафика.

Закрытые ключи были[воссозданы](https://bugzilla.mozilla.org/show_bug.cgi?id=2083449#c5)исследователями из имеющихся в публичном доступе данных, что стало возможным из-за ошибки в процессе генерации ключей на базе эллиптической кривой P-384. Ошибка привела к тому, что ключи были сгенерированы с использованием при инициализации целых чисел меньше 256 вместо криптографически стойких случайных чисел, т.е. размер закрытого ключа составил 1 байт вместо должных 48 байт. При такой генерации закрытый ключ может быть воссоздан c помощью алгоритма дискретного логарифмирования или простым перебором с генерацией первых 256 возможных ключей. Так как значения закрытых ключей теперь известны (4, 56, 66, 115, 155, 156, 230 и 237), всем пользователям рекомендуется срочно обновить браузеры и пакеты с корневыми сертификатами.

В качестве доказательства утечки закрытых ключей[сообщивший](https://bugzilla.mozilla.org/show_bug.cgi?id=2083449)об инциденте исследователь опубликовал[сообщение](https://emudhra.we-have-a-problem.com/proof.zip), подписанное закрытыми ключами от каждого из восьми скомпрометированных сертификатов eMudhra. Проверить свой браузер на предмет обновления информации об отозванных сертификатах можно на[сайте](https://emudhra.we-have-a-problem.com/), посвящённом инциденту.

Экстренно[сформированы](https://blog.mozilla.org/security/2026/10/20/protecting-firefox-users-following-the-compromise-of-emudhra-intermediate-certificates/)корректирующие выпуски Firefox[158.0.1](https://www.firefox.com/en-US/firefox/158.0.1/releasenotes/),[115.43.1](https://www.firefox.com/en-US/firefox/115.43.1/releasenotes/)и[153.5.1](https://www.firefox.com/en-US/firefox/153.5.1/releasenotes/), а также библиотеки[NSS 3.131.1](https://groups.google.com/a/mozilla.org/g/dev-tech-crypto/c/vSxZxnOMMvs), в которых обновлено хранилище корневых сертификатов и заблокированы проблемные сертификаты. В Chrome и продуктах Google скомпрометированные сертификаты заблокированы 17 октября, в Apple - 19 октября, а в Microsoft - 20 октября. Блокировка также выполнена через централизованные списки отозванных сертификатов[OneCRL](https://blog.mozilla.org/security/2015/03/03/revoking-intermediate-certificates-introducing-onecrl/),[CRLite](https://hacks.mozilla.org/2025/08/crlite-fast-private-and-comprehensive-certificate-revocation-checking-in-firefox/)и[CRLSets](https://www.chromium.org/Home/chromium-security/crlsets/).

Пакеты с обновлёнными корневыми сертификатами выпущены для[Ubuntu](https://bugs.launchpad.net/ubuntu/+source/ca-certificates/+bug/2171507)(ca-certificates 20260816ubuntu0.2*.04.1),[Debian](https://tracker.debian.org/pkg/ca-certificates)(ca-certificates 20250419+deb13u1),[Arch Linux](https://archlinux.org/packages/core/x86_64/ca-certificates-mozilla/)(ca-certificates-mozilla 3.131.1-1),[Gentoo](https://bugs.gentoo.org/984601)(ca-certificates 20260816.3.125),[curl](https://curl.se/docs/caextract.html),[Homebrew](https://github.com/Homebrew/homebrew-core/blob/d02b8762f4a29859c47a635a0d2683223fea9812/Formula/c/ca-certificates.rb),[Go](https://groups.google.com/g/golang-announce/c/66pojueaQek)(1.27.3, 1.26.10),[Python](https://github.com/certifi/python-certifi/releases/tag/2026.10.19),[RustTLS](https://github.com/rustls/webpki/releases/tag/v%2F0.103.16),[Electron](https://github.com/electron/electron/releases/tag/v44.9.1)и[Elixir](https://hex.pm/packages/castore/1.0.22). Необновлёнными остаются списки корневых сертификатов в FreeBSD, Node.js, Bun и Composer.

До обновления пакета ca-certificates для ручного удаления проблемных корневых сертификатов в Debian и Ubuntu можно использовать команду:

```

   sed -i \
     -e 's|^mozilla/emSign_ECC_Root_CA_-_G3.crt|!&|' \
     -e 's|^mozilla/Comodo_AAA_Services_root.crt|!&|' \
     /etc/ca-certificates.conf && update-ca-certificates
```

В Fedora, RHEL, CentOS Stream, Rocky Linux, AlmaLinux и Amazon Linux 2023:

```

   d=/etc/pki/ca-trust/source/blocklist; [ -d $d ] || d=/etc/pki/ca-trust/source/blacklist
   trust extract --overwrite --format=pem-bundle \
     --filter='pkcs11:object=Comodo%20AAA%20Services%20root;type=cert' \
     $d/Comodo_AAA_Services_root.pem &&
trust extract --overwrite --format=pem-bundle \
     --filter='pkcs11:object=emSign%20ECC%20Root%20CA%20-%20G3;type=cert' \
     $d/emSign_ECC_Root_CA_-_G3.pem &&
   update-ca-trust
```

В openSUSE и SLES:

```

   d=/etc/pki/trust/blocklist; [ -d $d ] || d=/etc/pki/trust/blacklist
trust extract --format=pem-bundle \
     --filter='pkcs11:object=Comodo%20AAA%20Services%20root;type=cert' \
     $d/Comodo_AAA_Services_root.pem &&
trust extract --format=pem-bundle \
     --filter='pkcs11:object=emSign%20ECC%20Root%20CA%20-%20G3;type=cert' \
     $d/emSign_ECC_Root_CA_-_G3.pem &&
   update-ca-certificates
```

В NixOS:

```

   security.pki.caCertificateBlacklist = [
     "Comodo AAA Services root"
     "emSign ECC Root CA - G3"
   ];
```

В NetBSD:

```

   certctl untrust /usr/share/certs/mozilla/all/emSign_ECC_Root_CA_-_G3.pem &&
   certctl untrust /usr/share/certs/mozilla/all/Comodo_AAA_Services_root.pem
```
