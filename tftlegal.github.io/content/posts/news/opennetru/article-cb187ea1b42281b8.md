# Доступен Emscripten 7.0, компилятор из C/C++ в WebAssembly

## Краткое содержание

Выпущена версия Emscripten 7.0 — инструментария для компиляции кода на C/C++ и других языках с LLVM-фронтэндами в WebAssembly. Полученные результаты можно интегрировать в JavaScript-проекты, запускать в веб-браузере, использовать в Node.js или создавать автономные кроссплатформенные приложения через wasm-рантайм. Проект распространяется по лицензии MIT. В основе компилятора лежат наработки проекта LLVM, а для генерации и оптимизации WebAssembly задействована библиотека Binaryen.

## Полная статья

[Опубликован](https://github.com/emscripten-core/emscripten/releases/tag/7.0.0)выпуск инструментария[Emscripten 7.0](http://emscripten.org/), позволяющего компилировать код на C/C++ и других языках, для которых имеются фронтэнды на базе LLVM, в универсальный низкоуровневый промежуточный код WebAssembly. Полученный результат можно использовать для интеграции с JavaScript-проектами, запуска в web-браузере, использования в Node.js или создания обособленных многоплатформенных приложений, запускаемых при помощи[wasm runtime](https://www.opennet.ru/opennews/art.shtml?num=62137). Код проекта[распространяется](https://github.com/emscripten-core/emscripten/)под лицензией MIT. В компиляторе используются наработки проекта LLVM, а для генерации WebAssembly и оптимизации задействована библиотека[Binaryen](https://github.com/WebAssembly/binaryen).

Основной целью Emscripten заявлено создание инструмента, позволяющего выполнять в Web код независимо от языка программирования, на котором этот код изначально написан. В компилируемых приложениях могут использоваться вызовы стандартных библиотек C и С++ (libc, libcxx), расширения C++, многопоточность на базе pthreads, API POSIX и многие мультимедийные библиотеки. Отдельно предоставляются API для интеграции с Web API и кодом на JavaScript. Emscripten поддерживает трансляцию вывода библиотеки SDL2 через Canvas, а также реализует поддержку[OpenGL](https://emscripten.org/docs/porting/multimedia_and_graphics/OpenGL-support.html)и[EGL](https://emscripten.org/docs/porting/multimedia_and_graphics/EGL-Support-in-Emscripten.html)через API WebGL, что позволяет преобразовывать в WebAssembly графические приложения и игры (например, имеется порт тулкита Qt, поддерживаются игровые движки Unreal Engine и Unity, а также движок симуляции физических процессов Bullet).

Помимо компиляции кода на C/C++ отдельно[развиваются](https://github.com/emscripten-core/emscripten/wiki/Porting-Examples-and-Demos)проекты для запуска в браузерах интерпретаторов и виртуальных машин для языков Lua, C#, Python, Ruby и Perl. Кроме того, возможно применение фронтэндов к LLVM, отличных от Clang, например, фронтэндов для языков, как Swift, Rust, D и Fortran.

Присвоение номера версии 7.0 связано с внесением изменений, нарушающих совместимость. Основные[изменения](https://github.com/emscripten-core/emscripten/blob/main/ChangeLog.md)в Emscripten 7.0:

- Обеспечено прямое связывание всех дополнительных модулей с runtime-библиотеками libclang_rt.builtins и libclang_rt.profile без необходимости экспортирования из основного модуля, как это делается в компиляторе clang.
- Добавлена библиотека libemcc, в которую из libclang_rt.builtins вынесен код, специфичный для Emscripten.
- Из runtime-библиотеки libclang_rt.builtins выделена библиотека libclang_rt.profile, которая теперь используется только при включении профилирования (например, при указании опций -fprofile-instr-generate или --coverage).
- Размер буфера неименованных каналов увеличен до 64 КБ. Неблокирующая запись в заполненный канал теперь завершается ошибкой EAGAIN, но блокирующая запись пока остаётся неограниченной.
- При компиляции и компоновке одной командой вспомогательные файлы, такие как ".dwo" при использовании опции "-gsplit-dwarf" или ".json" при использовании "-ftime-trace", теперь именуются как <output>-<input>.<ext> вместо <input>.<ext>, что соответствует поведению clang.
- Включено автоматическое определение зависимостей для JavaScript-библиотек. Для прямых обращений из одной JavaScript-библиотеки в другую теперь не требуется указание макроса "__deps", который остаётся необходимым только для косвенных зависимостей и зависимостей от скомпилированных библиотек C/C++.
- Удалена переменная окружения EMCC_ONLY_FORCED_STDLIBS, которая ранее была объявлена устаревшей. Для отключения связывания со стандартными библиотеками следует использовать флаг "-nostdlib".
- До кодовой базы LLVM 23.1.3 обновлены библиотеки libcxx, libcxxabi, libunwind и compiler-rt. Задействован выпуск mimalloc 3.6.1.
- Повышены требования к версиям браузеров Chrome 85 -> 93 (август 2021), Firefox 79 -> 92 (сентябрь 2021) и Safari 15.0 -> 15.4 (март 2022).

В частности очень важно чтобы там были драйвера и как-то можно было пользоваться этой ОС программе. Но ОС бывают разные. Более того компьютеры бывают разные. У них бывают разные процессоры, разные видеокарты, разные чипы в общем. И на разных ОС по разному исполняются задачи. Но задачи для разных ОС и железа бывают вполне и весьма типичные, соответственно существуют платформы как вот Java или .NET которые (нынче с компиляцией) выполняют эти задачи независимо от ОС, а на этой платформе, где вот установлена ОС. Так вот wasm по сути и есть такая же платформа. Там своё API, своя система команд. И то что оно изначально делалось для нужд веба, где открытость к исследованию кода и безопасность просто необходима также как и скорость ещё не означает что оно не может быть использовано как-то ещё. Производительность там близка к родному коду. Спецификации в целом открыты, написаны правда так-себе. Компилировать на wasm можно на многих языках программирования. Что вам господа не понятно?
