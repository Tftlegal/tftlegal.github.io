# Опубликован сетевой стек F-Stack 2.0, работающий в пользовательском пространстве

## Краткое содержание

Вышел релиз проекта F-Stack 2.0 — библиотеки, реализующей сетевой стек FreeBSD в пользовательском пространстве. Проект разработан китайской компанией Tencent и применяется в её продуктах и сервисах. Код написан на языке Си и распространяется по лицензии BSD. Поддерживаются платформы Linux и FreeBSD. В рамках проекта доступны модифицированные версии Nginx 1.28 и Redis 6.2.6, работающие поверх F-Stack. Эти сборки демонстрируют производительность, превышающую стандартные версии, использующие системный сетевой стек.

## Полная статья

[Состоялся](https://github.com/F-Stack/f-stack/releases/tag/v2.0)релиз проекта[F-Stack 2.0](http://www.f-stack.org), развивающего редакцию сетевого стека FreeBSD, адаптированную для обособленной работы в пользовательском пространстве в форме библиотеки. Проект создан крупнейшей в Китае телекоммуникационной компанией[Tencent](https://en.wikipedia.org/wiki/Tencent)и используется в её продуктах и сервисах. Код написан на языке Си и[распространяется](https://github.com/F-Stack/f-stack)под лицензией BSD. Поддерживается работа в Linux и FreeBSD. Проектом также[поддерживаются](https://github.com/F-Stack/f-stack/tree/dev/app)переведённые на использование F-Stack редакции Nginx 1.28 и СУБД Redis 6.2.6, демонстрирующие производительность выше обычных сборок, работающих поверх системного сетевого стека.

F-Stack позволяет задействовать в приложениях собственный локальный сетевой стек, не зависящий от сетевого стека операционной системы, функционирующий в пользовательском пространстве и напрямую работающий с сетевым оборудованием. F-Stack позиционируется как решение, позволяющее повысить производительность обработчиков сетевых запросов в условиях, когда штатный TCP/IP стек ядра Linux становится узким местом и ограничивает масштабирование. Теоретически F-Stack позволяет достигнуть потолка сетевой производительности, возможного для используемой сетевой карты, и в некоторых ситуациях даёт возможность в разы увеличить число обрабатываемых мелких сетевых запросов.

Повышение производительности достигается за счёт исключения таких операций, как копирования сетевых пакетов, планирование потоков, обработка прерываний и обращение к системным вызовам. Для взаимодействия с сетевой картой, минуя интерфейсы ядра операционной системы, применяется фреймворк[DPDK](http://dpdk.org/)(Data Plane Development Kit),[развивающий](https://www.opennet.ru/opennews/art.shtml?num=48099)набор библиотек для низкоуровневой работы с сетевыми адаптерами. DPDK даёт возможность снизить накладные расходы и уложиться в минимальное число циклов CPU при приёме или отправке сетевых пакетов.

Функциональность стека TCP/IP соответствует сетевому стеку FreeBSD 15 и выделена из данной операционной системы в независимую библиотеку. Для разработки приложений[можно использовать](https://github.com/F-Stack/f-stack/blob/dev/doc/F-Stack_API_Reference.md)стандартный API POSIX (socket, epoll, kqueue) или собственный программный интерфейс на основе микропотоков, упрощающий создание сетевых приложений и позволяющий обойтись без сложной логики асинхронной обработки запросов. Возможно использование с немодифицированными приложениями с загрузкой через LD_PRELOAD.

Наиболее заметные изменения в новом выпуске:

- Компоненты сетевого стека[обновлены](https://github.com/F-Stack/f-stack/blob/813b82016c5cebfcc545cb44fbbc19dd8d00e99d/docs/freebsd_13_to_15_upgrade_spec/README_EN.md?plain=1)до состояния FreeBSD 15 (ранее использовался FreeBSD 13).
- Реализован режим многопоточной работы (thread_mode=1) в одном процессе, дополняющий ранее доступный многопроцессный режим.
- Добавлен[легковесный](https://github.com/F-Stack/f-stack/issues/1078)режим работы (primary_slim), при котором основной процесс выполняет только базовые задачи инициализации и координации работы, а приём пакетов и обработка очередей приёма/передачи (rx/tx) производится только на стороне дочерних процессов.
- Добавлена поддержка механизма аппаратного ускорения TSO (TCP Segmentation Offload) для выноса на сторону сетевой карты операций объединения пакетов, с возможностью отката на программную реализацию. Улучшена поддержка TSO (TCP Segmentation Offload) для IPv6.
- Добавлена возможность изменения размера[MTU](https://ru.wikipedia.org/wiki/Maximum_transmission_unit)(Maximum transmission unit) и реализована поддержка[jumbo-кадров](https://ru.wikipedia.org/wiki/Jumbo-%D0%BA%D0%B0%D0%B4%D1%80).
- Расширены возможности управления аппаратным ускорением вычисления контрольных сумм отправляемых пакетов
- Добавлена функция ff_zc_recv() для получения данных в без промежуточной буферизации (zero-copy). Переработана аналогичная функция ff_zc_send() для отправки. Оптимизирована и дополнена поддержкой IPv6 функция ff_rss_check().
- Добавлен опция FF_KERNEL_COEXIST для работы совместно с сетевым стеком ядра.
- Предоставлена возможность сохранения информации о трафике в pcap-дампах с наносекундной точностью.
- В config.ini добавлены новые параметры idle_loop_interval, extra_eal_args, drain_ring_size, reload_heartbeat_timeout_ms и reload_udp_idle_ms.
- В специализированной сборке nginx реализована поддержка перезагрузки конфигурации и обновления бинарного файла без разрыва соединений (graceful_reload=1).
