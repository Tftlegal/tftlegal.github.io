# Уязвимость в uBlock Origin, позволяющая подставить JаvaScript-код на чужие сайты

## Краткое содержание

В браузерном расширении uBlock Origin обнаружена уязвимость, позволяющая злоумышленнику внедрить новый фильтр, действующий на сторонних сайтах. Поскольку фильтры внедряют JavaScript-код в страницы, атакующий может выполнить собственный код в контексте любого сайта. Для успешной атаке достаточно, чтобы пользователь кликнул на странице, подготовленной злоумышленником. Полученный доступ позволяет перехватывать конфиденциальные данные введённые пользователем и подменять информацию на страницах, например, номера криптокошельков или ссылки для загрузки. Проблема не получила CVE-идентификатор. Уязвимость была устранена в выпуске uBlock Origin 1.76.0.

## Полная статья

В браузерном дополнении для блокирования нежелательного контента[uBlock Origin](https://github.com/gorhill/uBlock/)выявлена[уязвимость](https://github.com/gorhill/uBlock/security/advisories/GHSA-cmqw-9r2w-6wv2)(CVE не назначен),[позволяющая](https://iter.ca/post/ubo-uxss/)добавить новый[фильтр](https://github.com/gorhill/ublock/wiki/Dashboard:-My-filters), действующий на других сайтах. Фильтры подставляют на страницы JavaScript-код, что даёт возможность атакующему выполнить свой JavaScript-код в контексте любого сайта. Для совершения атаки достаточно, чтобы пользователь кликнул на странице злоумышленника. Выполнение JavaScript кода в контексте чужого сайта позволяет перехватывать вводимые пользователем конфиденциальные данные и подменять информацию на страницах, например, заменять номера криптокошельков и ссылки для загрузки. Проблема устранена в выпуске[uBlock Origin 1.76.0](https://github.com/gorhill/uBlock/releases/tag/1.76.0).

Уязвимость присутствует в механизме отображения интерфейса "Element picker" для добавления собственных правил блокировки и фильтров, который можно вызвать при просмотре страницы через контекстное меню. Интерфейс показывается через подстановку на текущую страницу iframe и загрузки в него содержимого через URL "moz-extension://UUID_дополнения/web_accessible_resources/epicker-ui.html". Данная служебная страница взаимодействует с фоновым обработчиком дополнения и передаёт ему информацию о добавленных пользователем правилах и фильтрах.

Атака сводится к добавлению на страницу атакующего невидимого iframe, загружающего содержимое "Element picker" по служебному URL uBlock Origin. Далее в загруженный интерфейс подставляется новый фильтр, используя для обхода проверки подстановку через поле opt данных, отделённых символом переноса строки. После этого создаются условия для клика пользователя (например, выводится запрос согласия или отказа от передачи Cookie) и позиция невидимого iframe, размещённого поверх содержимого, подбирается так, чтобы клик пришёлся на невидимую кнопку "Create" в интерфейсе uBlock Origin.

Для проведения атаки требуется определение идентификатора дополнения (UUID), который при установке генерируется случайным образом. Чтобы узнать UUID использован трюк с перехватом операции fetch. Для блокирование некоторых ресурсов uBlock Origin перехватывает вызов fetch и выполняет через API XMLHttpRequest запрос к дополнению по служебному URL, например, "moz-extension://UUID_дополнения/web_accessible_resources/googlesyndication_adsbygoogle.js". Атакующий может узнать UUID, перехватив на своей странице вызов XMLHttpRequest и инициировав срабатывание фильтра uBlock Origin через выполнение "fetch('/adsbygoogle.js').catch(() => {});".

В отчёте об уязвимости упоминается, что похожая проблема проявляется и в дополнении[uBlock Origin Lite](https://github.com/uBlockOrigin/uBOL-home)(uBO Lite), использующем третью версию манифеста Chromium, но она не так опасна, как в дополнении uBlock Origin на базе второй версии манифеста, которое продолжает поставляться для Firefox.
