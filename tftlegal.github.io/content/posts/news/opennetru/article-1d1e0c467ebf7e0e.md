# Релиз KDE Plasma 6.8, в котором оставлен только сеанс на базе Wayland

## Краткое содержание

В день тридцатилетия проекта вышла новая версия среды рабочего стола KDE Plasma 6.8. Релиз приурочен к значимой годовщине развития проекта KDE. Для тестирования свежих выпусков KDE разработчики предлагают ряд дистрибутивов. Пользователи могут воспользоваться сборками от проектов KDE Linux и KDE Neon. Также доступны дистрибутивы на базе openSUSE: Argon, основанный на openSUSE Leap, и Krypton, основанный на openSUSE Tumbleweed. Все перечисленные варианты позволяют оценить работу новых компонентов KDE в готовой системе.

## Полная статья

В день тридцатилетия проекта[опубликован](https://kde.org/announcements/plasma/6/6.8.0/)релиз среды рабочего стола[KDE Plasma 6.8](https://community.kde.org/Plasma/). Для оценки работы новых выпусков KDE[можно](https://kde.org/distributions/)[воспользоваться](https://community.kde.org/Distributions)сборками от проектов[KDE Linux](https://files.kde.org/kde-linux/),[KDE Neon](https://neon.kde.org/)и[openSUSE](http://download.opensuse.org/repositories/KDE:/Medias/images/iso/)(Argon, основанный на openSUSE Leap, и Krypton, основанный на openSUSE Tumbleweed).

Основные[изменения](https://community.kde.org/Plasma/Plasma_6#Plasma_6.8)в KDE Plasma 6.8:

- Прекращена поддержка сеанса на базе протокола X11. Оставлен только сеанс для работы с использованием протокола Wayland, возможность запуска X11-приложений в котором обеспечивается при помощи DDX-сервера XWayland. Прекращение поддержки X11 затрагивает только сеанс среды рабочего стола KDE Plasma и не касается возможности запуска приложений KDE в окружениях на базе X-сервера (планов по прекращению поддержки X11 в приложениях KDE пока нет). Для тех, кому требуется X11, по возможности сохранена поддержка данного протокола в различных компонентах рабочего стола и добавлены дополнительные изменения для улучшения совместимости при запуске приложений поверх XWayland.

Среди причин прекращения поддержки X11 упоминается общая стагнация разработки X-сервера и желание не распылять ограниченные ресурсы разработчиков на параллельную поддержку двух дисплейных систем и типов сеансов. Заявлено, что в долгосрочной перспективе избавление от X11 предоставит новые возможности для расширения функциональности, повышения стабильности, оптимизации кода и ускорения процесса разработки.

- В основной состав Plasma перенесена система резервного копирования[kup](https://github.com/KDE/kup), позволяющая создавать версионированные бэкапы данных пользователя и сохранять их на внешние USB-накопители или на сервер. Возможна настройка автоматического сохранения изменений со времени прошлого резервного копирования при подключении к компьютеру накопителя с бэкапами.[

](https://blogs.kde.org/2026/09/12/this-week-in-plasma-6.8-beta-release/kup.webp)
- [Добавлена](https://invent.kde.org/plasma/kscreen/-/merge_requests/487)утилита[kscreenctl](https://invent.kde.org/plasma/kscreen/-/tree/master/kscreenctl?ref_type=heads), идущая на смену kscreen-doctor и предоставляющая более привычный и структурированный интерфейс командной строки для управления выводом. Поддерживаются такие операции, как определение доступных устройств вывода, включение/выключение устройств вывода и изменение настроек.[

Изменение позволило придать типовой для KDE вид таким приложениям, как Steam и Discord, окна которых ранее отрисовывались без теней, обрамления и скруглений.[

Автоматически тени добавляются к X11-приложениям, в которых не используется декорирование на стороне сервера и не отрисовыаются тени на стороне клиента.

![](/news/opennetru/article-1d1e0c467ebf7e0e/image-06.png)

- Значительно[повышена](https://zamundaaa.github.io/wayland/2026/07/31/fixing-multi-gpu.html)производительность при использовании внешних видеокарт. Из-за того, что при использовании Wayland-протокола linux-dmabuf v5 композитный менеджер мог работать только с одной видеокартой, при рендеринге на другом GPU (например, на дискретной видеокарте вместо встроенной) кадры необходимо было постоянно копировать через оперативную память. В новой версии протокола linux-dmabuf v6 проблема была решена и в KWin удалось избавиться от лишнего копирования буферов. В проведённых тестах c видеокартой, подключённой через USB-C, в vkcube FPS вырос с 5 до 120, в игре Cyberpunk 2077 с пресетом "low" FPS увеличился c 27 до 50 при использовании linux-dmabuf v6.
- [Включена](https://invent.kde.org/plasma/kwin/-/merge_requests/9472)[поддержка](https://invent.kde.org/plasma/kwin/-/merge_requests/9472/diffs)тройной буферизации вывода на системах c GPU NVIDIA (Kwin автоматически включает тройную буферизацию, если видеокарта не успевает выполнить отрисовку). При тройной буферизации используется три экранных буфера - в первый осуществляется отрисовка, из второго производится вывод на экран, а третий используется для продолжения непрерывного процесса отрисовки, если первый буфер был заполнен до завершения вертикальной развёртки (vblank). Применение третьего дополнительного буфера позволяет избавиться от рывков, возникающих при двойной буферизации в случае невозможности переключения между буферами отрисовки и вывода до завершения вертикальной развёртки. Подобная организация вывода позволяет повысить частоту кадров на маломощных устройствах, ценой увеличения задержки вывода.
- В KWin[прекращена](https://invent.kde.org/plasma/kwin/-/merge_requests/9488)поддержка десктопного графического API OpenGL в пользу использования только OpenGL ES. Поддержка OpenGL ES требуется для работы на некоторых старых GPU и, как оказалась, OpenGL ES достаточно для всех потребностей KWin, поэтому он оставлен в качестве базового внутреннего API, по крайней мере до тех пор, пока поддержка Vulkan не станет достаточно развита. Оставление только OpenGL ES позволило избавиться от периодически возникающих проблем, вызванных несовместимостями между OpenGL и OpenGL ES (код написанный и протестированный с одним API, приводил к проблемам с отрисовкой или сбоям при использовании другого API).
- В KWin[реализована](https://invent.kde.org/plasma/kwin/-/merge_requests/9112)поддержка новой версии системы[Emulated Input 1.6](https://libinput.pages.freedesktop.org/libei/)(libei), применяемой для эмуляции ввода в окружениях на базе Wayland.
- [Предложена](https://quantumproductions.info/articles/2026-08/union-summer-2026-update)для[тестирования](https://akselmo.dev/posts/union-qtwidgets/)бета-версия унифицированного движка стилей[Union](https://invent.kde.org/plasma/union), позволяющего[использовать](https://api.kde.org/union-index.html)разные технологии стилевого оформления приложений, доступные в KDE. По умолчанию в новом движке задействован формат CSS вместо ранее используемого SVG. Движок Union состоит из трёх слоёв: Входной слой - обеспечивает разбор входных форматов файлов со стилями (SVG или CSS) и их преобразование в абстрактное описание для отрисовки. Промежуточный - реализует модель данных и методы для применения стилей к каждому элементу. Выходной слой - отвечает за преобразование универсального стиля в команды для отрисовки, специфичные для конкретного графического стека (QtQuick или Qt Widgets). Для включения нового движка следует установить пакет union и активировать тему "Breeze (Union)" в настройках (System Settings → Colors & Themes → Application Style).[
