# Для уязвимостей PHP2Shell анонсирован первый эксплоит, обходящий рандомизацию адресов

## Краткое содержание

Исследователи VulnCheck представили первый работающий эксплойт для уязвимости PHP2Shell (CVE-2026-109618б), которая затрагивает PHP 8.4.10–8.4.26 в конфигурации по умолчанию. Ключевой прорыв заключается в обходе ASLR (рандомизации адресов) на x86-64 системах. Ранее создание a real-world exploit was hindered by the difficulty of determining the memory layout of the mod_php module. The developers solved this by exploiting an information leak in PHP's error-display code, which reveals memory addresses. This allows achieving arbitrary code execution on actual systems without needing non-default PHP settings. The result is a fully functional attack against the most common production configuration of the affected PHP versions.

## Полная статья

Исследователи из компании VulnCheck[заявили](https://www.vulncheck.com/blog/php2shell-vulnerabilities)о получении первого эксплоита для[уязвимости PHP2Shell](https://www.opennet.ru/opennews/art.shtml?num=66520)(CVE-2026-109618б), обходящего механизм рандомизации адресов (ASLR) на системах x86-64 с типовой конфигурацией PHP. Эксплоит позволяет атаковать системы с PHP 8.4.10-8.4.26 в конфигурации по умолчанию. Ранее трудность определения раскладки памяти в модуле mod_php мешала реализации эксплоита, позволяющего добиться выполнения кода на реальных системах. Для обхода ASLR в эксплоите задействована утечка информации об адресах в коде отображения информации об ошибках.

Заявлено, что доступ к рабочему эксплоиту предоставлен только клиентам, занимающимся защитой информации, но злоумышленники могут воссоздать используемую технику при помощи AI. Для обходного пути блокирования утечки информации о раскладке адресов следует выставить в php.ini параметр "display_errors=off", помимо ранее опубликованных[рекомендаций](https://www.opennet.ru/opennews/art.shtml?num=66520). VulnCheck также упоминает о том, что на GitHub появились сотни прототипов эксплоитов, но только единицы оценены как рабочие и лишь[один прототип](https://github.com/9bie/php2shell-bypass-aslr-exp/blob/main/archive/legacy-8m/ASLR_PATHS.md)был способен обойти ASLR.

Помимо этого, директор Cloudflare[сообщил](https://x.com/eastdakota/status/2113079352682570051), что компания фиксирует миллионы попыток эксплуатации уязвимостией PHP2Shell, при том, что за 10 часов до анонса наличия уязвимостей таких попыток уже были тысячи, а через 2 часа после официального раскрытия информации достигли сотен тысяч. Судя по всему, в атаках используются прототипы эксплоитов, лишь фиксирующие наличие уязвимых версий PHP, так как пока нет информации о подтверждённых фактах взлома через уязвимости PHP2Shell.

По[данным](https://aws.amazon.com/blogs/security/amazon-threat-intelligence-identifies-php2shell-exploitation-prior-to-public-disclosure-in-madpot/)компании Amazon первые попытки эксплуатации зафиксированы развёрнутыми honeypot-системами ещё 17 октября, т.е. за 3 дня до утечки первых сведений об CVE-идентификаторах. Активность усилилась 21 октября, за 12 часов до публикации корректирующих обновлений PHP, в это время зафиксированы попытки атак с использованием нескольких вариантов прототипов эксплоитов. Попытки атак до официального раскрытия информации также[зафиксировала](https://hadrian.io/vulnerability-alerts/php2shell-leaked-critical-php-rce-cve-2026-109618-cve-2026-109619)компания Hadrian.

Дополнение 1: Компания Perplexity[заявила](https://www.linkedin.com/posts/malwaretech_confirmed-in-the-wild-exploitation-of-php2shell-share-7519864366863847424-TaMU/)о[выявлении](https://x.com/0x4D31/status/2114027420084752479)на своих honeypot-серверах первых успешных[атак](https://www.linkedin.com/posts/malwaretech_confirmed-in-the-wild-exploitation-of-php2shell-share-7519864366863847424-TaMU/)на конфигурации mod_php c PHP 8.4.26,[приведших](https://github.com/0x4D31/honeypot-data/blob/main/reports/php2shell/2026-10-24-confirmed-rce.md)к удалённому выполнению кода. Атака состояла из 4 стадий, потребовавших отправки 51 запроса. Для успешной эксплуатации необходимо, чтобы все эти запросы были обработаны одним рабочим процессом mod_php.

Дополнение 2: Компания Cloudflare организовала[соревнование](https://blog.cloudflare.com/php-ctf/)по взлому системы с уязвимой версией PHP 8.5.11. Победа с денежным вознаграждением будет присуждена тому, чей эксплоит первым определит содержимое файла /flag.

Дополнение 3: Организация CISA (Cybersecurity and Infrastructure Security Agency)[подтвердила](https://www.cisa.gov/news-events/alerts/2026/10/26/cisa-adds-two-known-exploited-vulnerabilities-catalog)выявление реальных атак, осуществляемых через эксплуатацию уязвимостей PHP2Shell.

- Дополнение 4: Для старых версий Debian и Ubuntu подготовлен неофициальный[репозиторой](https://packages.sury.org/php/)с исправленными вариантами устаревших версий пакетов с PHP, включая исправление для ветки PHP 5.6.
- Дополнение 5:[Зафиксирована](https://dreamgroup.com/blog/chained-php2shell-exploit-roots-25-servers)компрометация 25 серверов, для атаки на которые использовался эксплоит, сочетающий эксплутацию уязвимостей PHP2Shell (CVE-2026-109618/CVE-2026-109619) для непривилегированного выполнения кода с уязвимостью[Fragnesia](https://www.opennet.ru/opennews/art.shtml?num=65441)(CVE-2026-46300) для получения прав root в системе.
