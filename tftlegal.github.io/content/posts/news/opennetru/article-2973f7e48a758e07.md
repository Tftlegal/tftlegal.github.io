# Стабильный выпуск СУБД MariaDB 13.0

## Краткое содержание

Представлен MariaDB 13.0.2 — первый стабильный выпуск ветки 13.0.  
Эта ветка относится к промежуточным rolling-выпускам.  
Она продолжает постепенное развитие функциональности СУБД.  
Поддержка будет продолжаться до стабильного релиза следующей ветки.  
Одновременно доступен MariaDB 13.1.1.  
Этот выпуск имеет статус кандидата в релизы.

## Полная статья

[Представлен](https://mariadb.org/mariadb-13-0-is-now-stable/)выпуск СУБД[MariaDB 13.0.2](https://mariadb.com/docs/release-notes/community-server/13.0/13.0.2), который отмечен как первый стабильный релиз ветки 13.0. Ветка MariaDB 13.0 отнесена к промежуточным выпускам (rolling), продолжающим постепенное развитие функциональности и сопровождаемым до стабильного релиза следующей ветки. Одновременно[доступен](https://mariadb.com/docs/release-notes/community-server/13.1/13.1.1)выпуск MariaDB 13.1.1, имеющий статус кандидата в релизы.

Проектом MariaDB развивается ответвление от MySQL, сохраняющее обратную совместимость и[отличающееся](https://www.opennet.ru/opennews/art.shtml?num=39444#note)интеграцией дополнительных движков хранения и расширенных возможностей. Развитие MariaDB курирует независимая организация MariaDB Foundation в соответствии с открытым и прозрачным процессом разработки, не зависящим от отдельных производителей. MariaDB поставляется вместо MySQL во многих дистрибутивах Linux (RHEL, SUSE, Fedora, openSUSE, Slackware, OpenMandriva, ROSA, Arch Linux, Debian) и внедрён в таких крупных проектах, как[Wikipedia](https://www.opennet.ru/opennews/art.shtml?num=36759),[Google Cloud SQL](https://www.opennet.ru/opennews/art.shtml?num=37905)и[Nimbuzz](https://www.opennet.ru/opennews/art.shtml?num=36506).

Среди[изменений](https://mariadb.com/docs/release-notes/community-server/13.0/mariadb-13.0-changes-and-improvements)в ветке MariaDB 13.0:

- [Добавлено](https://jira.mariadb.org/browse/MDEV-10152)выражение "TYPE .. IS REF CURSOR" для объявления ссылочного типа данных для курсора, который может использоваться для возвращения результата SQL-запроса или набора строк из хранимых процедур и функций.
- [Предоставлена](https://jira.mariadb.org/browse/MDEV-38768)возможность использования типа RECORD в параметрах процедур и в значениях, возвращаемых функциями.
- [Добавлен](https://jira.mariadb.org/browse/MDEV-38045)хинт оптимизатора QB_NAME(), позволяющий присвоить имя блоку запроса для последующего применения инструкций по оптимизации этого блока.
- [Добавлена](https://jira.mariadb.org/browse/MDEV-7381)поддержка исполняемых комментариев "/*!! ... */", раскрываемых только в версиях, старее заданной. Например, если в версии MariaDB 10.0 нужно выполнить конструкцию "CREATE OR REPLACE TABLE", а более старых версиях - "CREATE TABLE IF NOT EXISTS":

```

   CREATE /*!100000 OR REPLACE */ TABLE /*!!100000 IF NOT EXISTS */ t1 ...
```

- В таблицу INFORMATION_SCHEMA.SYSTEM_VARIABLES[добавлен](https://jira.mariadb.org/browse/MDEV-35369)столбец IS_DEPRECATED для пометки устаревших переменных, а в таблицах INFORMATION_SCHEMA.STATISTICS и INFORMATION_SCHEMA.COLUMNS[появился](https://jira.mariadb.org/browse/MDEV-36444)столбец CREATE_OPTIONS со сведениями о специфичных для движков возможностях выражения "CREATE TABLE".
- [Предоставлена](https://jira.mariadb.org/browse/MDEV-18386)возможность настройки формата времени, указываемого в логах плагина для проведения аудита.
- [Обеспечено](https://jira.mariadb.org/browse/MDEV-25292)атомарное выполнение операции "CREATE OR REPLACE TABLE".
- [Реализована](https://jira.mariadb.org/browse/MDEV-5092)конструкция "UPDATE ... RETURNING", позволяющая обновить строки и сразу вернуть их изменённые значения.
- [Добавлена](https://jira.mariadb.org/browse/MDEV-37949)переменная innodb_log_archive для включения режима сохранения файлов с WAL-логами (вместо цикличной перезаписи лога в одном файле, после заполнения запись переключается на новый файл).
- В движке MEMORY[ускорена](https://jira.mariadb.org/browse/MDEV-21543)работа индексов (UNIQUE INDEX) для столбцов типа CHAR.
