# Релиз СУБД PostgreSQL 19

## Краткое содержание

После года разработки опубликована новая стабильная ветка СУБД PostgreSQL 19. Обновления для этой ветки будут выходить в течение пяти лет, до ноября 2031 года. Поддержка PostgreSQL 14.x — самой старой из поддерживаемых версий — прекращена в этом же месяце. Релиз вышел почти на два месяца позже изначально запланированной даты. Причина задержки — необычно большой поток сообщений об ошибках, обнаруженных благодаря анализу кода с помощью ИИ-инструментов.

## Полная статья

После года разработки[опубликована](https://www.postgresql.org/about/news/postgresql-19-released-3449/)новая стабильная ветка СУБД[PostgreSQL 19](https://www.postgresql.org). Обновления для новой ветки[будут выходить](https://www.postgresql.org/support/versioning/)в течение пяти лет до ноября 2031 года. Поддержка PostgreSQL 14.x, самой старой из поддерживаемых веток, прекращена в этом месяце. Релиз опубликован почти на два месяца позднее изначально намеченной даты из-за несвойственного прошлым выпускам потока сообщений об ошибках, выявленных благодаря анализу кода при помощи AI-инструментов.

Основные[новшества](https://www.postgresql.org/docs/19/release-19.html):

- [Улучшена](https://thebuild.com/blog/async-io-in-postgresql-19-the-year-after/)реализация[подсистемы](https://wiki.postgresql.org/wiki/AIO)асинхронного ввода/вывода, позволяющей увеличить пропускную способность ввода/вывода и избавиться от задержек. В универсальной реализации AIO (io_method=worker) появилась возможность автоматического увеличения или уменьшения числа запущенных процессов-обработчиков ввода/вывода в зависимости от нагрузки. Для определения минимального и максимального числа процессов-обработчиков, а также таймута неактивности перед завершением и задержки перед запуском процессов, предложены параметры[io_min_workers](https://www.postgresql.org/docs/19/runtime-config-resource.html#GUC-IO-MIN-WORKERS),[io_max_workers](https://www.postgresql.org/docs/19/runtime-config-resource.html#GUC-IO-MAX-WORKERS),[io_worker_idle_timeout](https://www.postgresql.org/docs/19/runtime-config-resource.html#GUC-IO-WORKER-IDLE-TIMEOUT)и[io_worker_launch_interval](https://www.postgresql.org/docs/19/runtime-config-resource.html#GUC-IO-WORKER-LAUNCH-INTERVAL).

Кроме того, применяемый в AIO планировщик упреждающего чтения оптимизирован для повышения производительности запросов, требующих загрузки большого объёма данных с диска. Оптимизация реализована за счёт адаптивного определения допустимого числа операций упреждающего чтения в зависимости от характера и размера запроса (например, для операций сканирования крупных таблиц и индексов теперь заранее подгружается с диска больше данных). Для анализа выполнения операций ввода/вывода в асинхронном режиме в команду "[EXPLAIN ANALYZE](https://www.postgresql.org/docs/19/sql-explain.html)" добавлена опция "IO".

- Добавлены расширения[pg_plan_advice](https://www.postgresql.org/docs/19/pgplanadvice.html)и[pg_stash_advice](https://www.postgresql.org/docs/19/pgstashadvice.html)для передачи планировщику запросов параметров-подсказок на мини-языке "plan advice", позволяющих влиять на выбор планов выполнения, фиксировать выбранные планы и экспериментировать с разными планами. Для получения списка параметров, выбранных планировщиком при выполнении запроса, в команду EXPLAIN добавлена опция "PLAN_ADVICE", а для выставления своих параметров перед выполнением запроса можно использовать выражение "SET pg_plan_advice.advice = 'строка со списком параметров'". Расширение pg_stash_advice дополняет pg_plan_advice возможностями для привязки параметров к идентификаторам запросов, чтобы не добавлять их перед каждым запросом.

```

   EXPLAIN (COSTS OFF, PLAN_ADVICE) SELECT * FROM join_fact f JOIN join_dim d ON f.dim_id = d.id;
   ...
   Generated Plan Advice:
      JOIN_ORDER(f d)
      HASH_JOIN(d)
      SEQ_SCAN(f d)
      NO_GATHER(f d)

   SET pg_plan_advice.advice = 'JOIN_ORDER(f d) NO_GATHER(f d)';
```

- В процесс автоматического запуска очистки ([autovacuum](https://www.postgresql.org/docs/19/routine-vacuuming.html#AUTOVACUUM)) добавлена возможность параллельного использования нескольких обработчиков при выполнении чистки индексов. Число обработчиков настраивается через опцию[autovacuum_max_parallel_workers](https://www.postgresql.org/docs/19/runtime-config-autovacuum.html#GUC-AUTOVACUUM-MAX-PARALLEL-WORKERS). Также добавлены новые опции[autovacuum_vacuum_score_weight](https://www.postgresql.org/docs/19/runtime-config-vacuum.html#GUC-AUTOVACUUM-VACUUM-SCORE-WEIGHT),[autovacuum_vacuum_insert_score_weight](https://www.postgresql.org/docs/19/runtime-config-vacuum.html#GUC-AUTOVACUUM-VACUUM-INSERT-SCORE-WEIGHT)и[autovacuum_analyze_score_weight](https://www.postgresql.org/docs/19/runtime-config-vacuum.html#GUC-AUTOVACUUM-ANALYZE-SCORE-WEIGHT)для определения приоритета очистки таблиц.
- Реализована новая стратегия очистки, позволяющая сократить обьём работы в будущем, благодаря обновлению карты видимости страниц во время сканирования таблиц при выполнения SELECT-запросов, не дожидаясь запуска команды VACUUM.
- Добавлена новая SQL-команда "[REPACK](https://www.postgresql.org/docs/19/sql-repack.html)" для перестроения таблиц с меньшими накладными расходами. Команда REPACK полностью перезаписывает всё содержимое таблицы в новый файл на диске, что позволяет вернуть операционной системе место на диске, которое занимают неиспользуемые блоки. В отличие от команды "VACUUM FULL", во время перезаписи выставляющей жёсткую блокировку, в команде REPACK имеется опция "CONCURRENTLY", при указании которой во время переупаковки допускается использование таблицы другими транзакциями. В отличие от расширения pg_repack, REPACK заметно быстрее, так как не прикрепляет к таблице дополнительные триггеры, но не поддерживает обработку целиком секционированных таблиц.
- До двух раз повышена производительность операции INSERT для таблиц, в которых выполняется проверка записей по внешним ключам (Foreign Key). Ускорение достигнуто за счёт привлечения индекса для проверки внешнего ключа, что позволило обойтись без выполнения ресурсоёмкого внутреннего запроса к таблице.
- В планировщике запросов обеспечено распознавание операций Anti-Join (определение строк из первой таблицы, для которых отсутствуют совпадения во второй таблице) в сложных запросах с "LEFT JOIN" и запросах с выражениями "NOT IN" для задействования специфичных оптимизаций. Расширено применение инкрементальной сортировки. Добавлена оптимизация "[eager aggregation](https://www.postgresql.org/docs/19/runtime-config-query.html#GUC-ENABLE-EAGER-AGGREGATE)", выносящая операции агрегирования на стадию до слияния таблиц для сокращения числа строк, обрабатываемых в процессе слияния. Ускорено параллельное выполнение операций последовательного сканирования (parallel seq scan). Реализовано сведение конструкций "IS DISTINCT FROM" и "IS NOT DISTINCT FROM" к выражением с операторами "<>" и "=", если оба операнда не могут принимать значение NULL.
- Повышена эффективность доставки уведомлений при помощи команды[NOTIFY](https://www.postgresql.org/docs/19/sql-notify.html)в конфигурациях с несколькими каналами уведомлений. В разделяемой памяти теперь сохраняется карта каналов, позволяющая адресно обращаться только к бэкендам, подписанным на заданный канал.
- В команду "INSERT" добавлена поддержка выражения[ON CONFLICT DO SELECT ... RETURNING](https://www.postgresql.org/docs/19/sql-insert.html#SQL-ON-CONFLICT), возвращающего записи, в случае невозможности их добавления через "INSERT", в дополнение к выражениям "ON CONFLICT DO NOTHING/UPDATE", молча игнорирующих конфликты при вставке или выполняющих обновление вместо вставки.
- В команду[COPY](https://www.postgresql.org/docs/19/sql-copy.html)добавлена поддержка вывода данных в формате JSON.
- В язык[SQL/JSON](https://www.postgresql.org/docs/19/functions-json.html#FUNCTIONS-SQLJSON-PATH-OPERATORS)добавлены методы обработки строк lower(), upper(), replace(), split_part() и btrim().
- В[оконных функциях](https://www.postgresql.org/docs/19/functions-window.html)lead(), lag(), first_value(), last_value() и nth_value() добавлена поддержка выражения "IGNORE NULLS" для пропуска значений NULL.
- Добавлена команда "[WAIT FOR LSN](https://www.postgresql.org/docs/19/sql-wait.html)", которая при асинхронной репликации для предотвращения вывода устаревших данных позволяет приостановить SELECT-запрос на реплицированном сервере до тех пор, пока не применятся изменения с основного сервера, соответствующие определённой LSN-позиции (Log Sequence Number) в WAL-логе.
- В функцию[random()](https://www.postgresql.org/docs/19/functions-math.html#FUNCTIONS-MATH-RANDOM-TABLE)добавлена поддержка типов date и timestamp для генерации случайных дат и времени в заданном диапазоне.
- [Добавлена](https://www.postgresql.org/docs/19/plpython-event-trigger.html)возможность создавать на языке PL/Python функции для триггеров событий ([event trigger](https://www.postgresql.org/docs/19/event-triggers.html)).
- В принимающий сетевые соединения сервер[добавлена](https://www.postgresql.org/docs/19/ssl-tcp.html#SSL-SNI)поддержка TLS-расширения SNI (Server Name Indication) для использования TLS-сертификатов в привязке к именам хостов, к которым обращается клиент при установке шифрованного соединения по одному IP-адресу.
- В файл конфигурации postgresql.conf добавлен параметр[password_expiration_warning_threshold](https://www.postgresql.org/docs/19/runtime-config-connection.html#GUC-PASSWORD-EXPIRATION-WARNING-THRESHOLD), при помощи которого можно настроить вывод предупреждения о скором истечения времени действия пароля.
- Включён по умолчанию вывод предупреждений при использовании алгоритма MD5 при аутентификации, который объявлен устаревшим. Для отключения подобных предупреждений добавлен параметр[md5_password_warnings](https://www.postgresql.org/docs/19/runtime-config-connection.html#GUC-MD5-PASSWORD-WARNINGS).
- Добавлены представления: "[pg_stat_lock](https://www.postgresql.org/docs/19/monitoring-stats.html#MONITORING-PG-STAT-LOCK-VIEW)" для просмотра накопленной статистики о блокировках в привязке к типам блокировок; "[pg_stat_recovery](https://www.postgresql.org/docs/19/monitoring-stats.html#MONITORING-PG-STAT-RECOVERY-VIEW)" для получения информации о состоянии операций восстановления; "[pg_stat_autovacuum_scores](https://www.postgresql.org/docs/19/monitoring-stats.html#PG-STAT-AUTOVACUUM-SCORES-VIEW)" для определения приоритета обработки таблиц в autovacuum. Во многие системные представления добавлен столбец "stats_reset", в котором отражено последнее время очистки счётчиков. В представления "[pg_stat_progress_vacuum](https://www.postgresql.org/docs/19/progress-reporting.html#VACUUM-PROGRESS-REPORTING)" и "[pg_stat_progress_analyze](https://www.postgresql.org/docs/19/progress-reporting.html#ANALYZE-PROGRESS-REPORTING)" добавлен столбец "started_by", в котором показывается инициатор операции. В представление pg_stat_progress_vacuum добавлен столбец "mode", отражающий применяемый режим чистки.
- Добавлена возможность указания минимальных уровней информативности логов ([log_min_messages](https://www.postgresql.org/docs/19/runtime-config-logging.html#GUC-LOG-MIN-MESSAGES)) в привязке к типам процессов.
- В статистику, показываемую после операций[VACUUM](https://www.postgresql.org/docs/19/sql-vacuum.html)и[ANALYZE](https://www.postgresql.org/docs/19/sql-analyze.html), а также в представление "[pg_stat_wal](https://www.postgresql.org/docs/19/monitoring-stats.html#PG-STAT-WAL-VIEW)", добавлены сведения о размере записанных в WAL-лог полных страниц, что упрощает разбор причин излишнего разрастания WAL-лога (можно понять связан ли рост с использованием параметра full_page_writes).
- В механизме логической репликации[реализована](https://www.postgresql.org/docs/19/logical-replication-sequences.html)поддержка реплицирования значений последовательностей (SEQUENCE), которые можно[публиковать](https://www.postgresql.org/docs/19/logical-replication-publication.html)командой "[CREATE PUBLICATION](https://www.postgresql.org/docs/19/sql-createpublication.html)" при помощи выражения "FOR ALL SEQUENCES".
- Добавлен синтаксис "[CREATE PUBLICATION ... EXCEPT](https://www.postgresql.org/docs/19/sql-createpublication.html)" для репликации всех таблиц за исключением явно указанных.
- Добавлено выражение "[CREATE SUBSCRIPTION ... SERVER](https://www.postgresql.org/docs/19/sql-createsubscription.html)", позволяющее создавать подписки логической репликации, получая настройки подключения от стороннего сервера.
- Добавлена возможность включения логической репликации на лету без перезапуска сервера, даже если параметр "[wal_level](https://www.postgresql.org/docs/19/runtime-config-wal.html#GUC-WAL-LEVEL)" выставлен в значение "replica" вместо "logical". Для определения реально действующего уровня журналирования, не привязанного к настройке wal_level в файле конфигурации, добавлен параметр "[effective_wal_level](https://www.postgresql.org/docs/19/runtime-config-preset.html#GUC-EFFECTIVE-WAL-LEVEL)".
- В механизме подключения внешних таблиц Foreign Data Wrapper ([postgres_fdw](https://www.postgresql.org/docs/19/postgres-fdw.html)) реализованы возможности для проброса операций с массивами на удалённый сервер и добавлена опция[import_stats](https://www.postgresql.org/docs/19/postgres-fdw.html#POSTGRES-FDW-OPTIONS-COST-ESTIMATION)для импорта статистики для таблиц из внешнего сервера при выполнении команды ANALYZE для повышения эффективности локального планирования выполнения запросов.
- По умолчанию отключена JIT-компиляция так как заметный выигрыш в производительности она даёт в основном для тяжёлых аналитических запросов, а в обычных OLTP-нагрузках может приводить к провалам в производительности из-за ошибок при предсказании ресурсов, необходимых для выполнения запросов.
- Для повышения производительности сжатия и распаковки[TOAST-таблиц](https://www.postgresql.org/docs/19/storage-toast.html)параметр "default_toast_compression" выставлен в значение "lz4".
- Удалена поддержка аутентификации с использованием протокола RADIUS.
- В команде "vacuumdb --analyze-only" по умолчанию включён анализ секционированных таблиц.

Из-за проблем, выявленных на финальном этапе тестирования, в состав релиза не вошли некоторые возможности, представленные в бета-версии, такие как синтаксис "GROUP BY ALL", поддержка нетекстовых форматов вывода в pg_dumpall, SQL/PGQ для графовых запросов, включение на лету поддержки контрольных сумм без перезапуска и переинициализации, выражение "FOR PORTION OF" в UPDATE и DELETE, выражения "ALTER TABLE ... MERGE PARTITIONS" и "ALTER TABLE ... SPLIT PARTITIONS" для реорганизации секционированных таблиц, выставление LC_COLLATE в значение "C" для процесса postmaster и новые функции pg_get_role_ddl(), pg_get_tablespace_ddl() и pg_get_database_ddl().
