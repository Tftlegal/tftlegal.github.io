# Выпуск системы мониторинга Zabbix 8.0

## Краткое содержание

Состоялся релиз версии Zabbix 8.0 — открытой системы мониторинга. Новая редакция отнесена к семейству LTS, то есть получает длительную официальную поддержку. Zabbix представляет собой универсальный инструмент для контроля производительности и доступности широкого спектра IT-инфраструктуры. В его зону мониторинга входят серверы, сетевое и инженерное оборудование, приложения, базы данных, системы виртуализации, контейнеры, облачные сервисы и веб-приложения. Проект распространяется на условиях лицензии AGPLv3, что делает код полностью открытым для использования и модификации.

## Полная статья

[Состоялся](https://www.zabbix.com/ru/rn/rn8.0.0)релиз открытой системы мониторинга[Zabbix 8.0](https://www.zabbix.com/), который отнесён к версиям с длительным сроком официальной поддержки (LTS). Zabbix - универсальная система для мониторинга производительности и доступности серверов, инженерного и сетевого оборудования, приложений, баз данных, систем виртуализации, контейнеров, IT-сервисов, web-сервисов и облачной инфраструктуры. Код проекта[распространяется](https://github.com/zabbix/zabbix)под лицензией AGPLv3.

Система реализует полный цикл от сбора данных, их обработки и преобразования, анализа этих данных для обнаружения проблем, и заканчивая хранением этих данных, визуализацией и рассылкой оповещений с использованием правил эскалации. Также система предоставляет гибкие возможности расширения методов сбора данных и оповещений, а также возможности автоматизации через мощный API. Для централизованного управления предоставляется web-интерфейс.

Основные улучшения в версии 8.0 LTS ([1](https://www.zabbix.com/ru/whats_new_8_0),[2](https://www.zabbix.com/ru/rn/rn8.0.0),[3](https://www.zabbix.com/documentation/8.0/ru/manual/whatsnew)):

- Реализована возможность мониторинга производительности приложений (APM, Application Performance Monitoring) со сбором данных с использованием протокола[OpenTelemetry](https://opentelemetry.io/docs/what-is-opentelemetry/)(OTLP/gRPC) для отслеживания прохождения запросов через приложения и сервисы, измерения их производительности и выявления причин медленных или неудачных операций. Полученные данные телеметрии можно использовать в триггерах и визуализировать на графиках.[

![](/news/opennetru/article-90a0c8f71bedd70d/image-01.png)

](https://assets.zabbix.com/img/8.0/app_monitoring_5_1424x800.png)
- Заявлено увеличение производительности обработки метрик в 10 раз. Внесены оптимизации для снижения нагрузки на CPU, сокращения ввода/вывода и повышения масштабируемости. Сокращено время запуска Zabbix за счет одновременной загрузки исторических данных из БД. В сервере, прокси и агенте Zabbix реализовано кэширование DNS-запросов при помощи резолвера[c-ares](https://github.com/c-ares/c-ares).
- Реализован механизм[обработки сложных событий](https://www.zabbix.com/documentation/8.0/ru/manual/events/complex_event_processing)(CEP, Complex Event Processing), выполняющий обработку событий Zabbix на основе правил для анализа причин возникновения событий, оценки корреляции событий, сопоставления с шаблоном и снижения информационного шуму за счет дедупликации, подавления или отбрасывания нежелательных событий. CEP позволяет группировать связанные события, помечать первое событие в серии как причину, задавать время жизни событий, лимитировать максимальное количество определённых событий, получать уведомления о похожих событиях по местоположению и получать уведомления, если какое-либо событие происходит слишком часто или не происходит вообще в течение определенного периода времени. Поддерживается определение временных окон, в пределах которых все события образуют единый контекст и могут анализироваться как единое целое.[

![](/news/opennetru/article-90a0c8f71bedd70d/image-02.png)

](https://assets.zabbix.com/img/8.0/cloud_native_1_1461x800.png)
- Реализован MCP-сервер для подключения AI-агентов к Zabbix. Можно давать AI-ассистенту команды и задавать вопросы о мониторинге на естественном языке, а также использовать AI для выявления причин проблем, анализа данных и отсеивания информационного шума. MCP-сервер учитывает права доступа и роли пользователей.[

![](/news/opennetru/article-90a0c8f71bedd70d/image-03.png)

](https://assets.zabbix.com/img/8.0/mcp_server_2_1424x800.png)
- Предоставлены возможности для изменения компоновки таблиц в web-интерфейсе, позволяющие скрывать/показывать столбцы, менять порядок и изменять ширину столбцов, добавлять дополнительные столбцы с произвольным текстом (например, данными инвентаризации) и значениями макросов.[

![](/news/opennetru/article-90a0c8f71bedd70d/image-04.png)

](https://assets.zabbix.com/img/8.0/custom_tables_1_1375x584.png)
- Модернизирован web-интерфейс. Добавлена тёмно-синяя тема оформления. Предложены новые встроенные шрифты, обеспечивающие единообразный внешний вид в разных системах. Реализовано полное наследование тегов для шаблонов, узлов сети и элементов данных. В формах ввода реализована встроенная проверка ошибок ввода. Добавлена возможность импортирования сертификатов и закрытых ключей SAML. Закруглены края полей ввода.[

![](/news/opennetru/article-90a0c8f71bedd70d/image-05.png)

](https://assets.zabbix.com/img/8.0/uxui_1_1492x800.png)
- Добавлен виджет "Диаграмма рассеяния". Реализована поддержка инвертирования значений оси Y в виджете "График", объединения близко расположенных маркеров карты в виджете "Геокарта" и группировки шаблонов в виджете "Топ элементов данных".[

![](/news/opennetru/article-90a0c8f71bedd70d/image-06.png)

](https://www.zabbix.com/documentation/8.0/assets/en/manual/web_interface/frontend_sections/dashboards/widgets/scatter_plot_overview.png)
- Реализована возможность импорта и экспорта панелей мониторинга вместе с их страницами, виджетами и конфигурацией, например, для использования на других серверах. Панели могут сохраняться в форматах YAML, JSON и XML.[

![](/news/opennetru/article-90a0c8f71bedd70d/image-07.png)

](https://www.zabbix.com/documentation/8.0/assets/en/manual/xml_export_import/export_dashboards.png)
- Добавлены готовые информационные панели, которые можно импортировать из репозитория, такие как панель для мониторинга затрат на облачные ресурсы в AWS, Azure, Google Cloud и Oracle Cloud, и панель для мониторинга виртуальных машин, работающих в AWS, Google Cloud, Oracle Cloud и Azure.[

![](/news/opennetru/article-90a0c8f71bedd70d/image-08.png)

](https://assets.zabbix.com/img/8.0/visualization_1_1620x539.png)
- Предоставлена возможность использования СУБД ClickHouse в качестве серверной базы данных Zabbix для хранения истории значений элементов данных, а также в качестве источника данных телеметрии для мониторинга производительности приложений.
- Стабилизирована поддержка Elasticsearch и реализована возможность использования Elasticsearch 8.x и 9.x для хранения истории.
- Добавлена поддержка определения периодов обслуживания для триггеров или имён событий.
- Разрешено фильтровать список глобальных регулярных выражений по имени и описанию. Добавлена поддержка импорта и экспорта глобальных регулярных выражений.
- Добавлены новые шаблоны, например, шаблоны для мониторинга использования API Claude; отслеживания состояния кластера и узлов Kubernetes, Microsoft Hyper-V, Proxmox VE и Podman; мониторинга СУБД MariaDB и Percona, коммутаторов Aruba CX 8300, Ciena 3906, Cisco Secure Firewall, Cradlepoint NCM v2, Huawei AR600, Ribbon SBC, Vyatta Virtual Router.
- Добавлена поддержка JSON в качестве типа данных для значений элементов данных.
