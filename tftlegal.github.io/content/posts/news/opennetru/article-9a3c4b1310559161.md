# Аnthropic развивает технику для формальной верификации существующего ПО при помощи AI

## Краткое содержание

Компания Anthropic опубликовала результаты эксперимента по применению ИИ-моделей для формальной верификации. Цель работы состояла в проверке надёжности и безопасности уже существующих проектов. В ходе эксперимента были проанализированы 123 открытые библиотеки. Тестирование проводилось в инфраструктуре OSS Fuzz. С помощью ИИ-моделей для каждой из этих библиотек были сгенерированы строгие математические доказательства. Эти доказательства подтверждают отсутствие ошибок при работе с памятью. Таким образом, показано, что ИИ способен выполнять задачи формальной верификации на реальных открытых проектах.

## Полная статья

Компания Аnthropic[представила](https://www.anthropic.com/research/formal-verification)результаты[экспериментов](https://www-cdn.anthropic.com/files/4zrzovbb/website/6867eadf760258fa8b42a504600cd3c036d16358.pdf)по использованию AI-моделей для[формальной верификации](https://ru.wikipedia.org/wiki/%D0%A4%D0%BE%D1%80%D0%BC%D0%B0%D0%BB%D1%8C%D0%BD%D0%B0%D1%8F_%D0%B2%D0%B5%D1%80%D0%B8%D1%84%D0%B8%D0%BA%D0%B0%D1%86%D0%B8%D1%8F)надёжности и безопасности уже существующих проектов. В ходе эксперимента при помощи AI-моделей для 123 открытых библиотек, протестированных в инфраструктуре[OSS Fuzz](https://www.opennet.ru/opennews/art.shtml?num=45602), были сгенерированы математические доказательства отсутствия ошибок при работе с памятью.

Проверка проводилась на уровне скомпилированного ассемблерного кода для архитектуры RISC-V. Общий объём сгенерированных доказательств составил около 180 миллионов строк кода для системы верификации[Rocq Prover](https://rocq-prover.org/)(около 600 тысяч строк на бинарный файл с 18 тысячами RISC-V инструкций). Доказательства формировались путём автоматического преобразования существующих fuzzing-тестов в формальные спецификации, после чего AI-модель Claude доказывала, что при любых входных данных объёмом до 64 МБ в программе не возникает сбоев.

В процессе построения доказательств AI-модель смогла выявить и подготовить исправления для сотен ошибок, ранее не замеченных при fuzzing-тестировании. Среди прочего, были выявлены уязвимости, приводящие к переполнению буфера при обработке определённых входных данных (например,[CVE-2026-56132](https://security-tracker.debian.org/tracker/CVE-2026-56132)в libexpat), а также логические ошибки. Помимо этого, AI-модель была использована для доказательства соответствия реализации алгоритма zlib в ядре Linux спецификации[RFC 1950](https://www.rfc-editor.org/info/rfc1950/).

Также на языке Rust был сгенерирован интерпретатор для подмножества языка Python, для которого при помощи инструментария[Verus](https://github.com/verus-lang/verus)подготовлено формальное доказательство соответствия семантике CPython. Для сравнения поведения с CPython было выполнено более 1.7 миллионов случайно сгенерированных Python-программ. В 99.95% случаев результаты выполнения этих программ в новой реализации и в CPython совпали, а выявленные расхождения оказались известными граничными случаями.

Проведённая формальная верификация гарантирует соответствие спецификации, но полностью не исключает возникновение проблем с безопасностью, так как остаются неформализованными риски, вызванные проблемами с многопоточностью, динамическим связыванием и аномальным поведением реального оборудования. Ключевым преимуществом предложенного подхода является работа непосредственно с бинарными файлами, что позволяет обойтись без необходимости переписывания существующего кода на формально верифицируемых языках.
