# Основатель CentOS и Rocky Linux представил Linux-совместимое ядро Ginux, написанное на Rust

## Краткое содержание

Грегори Курцер, основатель дистрибутивов CentOS и Rocky Linux, представил проект Ginux — операционную систему с ядром, написанным на языке Rust. Главная цель проекта — обеспечить совместимость с ядром Linux. Опубликованный исследовательский прототип уже умеет загружать окружение Alpine с BusyBox и Rocky Linux 10 с systemd в многопользовательском консольном режиме. Исходный код распространяется под лицензией Apache 2.0. На данный момент поддерживается только архитектура x86-64.

## Полная статья

Грегори Курцер (Gregory Kurtzer), основатель дистрибутивов CentOS и Rocky Linux,[представил](https://x.com/gmkurtzer/status/2114958282481910115)проект[Ginux](https://github.com/gmkurtzer/ginux), развивающий ядро операционной системы на языке Rust, нацеленное на достижение совместимости с ядром Linux. Опубликованный исследовательский прототип уже способен загрузить системное окружение дистрибутивов Alpine с BusyBox и Rocky Linux 10 с systemd в многопользовательском консольном режиме. Код проекта[распространяется](https://github.com/gmkurtzer/ginux)под лицензией Apache 2.0. Поддерживается работа на системах с архитектурой x86-64.

Прототип создан за 11 дней в рамках эксперимента по[применению](https://zenodo.org/records/23682548)техники разработки HDAE (Human-Directed Agentic Engineering) для создания сложных проектов, уровня ядра Linux. При использовании метода HDAE код генерируется AI-агентом (использован Codex c моделью GPT-5.6 Sol), а человек сосредоточен на разработке архитектуры, принятии решений, координации работы, формировании плана разработки и определении критериев готовности развиваемых компонентов. AI-агенты также привлекаются для тестирования, рецензирования и диагностики проблем.

Проект не пытается копировать технологии из ядра Linux, а создаёт[собственные](https://github.com/gmkurtzer/ginux/blob/main/ARCHITECTURE.md)совместимые реализации с оглядкой на них. Ginux предоставляет независимые систему управления памятью, планировщик задач, загрузочный процесс, модель процессов, файловые системы, сетевой стек, драйверы устройств и слой для совместимости с Linux ABI. Ядро Ginux загружается напрямую через UEFI без привлечения хостовой Linux-системы.

Ginux пока не претендует на замену Linux и не готов для использования в рабочих системах, но уже пригоден для проведения экспериментов и тестирования. В долгосрочной перспективе проект рассматривается как операционная система для запуска в изолированных контейнерах компонентов для AI-инфраструктуры. Имя Ginux сформировано как комбинация из слов GPT/Gregory и Linux. Основой платформой для тестирования является запускаемая при помощи гипервизора KVM виртуальная машина[Q35](https://wiki.qemu.org/images/4/4e/Q35.pdf)(Intel Q35/ICH) с OVMF (Open Virtual Machine Firmware), Intel IOMMU и virtio-устройствами.

Из 375 системных вызовов ядра Linux 6.12[полностью реализовано](https://github.com/gmkurtzer/ginux/blob/main/docs/LINUX-COMPATIBILITY.md)82, частично - 245 и заблокировано из соображений безопасности - 48. Для выявления сбоев, которые невозможно выявить в синтетических тестах, работа ядра оценивается при запуске реальных приложений и библиотек, таких как musl, glibc, BusyBox и systemd.

Среди планов:

- Обеспечение запуска компонентов пользовательского пространства Linux-дистрибутивов без использования ядра Linux.
- Возможность создания изолированных доменов со своими наборами процессов, адресным пространством, файловыми системами, устройствами, ресурсами и независимым жизненным циклом.
- Подготовка самодостаточного загрузочного образа.
- Предоставление минимального управляющего окружения в пространстве пользователя (userspace control plane), позволяющего управлять ядром без выполнения кода на нулевом кольце защиты.
- Система управления доступом, работающая на уровне именованных объектов.
- Поддержка изолированного запуска образов контейнеров в формате OCI.
