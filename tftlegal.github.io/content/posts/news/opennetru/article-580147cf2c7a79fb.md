# Выпуск ядра Asterinas 0.19, написанного на языке Rust и совместимого с Linux

## Краткое содержание

Вышел релиз 0.19 проекта Asterinas — операционного ядра, написанного на языке Rust. Ядро предназначено для систем общего назначения и обеспечивает совместимость с ABI ядра Linux, что позволяет использовать его как его замену. Параллельно с ядром развивается дистрибутив Asterinas NixOS, объединяющий ядро Asterinas с системным окружением NixOS. Разработка кода ведётся с 2022 года. Проект распространяется под лицензией MPL (Mozilla Public License).

## Полная статья

[Опубликован](https://asterinas.github.io/2026/10/13/announcing-asterinas-0.19.0.html)релиз проекта[Asterinas 0.19](https://asterinas.github.io/), развивающего ядро, написанное на языке Rust и предназначенное для использования в операционных системах общего назначения. Ядро предоставляет ABI (Application Binary Interface), совместимый с ядром Linux и способный использоваться вместо него. Параллельно развивается дистрибутив[Asterinas NixOS](https://asterinas.github.io/book/distro/index.html), сочетающий ядро Asterinas с системным окружением NixOS. Код проекта развивается с 2022 года и[распространяется](https://github.com/asterinas/asterinas)под лицензией MPL (Mozilla Public License).

В настоящее время в ядре реализовано более 240 системных вызовов Linux. В дистрибутиве Asterinas NixOS верифицирована работа поверх ядра Asterinas более[100 пакетов](https://asterinas.github.io/book/distro/popular-applications/index.html)из NixOS. Среди поддерживаемых пакетов: Xfce, Firefox, bash, systemd, Podman, QEMU, rsync, Apache httpd, nginx, SQLite, Redis, Clang, GCC, Go, Lua, Node.js, OpenJDK, Perl, PHP, Python, Ruby, Rust, Git, FFmpeg, PyTorch, TensorFlow, Ollama и Codex.

В ядре обеспечена полная поддержка архитектуры x86-64, частичная поддержка ARM64, RISC-V 64 и x86-64 с изоляцией на базе Intel TDX, а также начальная поддержка архитектуры LoongArch 64. Из приоритетных областей применения называются системы, завязанные на Linux ABI, но требующие более высокого уровня защищённости. Например, Asterinas предлагается использовать для формирования системного окружения защищённых виртуальных машин, для изоляции которых используются такие технологии, как ARM CCA, AMD SEV и Intel TDX, а также на стороне хост-системы, обеспечивающей запуск контейнеров.

Для снижения вероятности появления ошибок при работе с памятью, являющихся главным источником наиболее опасных уязвимостей, при написании Asterinas задействован язык Rust и тактика ограниченного использования unsafe-блоков. Ядро построено с использованием архитектуры[framekernel](https://asterinas.github.io/book/kernel/the-framekernel-architecture.html), в которой попытались совместить возможности изоляции микроядер с эффективностью монолитных ядер.

Компоненты ядра в Asterinas размещаются в общем адресном пространстве, а безопасность достигается на уровне логического разделения безопасного кода и кода, в котором не исключено возникновение проблем с безопасностью. Ядро разбито на две части, написанные на Rust: OS Framework и OS Services. В OS Services запрещено применение unsafe-блоков, а все низкоуровневые операции, требующие выполнения кода в блоках unsafe, вынесены в OS Framework и доступны только через высокоуровневый API. Все системные вызовы, файловые системы и драйверы реализуются на уровне OS Services и не могут включать unsafe-блоки.

Для разработки системных сервисов и модулей ядра поставляется инструментарий[OSDK](https://asterinas.github.io/book/osdk/guide/)(Operating System Development Kit), предоставляющий утилиту cargo-osdk для создания, сборки, тестирования и запуска компонентов операционной системы. Для разработчиков подготовлен набор библиотек[OSTD](https://asterinas.github.io/book/ostd/)(Operating System Standard Library), включающий редакцию стандартных библиотек Rust (crate std), адаптированную для использования в компонентах операционной системы.

Среди изменений в Asterinas 0.19:

- Реализована подсистема DRM (Direct Rendering Manager), устройство /dev/dri, интерфейс KMS (kernel mode setting) и драйвер "modesetting", позволившие запустить штатный графический стек на базе X.Org Server и Mesa, вместо ранее применявшегося драйвера fbdev, использующего фреймбуфер.
- Добавлена поддержка архитектуры AArch64 (ARM64), которая теперь используется в качестве основной архитектуры при разработке, наряду с x86-64. Для AArch64 реализован второй уровень поддержки, подразумевающий работоспособность базовой функциональности, проверку в системе непрерывной интеграции и частичный охват тестами.
- Продолжена работа по адаптации Asterinas для запуска в качестве гостевой системы в VM-контейнерах[Kata Containers](https://www.opennet.ru/opennews/art.shtml?num=61039)и[Confidential Containers](https://confidentialcontainers.org/). Предложена новая реализация Overlayfs, успешно проходящая стандартные тестовые наборы ФС ядра Linux и xfstests. Реализован новый API монтирования. Стабилизирован код virtio-fs. Добавлена поддержка протокола direct-boot, используемого в QEMU, Cloud Hypervisor и Firecracker. Ускорена загрузка в виртуальных машинах, память которых шифруется при помощи технологии Intel TDX.
- Во фреймворке OSTD (Operating System Standard Library) реализован базовый API для создания минималистичных гипервизоров на базе Intel VMX.
- Добавлена поддержка модели разработки драйверов на языке Rust. Добавлен компонент aster-device с функциональностью, напоминающей компоненты ядра Linux c базовыми примитивами и абстракциями для разработки драйверов, но написанный на Rust без unsafe-кода.
- Обеспечена возможность собственной пересборки (self-hosting) - из окружения с ядром Asterinas и пакетами NixOS теперь можно собрать ядро Asterinas.
