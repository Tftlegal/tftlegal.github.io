**GNU utils** (чаще всего имеются в виду **GNU Coreutils**, а также смежные пакеты GNU) — это набор базовых утилит командной строки для работы с файлами, текстом и системой в Unix-подобных операционных системах. 

Это фундамент, на котором строится работа в терминале Linux и многих других систем.

### 📜 Краткая история и цель
Проект GNU был основан Ричардом Столлманом в 1983 году с целью создания полностью свободной операционной системы, совместимой с UNIX. Поскольку оригинальные утилиты UNIX были проприетарными, команда GNU написала свои собственные, свободные (open-source) аналоги с нуля. Так появились GNU utils.

### 🛠 Что входит в GNU utils?
Строго говоря, пакет **GNU Coreutils** объединяет в себе три старых пакета: `fileutils`, `shellutils` и `textutils`. Вот самые известные примеры:

1. **Работа с файлами и директориями**:  
   `ls` (список файлов), `cp` (копирование), `mv` (перемещение), `rm` (удаление), `mkdir` (создание директории), `touch` (изменение времени файла), `chmod`/`chown` (права доступа).
2. **Работа с текстом и потоками**:  
   `cat` (вывод содержимого), `echo` (вывод текста), `head`/`tail` (начало/конец файла), `sort` (сортировка), `uniq` (удаление дубликатов), `wc` (подсчет слов/строк).
3. **Системные и вспомогательные**:  
   `date` (дата и время), `sleep` (задержка), `pwd` (текущая директория), `dd` (побайтовое копирование).

*Помимо Coreutils, под "GNU utils" часто подразумевают и другие базовые пакеты GNU:*  
- **GNU findutils**: `find`, `locate`, `xargs` (именно их вы использовали в предыдущем примере).
- **GNU tar**: утилита для архивации (`tar`), которая поддерживает такие специфичные опции, как `--remove-files`.
- **GNU grep, sed, awk**: мощные инструменты для поиска и обработки текста.

### ⭐ Ключевые особенности GNU-утилит (в отличие от классических UNIX/BSD)
1. **Длинные опции (long options)**: GNU-утилиты поддерживают удобочитаемые флаги с двумя дефисами, например, `--help`, `--verbose`, `--remove-files`. Классические UNIX-утилиты обычно поддерживают только короткие флаги (например, `-v`, `-h`).
2. **Расширенный функционал**: GNU-версии часто имеют больше возможностей. Например, GNU `cp` имеет опцию `--preserve=all`, а GNU `ls` умеет раскрашивать вывод (`--color=auto`).
3. **Строгая совместимость и предсказуемость**: Они ведут себя одинаково на любом дистрибутиве Linux, что делает скрипты (bash-скрипты, Ansible-плейбуки) переносимыми.

### 💻 Где они используются?
- **Linux**: Абсолютно во всех дистрибутивах (Ubuntu, CentOS, Debian, Arch и др.) GNU Coreutils являются стандартом по умолчанию.
- **macOS**: По умолчанию использует утилиты BSD (например, `ls` или `date` там ведут себя немного иначе). Но разработчики часто устанавливают GNU-версии через Homebrew (`brew install coreutils`), чтобы получить привычный функционал и длинные опции.
- **Windows**: Доступны через подсистему WSL (Windows Subsystem for Linux), а также через среды совместимости, такие как Cygwin или MSYS2.

### 🔗 Команда:
```bash

```
Является классическим примером **силы GNU utils**:  
- `find` (из GNU findutils) умеет безопасно передавать данные через `-print0`.  
- `tar` (GNU tar) понимает `--null`, `-T -` и `--remove-files`, что позволяет элегантно решить задачу архивации с удалением в одном конвейере (pipe), не прибегая к сложным циклам `bash`.

Посчитаем, сколько дней прошло с 01.01.2023 до сегодня (31.07.2026), и используем это в `find` через модуль `shell`.

### Расчёт дней

С 01.01.2023 по 31.07.2026:

- 2023: весь год → 365 дней  
- 2024: високосный → 366 дней  
- 2025: 365 дней  
- 2026: с 01.01 по 31.07 → 31 (янв) + 28 (фев) + 31 (мар) + 30 (апр) + 31 (май) + 30 (июн) + 31 (июл) = 212 дней  

Итого:  
365 + 366 + 365 + 212 = **1308 дней**

То есть с 01.01.2023 прошло примерно 1308 дней.

### Плейбук (через `shell` + `find` по времени изменения)

Если использовать стандартный `mtime` (дней):

```yaml
---
- name: Delete files in /opt/test_files older than 2023-01-01
  hosts: all
  become: yes

  vars:
    # количество дней с 01.01.2023 по текущую дату (31.07.2026)
    days_since_2023_01_01: 1308

  tasks:
    - name: Ensure target directory exists
      ansible.builtin.file:
        path: /opt/test_files
        state: directory

    - name: Delete files older than 2023-01-01
      ansible.builtin.shell: |
        find /opt/test_files -type f -mtime +{{ days_since_2023_01_01 }} -delete
      args:
        warn: false
      register: rm_result
      changed_when: rm_result.stdout | length > 0 or rm_result.rc == 0
```

Это удаляет файлы, у которых `mtime` больше чем 1308 дней назад, то есть изменённые до 01.01.2023.

### Вариант с `-printf '%B@'` и точной датой

Если хотите именно сравнение по timestamp (включая birth time, если ФС его поддерживает), можно так:

```yaml
---
- name: Delete files in /opt/test_files with mtime before 2023-01-01
  hosts: all
  become: yes

  tasks:
    - name: Ensure target directory exists
      ansible.builtin.file:
        path: /opt/test_files
        state: directory

    - name: Find and remove files with mtime before 2023-01-01
      ansible.builtin.shell: |
        find /opt/test_files -type f -printf '%B@ %p\n' |
        while read -r ts path; do
          if [ "$(echo "$ts" | cut -d. -f1)" -lt 1672531200 ]; then
            rm -f "$path"
          fi
        done
      args:
        warn: false
      register: rm_result
      changed_when: rm_result.rc == 0
```

Где:

- `1672531200` — Unix‑timestamp для `2023-01-01 00:00:00 UTC`.
- `%B@` выводит время изменения (mtime) в секундах с начала эпохи.
- Скрипт удаляет файлы, у которых mtime < 2023-01-01.

Если вам нужен именно простой и надёжный вариант — используйте первый плейбук с `-mtime +1308`.

### Важные замечания

1. **Дата создания vs дата изменения**  
   На большинстве Linux-файловых систем (ext4, xfs) «дата создания» (birth time) либо не хранится, либо плохо доступна из стандартных инструментов. Ansible модуль `find` фильтрует по:
   - `age` + `age_stamp` (mtime, ctime, atime).  

   Поэтому на практике используют **mtime** (время последнего изменения). Если вам критична именно birth time, потребуется кастомный скрипт (например, через `stat` + `debug` или `find` с `-printf '%B@'`), но это уже сложнее и менее переносимо.

2. **Точная дата 01.01.2023**

Проблема в том, что при использовании `>-` весь многострочный текст схлопывается в одну строку, и Python получает некорректный код (`import os from datetime import datetime` и т.д.).

Нужно передать Python‑скрипт как **многострочный** через `|` и отдельный файл или использовать `script`, но проще всего — записать скрипт в `/tmp` и выполнить его.

Вот надёжный вариант: создаём временный Python‑скрипт через `copy` и запускаем его через `shell`.

```yaml
---
- name: Удаление файлов, созданных до 2023-01-01 (используя Python)
  hosts: your_target_hosts
  become: true

  vars:
    cutoff_date: "2023-01-01 00:00:00"
    script_path: /tmp/cleanup_old_files.py

  tasks:
    - name: Создать Python-скрипт для удаления старых файлов
      ansible.builtin.copy:
        dest: "{{ script_path }}"
        mode: '0755'
        content: |
          #!/usr/bin/env python3
          import os
          from datetime import datetime

          target_dir = "/opt/test_files"
          cutoff_time = datetime.strptime("{{ cutoff_date }}", "%Y-%m-%d %H:%M:%S").timestamp()

          for filename in os.listdir(target_dir):
              filepath = os.path.join(target_dir, filename)
              if os.path.isfile(filepath):
                  try:
                      # На Linux st_ctime — это change time, используем как аппроксимацию
                      creation_time = os.stat(filepath).st_ctime

                      if creation_time < cutoff_time:
                          print("DELETING: " + filepath)
                          os.remove(filepath)
                  except Exception as e:
                      print("ERROR processing " + filepath + ": " + str(e))
      register: script_deploy

    - name: Удалить файлы, созданные до cutoff_date
      ansible.builtin.shell: "{{ script_path }}"
      args:
        _uses_shell: true
      register: cleanup_output
      changed_when: cleanup_output.stdout | length > 0

    - name: Вывод результатов
      ansible.builtin.debug:
        var: cleanup_output.stdout_lines
```

Что здесь исправлено:

- Python‑код теперь лежит в отдельном файле, который Ansible создаёт через `copy` с `content: |`. Это гарантирует корректные переносы строк и отступы.
- `shell` просто вызывает скрипт: `{{ script_path }}`.
- Ошибки синтаксиса Python больше не возникают из‑за схлопывания строк YAML.

Теперь видно, почему Python‑скрипт ничего не удалил:

- `Modify: 2015-09-13` — файл изменён в 2015 году (до 2023‑01‑01).
- `Change: 2026-07-30` — метаданные менялись сегодня (например, когда вы его копировали/создавали заново).
- `Birth: 2024-07-09` — дата создания (birth time) тоже **после** 2023‑01‑01.

Ваш скрипт использовал:

```python
creation_time = os.stat(filepath).st_ctime  # это Change, а не Birth
```

`st_ctime` = 2026‑07‑30 > 2023‑01‑01 → условие `creation_time < cutoff_time` ложно → файл не удаляется.


При этом `find ! -newermt "2023-01-01"` использует **mtime** (Modify), который 2015 год, поэтому файл попадает в выборку.


## Как исправить Python‑скрипт

Если цель — удалять файлы по **mtime** (как `find ! -newermt`), нужно использовать `st_mtime`:

```python
creation_time = os.stat(filepath).st_mtime
```

Исправленный плейбук:

```yaml
---
- name: Удаление файлов с mtime до 2023-01-01 (используя Python)
  hosts: your_target_hosts
  become: true

  vars:
    cutoff_date: "2023-01-01 00:00:00"
    script_path: /tmp/cleanup_old_files.py

      ansible.builtin.copy:
        dest: "{{ script_path }}"
        mode: '0755'
        content: |
          #!/usr/bin/env python3
          import os
          from datetime import datetime

          target_dir = "/opt/test_files"
          cutoff_time = datetime.strptime("{{ cutoff_date }}", "%Y-%m-%d %H:%M:%S").timestamp()

          for filename in os.listdir(target_dir):
              filepath = os.path.join(target_dir, filename)
              if os.path.isfile(filepath):
                  try:
                      # Используем mtime (Modify), как find ! -newermt
                      mtime = os.stat(filepath).st_mtime

                      if mtime < cutoff_time:
```

Теперь:
