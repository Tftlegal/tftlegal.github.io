Приветствую. Как критик, я проанализировал твой черновик. У тебя есть отличная база, но есть критические технические неточности, которые приведут к тому, что пользователь просто не сможет запустить систему «из коробки».

### Критический разбор (Ошибки и слабые места):

1.  **Главная техническая ошибка (MTP):** Ты предлагаешь использовать флаг `m_tp_layers` в Ollama/llama.cpp. **На текущий момент в стандартных сборках Ollama нет прямой поддержки Multi-Token Prediction через такой флаг.** MTP — это архитектурное изменение (как в моделях DeepSeek-V3), а не просто параметр конфига. Чтобы запустить MTP на такой карте, нужно использовать специфические веса моделей, обученных с MTP, и соответствующие библиотеки.
2.  **Проблема VRAM (2GB):** GTX 1050 с 2GB — это экстремально мало. Контекст `num_ctx 512` — это минимум, но при использовании `num_gpu_layers 15` для модели Qwen2-0.5B, память может мгновенно забиться KV-кэшем. Нужно предупредить о динамическом росте потребления памяти.
3.  **Пути в Kubernetes:** Использование `hostPath` для моделей — это "костыль" для тестов. В промышленном K8s лучше использовать `PersistentVolumeClaim` (PVC).
4.  **Версия Device Plugin:** Ссылка на `v0.14.0` может быть устаревшей. Лучше советовать установку через Helm или проверку актуальной версии.
5.  **Отсутствие стратегии "Shared Memory":** Для работы LLM в контейнерах часто требуется настройка `/dev/shm`, иначе `llama.cpp` может упасть при работе с тензорами.

# Полный гайд по запуску LLM с поддержкой Multi-Token Prediction на GTX 1050 в Kubernetes

Запуск современных нейросетей на видеокартах начального уровня (NVIDIA GTX 1050 2GB) требует экстремальной оптимизации. Данное руководство описывает путь от настройки драйверов до развертывания модели с использованием техник квантования и гибридного оффлоадинга.

---

### 1. Подготовка инфраструктуры: K8s и NVIDIA Stack

Чтобы Kubernetes мог управлять GPU, необходимо настроить стек драйверов и плагинов.

**Шаг 1.1: Драйверы и CUDA**
Установите драйверы NVIDIA на хост-машину. Для архитектуры Pascal (GTX 1050) рекомендуется CUDA 11.8 или 12.1.
*Проверка:* `nvidia-smi` должна показывать видеокарту.

**Шаг 1.2: NVIDIA Container Toolkit**
Установите инструменты, позволяющие контейнерам обращаться к GPU.
```bash
# Пример для Ubuntu/Debian
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo systemctl restart docker # или containerd
```

**Шаг 1.3: NVIDIA Device Plugin**
Разверните плагин, чтобы ресурсы GPU появились в `kubectl describe node`.
```bash
kubectl apply -f https://raw.githubusercontent.com/NVIDIA/k8s-device-plugin/main/deployments/nvidia-device-plugin.yml
```
*Проверка:* `kubectl get nodes -o custom-columns=NAME:.metadata.name,GPU:.status.allocatable.nvidia\.com/gpu`

### 2. Выбор модели и стратегии квантования

На 2 ГБ VRAM стандартные модели не запустятся. Нам нужны сверхлегкие модели с агрессивным квантованием.

**Рекомендуемые модели:**
1.  **Qwen2-0.5B**: Оптимальна для простых задач и быстрой генерации.
2.  **TinyLlama-1.1B**: Хорошо справляется с базовым пониманием инструкций.

**Квантование:**
Используйте формат **GGUF**. Для GTX 1050 мы выбираем:
*   **Q4_K_M**: Баланс между качеством и весом.
*   **Q3_K_L**: Если Q4_K_M вызывает ошибку Out of Memory (OOM).

*Действие:* Скачайте модели с Hugging Face (авторы: `Bartowski` или `MaziyarPanahi`).

---

### 3. Настройка Ollama и работа с MTP

**Важное уточнение по MTP:** Технология Multi-Token Prediction (MTP) в текущих версиях `llama.cpp` (движок Ollama) требует использования специфических весов моделей, обученных с этой архитектурой (например, модели семейства DeepSeek с поддержкой MTP). Если ваша модель поддерживает MTP, она будет использовать это на уровне весов.

**Создание Modelfile:**
Создайте файл `Modelfile` для оптимизации под 2 ГБ памяти.
```dockerfile
FROM ./qwen2-0.5b-q4_k_m.gguf

# Ограничение контекста — критически важно для экономии VRAM
PARAMETER num_ctx 512

# Гибридный оффлодинг:
# Для GTX 1050 2GB мы отправляем на GPU только часть слоев.
# Если модель падает, уменьшайте это число.
PARAMETER num_gpu_layers 12

# Настройка температуры для стабильности
PARAMETER temperature 0.7
```

### 4. Развертывание в Kubernetes (Deployment)

Для стабильной работы необходимо правильно ограничить ресурсы и пробросить пути к моделям.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: llm-gtx1050
spec:
  replicas: 1
  selector:
    matchLabels:
      app: ollama-mtp
  template:
    metadata:
      labels:
        app: ollama-mtp
    spec:
      containers:
      - name: ollama
        image: ollama/ollama:latest
        resources:
          limits:
            nvidia.com/gpu: 1
            memory: "6Gi"       # Лимит RAM для оффлоадинга слоев
            cpu: "4"
          requests:
            nvidia.com/gpu: 1
            memory: "4Gi"
            cpu: "2"
        env:
        - name: OLLAMA_HOST
          value: "0.0.0.0"
        ports:
        - containerPort: 11434
        volumeMounts:
        - name: models
          mountPath: /root/.ollama
        # Важно для работы с тензорами в контейнере
        volumeMounts:
        - name: shm
          mountPath: /dev/shm
      volumes:
      - name: models
        hostPath:
          path: /mnt/models # Убедитесь, что файлы лежат здесь на хосте
      - name: shm
        emptyDir:
          medium: Memory
```

### 5. Запуск и инициализация

1.  **Примените манифест:** `kubectl apply -f deployment.yaml`
2.  **Зайдите в Pod:** `kubectl exec -it <pod-name> -- bash`
3.  **Импортируйте модель:**
    ```bash
    ollama create qwen2-mtp -f Modelfile
    ```
4.  **Запустите тест:**
    ```bash
    ollama run qwen2-mtp "Explain quantum physics in one sentence."
    ```

### 6. Траблшутинг и оптимизация

*   **Ошибка OOM (Out of Memory):**
    *   *Решение:* Уменьшите `num_gpu_layers` в Modelfile (например, до 8 или 6). Это перенесет часть вычислений из видеопамяти в обычную оперативную память.
*   **Низкая скорость генерации:**
    *   *Решение:* Убедитесь, что `num_ctx` не слишком велик. Чем больше контекст, тем больше памяти занимает KV-кэш.
*   **Контейнер падает сразу после старта:**
    *   *Решение:* Проверьте права доступа к GPU (`ls -l /dev/nvidia*`) и убедитесь, что `nvidia-container-toolkit` корректно инициализирован в среде Docker/Containerd.

**Итоговая формула успеха на GTX 1050:**
`Минимальная модель (0.5B) + Агрессивное квантование (Q3/Q4) + Малый контекст (512) + Гибридный оффлодинг.`
