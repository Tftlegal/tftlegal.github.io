# Профессиональное руководство по восстановлению данных на Linux

Данное руководство предназначено для системных администраторов и специалистов по кибербезопасности. **Внимание:** Работа с поврежденными носителями требует предельной осторожности. Ошибка может привести к безвозвратной потере данных.

## ⚠️ Золотые правила безопасности
1. **Никогда не монтируйте поврежденный раздел.** Монтирование вызывает запись метаданных, что может перезаписать удаленные файлы.
2. **Работайте только с образом.** Все операции по восстановлению проводятся на копии диска, а не на исходном физическом устройстве.
3. **Целевой носитель.** Данные, извлекаемые из образа, должны записываться на абсолютно другой физический диск.

---

## Этап 1: Создание образа диска (Imaging)

Прежде чем приступать к анализу, необходимо создать побитовую копию носителя. Это защитит оригинальный диск от дальнейшего износа при попытках чтения.

### Инструментарий:
*   `dd`: Классическая утилита для побитового копирования.
*   `ddrescue`: Продвинутый инструмент, который умеет обходить битые сектора и повторно читать проблемные области.

### Инструкция по созданию образа:

**Вариант А: Использование `dd` (для исправных дисков)**
```bash
# Пример: Копирование диска /dev/sdb в файл image.dd на другой диск
sudo dd if=/dev/sdb conv=noerror,sync bs=64K status=progress | gzip > /path/to/external_drive/disk_image.img.gz
```
*Параметры:* `conv=noerror,sync` позволяет игнорировать ошибки чтения, сохраняя структуру блоков.

**Вариант Б: Использование `ddrescue` (для дисков с битыми секторами)**
*Рекомендуется для физически поврежденных носителей.*
```bash
# Сначала создаем файл-лог (mapfile), чтобы сохранить прогресс
sudo ddrescue -d -n /dev/sdb /path/to/external_drive/disk_image.dd /path/to/external_drive/recovery.log

# Затем запускаем повторную попытку чтения битых секторов (более агрессивно)
sudo ddrescue -d -r3 /dev/sdb /path/to/external_drive/disk_image.dd /path/to/external_drive/recovery.log
```
*Важно:* Никогда не используйте `/dev/null` как путь вывода, если ваша цель — сохранить данные.

## Этап 2: Анализ типа повреждений

Определите характер проблемы перед выбором инструмента:

1.  **Логическое удаление:** Файловая система цела, но записи в таблице файлов удалены (например, `rm` или форматирование).
    *   *Инструменты:* `extundelete`, `TestDisk`.
2.  **Коррупция файловой системы:** Повреждены суперблоки, иноды или структура директорий.
    *   *Инструменты:* `TestDisk` (восстановление таблицы разделов/структуры).
3.  **Физическое повреждение / Полная деградация:** Диск не читается, структура файловой системы уничтожена.
    *   *Инструменты:* `PhotoRec` (поиск файлов по сигнатурам — "Carving").

## Этап 3: Процесс восстановления

### Сценарий 1: Восстановление структуры (TestDisk)
Используйте, если раздел исчез или файловая система повреждена.
1. Запустите: `sudo testdisk /path/to/disk_image.dd`
2. Выберите тип таблицы разделов (обычно GPT или MBR).
3. Используйте функцию *Analyse* и *Quick Search*.
4. Если файлы видны, используйте функцию *Copy* для их извлечения.

### Сценарий 2: Восстановление удаленных файлов (extundelete)
Используйте для файловых систем ext3/ext4 при случайном удалении.
```bash
# Восстановление всех файлов в папке /home/user/data
sudo extundelete /path/to/disk_image.dd --restore-all
```

### Сценарий 3: Глубокое сканирование (PhotoRec)
Используйте, если файловая система полностью уничтожена (Raw Data Recovery).
1. Запустите: `sudo photorec /path/to/disk_image.dd`
2. Выберите тип файловой системы.
3. Укажите путь для сохранения файлов (на **другой** диск!).
4. Программа начнет поиск файлов по их заголовкам (JPEG, PDF, DOCX и т.д.).

## Этап 4: Проверка и верификация

После извлечения данных необходимо убедиться в их целостности.

1.  **Контрольные суммы:** Если у вас есть исходные хеш-суммы (MD5/SHA256), сверьте их с восстановленными файлами.
2.  **Визуальная проверка:** Проверьте случайную выборку файлов на открываемость и корректность отображения.
3.  **Изоляция:** Всегда проверяйте восстановленные данные в изолированной среде (песочнице), если есть подозрение на вирусное заражение или повреждение системных файлов.


## Чек-лист критических ошибок (Do Not Do!)

| Действие | Почему это плохо | Правильное действие |
| :--- | :--- | :--- |
| **Монтирование диска** | Перезапись метаданных и данных | Работайте только с образом (`.dd`, `.img`) |
| **Запись на исходный диск** | Необратимая потеря данных | Всегда используйте внешний носитель для сохранения |
| **Использование `dd` без `conv=noerror`** | Процесс прервется на первом битом секторе | Используйте `ddrescue` для поврежденных дисков |
| **Восстановление "на месте"** | Риск перезаписи данных | Извлекайте файлы в отдельную директорию |

## 1. Проверьте структуру диска

```bash
lsblk -o NAME,SIZE,FSTYPE,FSVER,LABEL,UUID,MOUNTPOINTS,MODEL /dev/sdb
fdisk -l /dev/sdb
blkid /dev/sdb*
```

Важно: `/dev/sdb` — это весь диск. Монтировать обычно нужно раздел, например `/dev/sdb1`, `/dev/sdb2`, а не `/dev/sdb`.

Если диск определяется нестабильно, медленно или есть ошибки I/O:

```bash
dmesg -T | grep -iE 'sda|ata|error|fail|reset|uncorrect' | tail -50
```

## 2. Если диск исправен — попробовать чтение:

Например, если `lsblk` покажет NTFS на `/dev/sdb2`:

```bash
mkdir -p /mnt/recovery
mount -t ntfs3 -o ro /dev/sdb2 /mnt/recovery
```

Для ext4:

```bash
mount -t ext4 -o ro,noload /dev/sdb2 /mnt/recovery
```

Для XFS:

```bash
mount -t xfs -o ro,norecovery /dev/sdb2 /mnt/recovery
```

После монтирования копируйте данные на **другой диск**:

```bash
rsync -aHAX --info=progress2 /mnt/recovery/ /mnt/pbs/recovered/
```

| Параметр | Значение |

| Объём | 232.9 GiB (250,059,350,016 байт) |

PhotoRec игнорирует файловую систему и работает напрямую с данными на диске, что позволяет восстанавливать файлы даже с серьёзно повреждённых или отформатированных носителей.

## 2. Подготовка к восстановлению

### 2.1. Создание образа диска (рекомендовано)

Прямая работа с физическим диском сопряжена с рисками. **Настоятельно рекомендуется** сначала создать посекторную копию:

```bash
sudo dd if=/dev/sdb of=/mnt/pbs/232G/sdb.img bs=4M status=progress
```

> **Важно:** образ должен сохраняться на **другом** физическом носителе, не на `/dev/sdb`.

### 2.2. Проверка целостности образа (опционально)

```bash
sudo sha256sum /dev/sdb /mnt/pbs/232G/sdb.img
```

Контрольные суммы должны совпадать — это подтверждает корректность создания образа.

### 2.3. Установка PhotoRec

```bash
# Debian/Ubuntu
sudo apt update && sudo apt install testdisk -y

# RHEL/CentOS/Fedora
sudo dnf install testdisk -y

# Arch Linux
sudo pacman -S testdisk
```

## 3. Запуск PhotoRec

### 3.1. Синтаксис команды

Общий синтаксис PhotoRec:

```
photorec [/log] [/debug] [/d каталог_восстановления] [устройство|образ.dd|образ.e01]
```

### 3.2. Рекомендуемая команда

Исходя из вашей среды (каталог `/mnt/pbs` существует, образ расположен по пути `/mnt/pbs/232G/sdb.img`):

```bash
sudo photorec /log /d /mnt/pbs/recovered /mnt/pbs/232G/sdb.img
```

**Пояснение параметров**:

| Параметр | Назначение |
|----------|------------|
| `/log` | Создаёт файл `photorec.log` в текущей рабочей директории с деталями восстановления |
| `/d /mnt/pbs/recovered` | Указывает каталог для сохранения восстановленных файлов |
| `/mnt/pbs/232G/sdb.img` | Путь к образу диска (или устройству) для сканирования |

### 3.3. Важные предостережения

1. **Никогда не сохраняйте восстановленные файлы на восстанавливаемый диск**. В вашем случае образ и результаты разделены — это правильно.
2. **Запускайте с правами root** (`sudo`).
3. PhotoRec **не пытается записывать данные на восстанавливаемый носитель** — это безопасный инструмент.

## 4. Интерактивный процесс

После запуска PhotoRec переходит в интерактивный режим:

### 4.1. Выбор диска/образа
- Если вы работаете с образом (`sdb.img`), PhotoRec автоматически определит его.
- При работе с физическим диском будет предложен выбор из списка доступных устройств.

### 4.2. Выбор типа таблицы разделов
- Для GPT-диска (как в вашем случае) выберите **[Intel]** (для MBR) или **[EFI GPT]** — PhotoRec определит автоматически.

### 4.3. Выбор раздела для анализа
- Если таблица разделов повреждена, выберите **`[Whole disk]`** для сканирования всего диска.
- Если известен конкретный раздел — выберите его.

### 4.4. Выбор файловой системы
- PhotoRec поддерживает:
  - **ext2/ext3/ext4** — для Linux
  - **FAT/NTFS** — для Windows
  - **HFS+** — для macOS
  - **None** — если файловая система не определена
- В вашем случае, поскольку FSTYPE отсутствует, выберите **`[Other]`** или **`[None]`**.

### 4.5. Выбор места сохранения
- Укажите каталог, переданный через параметр `/d` (`/mnt/pbs/recovered`).
- **Важно:** этот каталог должен находиться на другом диске.

### 4.6. Выбор типов файлов
- PhotoRec распознаёт **более 480 форматов файлов**.
- Можно оставить все типы (`[File Opt]` → `[Enable all]`) или выбрать конкретные расширения.

### 4.7. Запуск сканирования
- Подтвердите выбор и дождитесь завершения.
- Время сканирования зависит от размера диска и скорости чтения.


### 5.2. Особенности восстановленных файлов

| Характеристика | Описание |
|----------------|----------|
| **Имена файлов** | **Не сохраняются**. Файлы именуются по порядку обнаружения (например, `f123456789.jpg`) |
| **Структура каталогов** | **Не сохраняется**. Все файлы группируются по каталогам `recup_dir.N` |
| **Типы файлов** | Определяются по сигнатурам (заголовкам) и получают соответствующее расширение |
| **Метаданные** | Частично теряются (дата создания, права доступа и т.д.) |

### 5.3. Анализ лог-файла

Файл `photorec.log` содержит информацию о местоположении восстановленных файлов на диске. Это может помочь при последующей сортировке.

## 6. Постобработка восстановленных данных

### 6.1. Сортировка по типу

```bash
# Собрать все файлы определённого типа в один каталог
find /mnt/pbs/recovered -name "*.jpg" -exec cp {} /mnt/pbs/sorted/jpg/ \;
```

### 6.2. Восстановление имён через метаданные (для JPEG)

```bash
exiftool '-Filename<DateTimeOriginal' -d "%Y%m%d_%H%M%S%%-c.%%e" /mnt/pbs/recovered/*.jpg
```

## 7. Альтернативные подходы

### 7.1. Восстановление таблицы разделов через TestDisk

Если файловая система была повреждена, но структура разделов сохранилась:

```bash
sudo testdisk /dev/sdb
```

TestDisk может восстановить таблицу разделов и, в некоторых случаях, вернуть доступ к файловой системе.

### 7.2. Сканирование только свободного пространства

Для ускорения работы (если не требуется восстанавливать существующие файлы):

```bash
sudo photorec /cmd /dev/sdb fileopt,everything,disable,jpg,enable,freespace,search
```

Этот пример восстанавливает только JPG из свободного пространства.

### 7.3. Пакетный режим (scripted run)

Для автоматизации без интерактивного ввода:

```bash
sudo photorec /log /d /mnt/pbs/recovered /cmd /mnt/pbs/232G/sdb.img options,mode_ext2,search
```

## 9. Заключение

Восстановление данных с диска `/dev/sdb` возможно исключительно методом файлового карвинга через PhotoRec, так как файловая система не распознаётся. Рекомендованная команда:

```bash
sudo photorec /log /d /mnt/pbs/recovered /mnt/pbs/232G/sdb.img
```

**Ключевые ограничения**, о которых следует помнить:
- Исходные имена файлов и структура каталогов **не сохраняются**
- Восстановление занимает продолжительное время (зависит от размера диска)
- Часть данных может быть невосстановима из-за фрагментации или перезаписи

После завершения работы PhotoRec рекомендуется проанализировать лог и выполнить сортировку полученных файлов для упорядочивания результатов.
