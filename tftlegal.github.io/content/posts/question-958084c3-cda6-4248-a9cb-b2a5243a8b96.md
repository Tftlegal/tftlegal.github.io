Приветствую. Как критик, я проанализировал ваш черновик. Скажу прямо: в текущем виде этот гайд — **инструкция к катастрофе**. Он содержит критические технические ошибки, которые не позволят запустить модель даже на мощном сервере, не говоря уже о бюджетной GTX 1050.

### Основные ошибки и критические замечания:

1.  **Аппаратный тупик (VRAM):** GTX 1050 имеет 2 ГБ VRAM. Современные библиотеки инференса (vLLM, TGI) требуют минимум 4-8 ГБ только для загрузки весов и KV-кэша. Использование vLLM на такой карте невозможно. Нужно использовать `llama.cpp` (GGUF) с поддержкой GPU-ускорения (CUDA).
2.  **Архитектурная ошибка (MTP):** Multi-Token Prediction — это специфическая архитектура (как в модели Mamba или специализированных версиях GPT). Вы не можете просто включить `model.config.mtp` в стандартной библиотеке `transformers` для TinyLlama. Это требует специфических весов и кода.
3.  **Версии ПО:** Указание CUDA 11.0 и старых драйверов для современных библиотек PyTorch — путь к конфликтам зависимостей.
4.  **Kubernetes ресурсы:** Запрос `nvidia.com/gpu: 0.25` не работает так. В стандартном NVIDIA Device Plugin GPU выделяются целыми единицами (`1`). Для дробления (fractional GPU) нужны специальные плагины (например, NVIDIA MPS или Time-Slicing).
5.  **Безопасность и логика:** Использование `docker build` без указания контекста и `run.py` без описания логики API (FastAPI/Flask) делает гайд бесполезным.

### Исправленная и расширенная версия гайда

Ниже представлена технически корректная версия. Мы заменим vLLM на **llama.cpp**, так как это единственный способ запустить LLM на 2 ГБ VRAM с использованием CUDA.

# Полный гайд: Развертывание LLM с поддержкой MTP на GTX 1050 в Kubernetes

Этот гайд описывает процесс развертывания сверхлегкой модели (TinyLlama) с использованием квантования и оптимизаций для работы на видеокарте с крайне малым объемом памяти (2 ГБ VRAM).

## Шаг 1: Анализ ограничений и выбор стека
*   **GPU:** NVIDIA GTX 1050 (2 GB VRAM).
*   **Проблема:** Стандартные методы инференса (vLLM) не запустятся из-за нехватки памяти под KV-кэш.
*   **Решение:**
    *   **Модель:** TinyLlama-1.1B или Qwen-0.5B.
    *   **Формат:** GGUF (квантование Q4_K_M или Q5_K_M).
    *   **Движок:** `llama.cpp` (поддерживает CUDA и позволяет эффективно распределять слои между CPU и GPU).
    *   **MTP:** Использование моделей с поддержкой Multi-Token Prediction (например, специализированные веса, если доступны, иначе — стандартный авторегрессионный инференс с высокой скоростью).

## Шаг 2: Подготовка хостовой машины
Для работы Kubernetes с GPU необходим корректный стек драйверов:
1.  **NVIDIA Driver:** Установите версию 525+ (рекомендуется для совместимости с CUDA 12.x).
2.  **NVIDIA Container Toolkit:** Обязателен для проброса GPU в контейнеры.
    ```bash
    # Пример для Ubuntu
    sudo apt-get install -y nvidia-container-toolkit
    sudo systemctl restart docker # или containerd
    ```
3.  **NVIDIA Device Plugin:** Установите в кластер для регистрации GPU.

## Шаг 3: Подготовка образа (Dockerfile)
Мы будем использовать `llama.cpp`, так как он позволяет "выгружать" часть слоев в системную память, если VRAM закончится.

```dockerfile
# Используем официальный образ с поддержкой CUDA
FROM nvidia/cuda:12.1.0-runtime-ubuntu22.04

# Установка зависимостей
RUN apt-get update && apt-get install -y \
    python3-pip \
    git \
    && rm -rf /var/lib/apt/lists/*

# Клонируем и собираем llama.cpp с поддержкой CUDA
RUN git clone https://github.com/ggerganov/llama.cpp && \
    cd llama.cpp && \
    make LLAMA_CUDA=1

# Установка зависимостей для API
RUN pip3 install fastapi uvicorn

# Копируем бинарные файлы и скрипт запуска
COPY --from=0 /llama.cpp/build/bin/llama-server /app/llama-server
COPY ./models /app/models
COPY server.py /app/server.py

WORKDIR /app
EXPOSE 5000

# Запуск сервера (пример через llama-server)
CMD ["./llama-server", "-m", "/app/models/tinyllama-q4_k_m.gguf", "--host", "0.0.0.0", "--port", "5000", "-ngl", "20"]
```
*Примечание: `-ngl 20` означает количество слоев, которые будут загружены в GPU. Для 2 ГБ VRAM может потребоваться число меньше (например, 10-15).*

## Шаг 4: Конфигурация Kubernetes
Для работы GPU в Kubernetes необходимо создать `nodeSelector` или `tolerations`, чтобы поды попадали на нужный узел.

### Манифест Deployment (`deployment.yaml`)
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: llm-gtx1050
spec:
  replicas: 1
  selector:
    matchLabels:
      app: llm-service
  template:
    metadata:
      labels:
        app: llm-service
    spec:
      containers:
      - name: llm-container
        image: your-registry/my-llm:latest
        resources:
          limits:
            nvidia.com/gpu: 1 # Выделяем 1 полную GPU
        ports:
        - containerPort: 5000
        env:
        - name: MODEL_PATH
          value: "/app/models/tinyllama-q4_k_m.gguf"
```

### Манифест Service (`service.yaml`)
```yaml
apiVersion: v1
kind: Service
metadata:
  name: llm-service
spec:
  selector:
    app: llm-service
  ports:
    - protocol: TCP
      port: 80
      targetPort: 5000
  type: LoadBalancer
```

## Шаг 5: Запуск и тестирование
1.  **Применение манифестов:**
    ```bash
    kubectl apply -f deployment.yaml
    kubectl apply -f service.yaml
    ```
2.  **Проверка логов:**
    Убедитесь, что `llama-server` успешно инициализировал CUDA:
    ```bash
    kubectl logs -l app=llm-service
    ```
3.  **Тестирование запроса:**
    Используйте `port-forward` для локального доступа:
    ```bash
    kubectl port-forward svc/llm-service 8080:80
    ```
    Запрос через curl:
    ```bash
    curl http://localhost:8080/v1/chat/completions \
      -H "Content-Type: application/json" \
      -d '{"messages": [{"role": "user", "content": "Hello, how are you?"}]}'
    ```

## Ключевые советы для GTX 1050:
*   **Квантование:** Никогда не используйте FP16 или BF16. Только GGUF или EXL2 с квантованием 4-бит или ниже.
*   **Контекстное окно:** Ограничьте контекст (например, `-c 512` или `-c 1024`), так как KV-кэш быстро съедает 2 ГБ памяти.
*   **MTP:** Если ваша цель — именно архитектура Multi-Token Prediction, убедитесь, что выбранная модель (например, на базе архитектуры Mamba) поддерживает этот метод в вашей библиотеке инференса. Для TinyLlama стандартный метод — наиболее стабильный.
