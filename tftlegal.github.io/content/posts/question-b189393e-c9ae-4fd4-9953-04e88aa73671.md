Комплексное руководство по типам данных в SQL: от основ до сравнения PostgreSQL, SQLite и ClickHouse

1. Введение
Цель данного руководства – дать четкое представление о типах данных в SQL, объяснить их назначение и продемонстрировать, как различные системы управления базами данных (СУБД) реализуют эти типы. В руководстве также рассматриваются распространенные ошибки, которые могут возникнуть при выборе типов данных, и даются рекомендации по их предотвращению.

2. Основные категории типов данных в SQL
2.1 Числовые типы
– Exact numeric: INTEGER, SMALLINT, BIGINT, NUMERIC(precision, scale), DECIMAL.
– Approximate numeric: FLOAT, REAL, DOUBLE PRECISION.
Типичные ошибки: использование типа с плавающей точкой для денежных сумм, переполнение при хранении больших значений, потеря точности при арифметических операциях.
2.2 Строковые типы
– Character varying: VARCHAR(n), CHAR(n).
– Text: TEXT (в большинстве СУБД эквивалентно VARCHAR(MAX) или без ограничения длины).
– Бинарные данные: BLOB, BYTEA, RAW, VARBINARY.
Типичные ошибки: указание фиксированной длины для значений, длина которых может варьироваться, что приводит к неэффективному использовании памяти или обрезке данных; кодировка и сортировка, несовместимые с используемыми типами.
2.3 Даты и время
– Date: хранит только дату.
– Time: хранит только время (с субсекундной точностью в некоторых СУБД).
– Timestamp: хранит дату и время, часто с тайм-зоной.
– Interval: представляет собой период времени.
Типичные ошибки: смешивание типов даты и времени, игнорирование тайм-зон, хранение временных меток в нестандартном формате.
2.4 Логический тип

### – boolean, bool, bit(1).

Типичные ошибки: использование целочисленных значений (0/1) для представления истинности, что приводит к неявным преобразованиям и неясности намерений.
2.5 Другие специализированные типы
– Array, JSON, XML, UUID, ENUM, SET (в MySQL) и т.д.
Типичные ошибки: выбор нестандартного типа, когда стандартный тип подойдет лучше, что усложняет запросы и индексацию.

3. PostgreSQL
3.1 Числовые типы
– INTEGER (4-байтовое целое число), SMALLINT (2-байта), BIGINT (8-байтовое целое число).
– NUMERIC(p,s) для точных десятичных чисел.

### – float8 (double precision), float4 (real).

3.2 Строковые типы
– VARCHAR(n), CHAR(n) (с переменной/фиксированной длиной).
– TEXT (без ограничения длины).
– BYTEA для бинарных данных.
3.3 Даты и время
– DATE, TIME (с/без тайм-зоны), TIMESTAMP (с/без тайм-зоны), INTERVAL.
3.4 Логический тип

### – boolean.

3.5 Специализированные типы
– Массивы (например, INTEGER[]), JSON/JSONB, XML, UUID, ENUM (через ENUM или связанные типы домена), геометрические типы (в拡張 модулях).
3.6 Соответствие типов
PostgreSQL поддерживает неявные преобразования (например, числовые типы преобразуются между собой, строковые типиы с совпадающей кодировкой), но может потребовать явного приведения типа при неоднозначности.
3.7 Распространенные ошибки и лучшие практики
– Избегайте использования VARCHAR без ограничения длины для логгирования больших текстов; это может негативно повлиять на производительность индексации.
– Используйте NUMERIC для денежных сумм; хранение значений в формате FLOAT может привести к ошибкам округления.
– Для столбцов, требующих поиска, добавьте необходимые ограничения (NOT NULL, UNIQUE) и рассмотрите возможность использования индексов.

4. SQLite
4.1 Числовые типы
– INTEGER (64-битное целое число), REAL (двойная точность с плавающей точкой), NUMERIC (любое числовое значение, хранящееся в виде текстового представления).
4.2 Строковые типы
– TEXT (строка Unicode), BLOB (данные произвольного двоичного формата).
4.3 Даты и время
– SQLite не имеет встроенных типов даты/времени; обычно используется TEXT (ISO-8601), INTEGER (Unix timestamp) или REAL (дробное значение Julian Day).
4.4 Логический тип
– Булевы значения представлены в виде INTEGER (0 = false, 1 = true) или TEXT ("false"/"true").
4.5 Специализированные типы
– Нет встроенных массивов или JSON; могут использоваться расширения (например, JSON1).
4.6 Соответствие типов
Типы являются ленивыми; SQLite может автоматически преобразовывать типы в пределах категории INTEGER, REAL, TEXT, BLOB.
4.7 Распространенные ошибки и лучшие практики
– Не создавайте столбцы DATE как TEXT с нестандартным форматом; используйте ISO-8601 для обеспечения совместимости.
– Будьте осторожны с типом NUMERIC: он может хранить данные в виде текстового представления, что может привести к неожиданным преобразованиям.
– Так как SQLite не имеет строгой типизации, убедитесь, что вы используете соответствующие ограничения в своих приложениях.

5. ClickHouse
5.1 Числовые типы
– Типы целых чисел: Int8, Int16, Int32, Int64, UInt8, UInt16, UInt32, UInt64.
– Типы с плавающей точкой: Float32, Float64.
– Decimal(p,s) для точных десятичных чисел.
– Enum8, Enum16 (перечисления).
5.2 Строковые типы
– String (последовательность символов в стиле UTF-8), FixedString(n) (строка с фиксированной длиной).
5.3 Даты и время
– Date (дата в формате YYYY-MM-DD), DateTime (дата и время, опционально с тайм-зоной), DateTime64 (с субсекундной точностью).
– Также поддерживается тип Something для хранения временных меток в формате Unix (например, квази-тип).
5.4 Логический тип
– Нет отдельного булева типа; обычно используется UInt8 с 0/1 или String "true"/"false" (часто оптимизируется в виде числового представления).
5.5 Специализированные типы
– Array(T) для массивов гомогенных элементов, Tuple(T1, T2, …), Nested (массив структур), JSON (тип данных в стиле JSON), UUID.
5.6 Соответствие типов
ClickHouse имеет строгую типизацию; неявные преобразования возможны только в определенных случаях (например, целочисленный тип может быть использован в арифметических операциях с плавающим типом). Операторы часто требуют явного приведения типа.
5.7 Распространенные ошибки и лучшие практики
– Избегайте использования String для столбцов, которые имеют фиксированный набор значений; используйте Enum или специальный тип данных, если это возможно, для экономии места.
– При хранении больших массивов используйте тип Array с соответствующим типом данных; помните, что каждый элемент хранится отдельно, что может быстро увеличить размер данных.
– Для столбцов, используемых в агрегатных функциях, выберите наиболее подходящий числовой тип (например, UInt8 для флагов) для улучшения производительности компрессии.

7. Общие рекомендации по выбору типов данных
– Соответствуйте семантике домена: используйте точные числовые типы для денежных сумм, строки с ограничением длины для идентификаторов, типы даты/времени для временных меток.
– Учитывайте характеристики хранения и индексации: фиксированные типы могут быть более компактными; типы с переменной длиной увеличивают размер строк.
– Планируйте производительность: узкоспециализированные типы (например, UInt8 для флагов) уменьшают размер страниц и ускоряют сканирование.
– Думайте о совместимости с различными СУБД: если вам нужно работать с несколькими системами, выбирайте наиболее широко поддерживаемые типы (например, INTEGER, TEXT, DATE/TIMESTAMP).
– Используйте ограничения (NOT NULL, UNIQUE, CHECK) для обеспечения целостности данных независимо от СУБД.
– Избегайте хитроумных нестандартных типов там, где стандартные типы подходят; они могут усложнить перенос базы данных.

8. Распространенные ошибки и способы их предотвращения
– Хранение данных в неправильном формате (например, числовое значение в TEXT): используйте соответствующие ограничения и проверки при вводе данных.
– Переполнение при использовании неподходящего целочисленного типа: выберите signed/unsigned с достаточным диапазоном значений.
– Использование типа с плавающей точкой для денежных сумм: замените его на NUMERIC/DECIMAL.
– Игнорирование тайм-зон при хранении дат/времени: используйте тип с тайм-зоной, если это необходимо, или храните смещение.
– Использование VARCHAR без ограничения длины в PostgreSQL: может привести к разрастанию строк; рассмотрите возможность применения разумного ограничения или использования TEXT для очень больших текстов.
– Зависимость от неявных преобразований в SQLite: явно объявляйте типы столбцов для обеспечения строгой типизации.
– Использование String в ClickHouse для столбцов с низкой кардинальностью: замените его на Enum или специализированный числовой тип для улучшения компрессии.
